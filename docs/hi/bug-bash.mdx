Bug Bash में एक साथ कई `e2e explore` सेशन चलते हैं, और हर सेशन ऐप के एक हिस्से
पर लगता है। इसके बाद कोडिंग एजेंट हर फ़ाइंडिंग के लिए एक टेस्ट लिखता है। वह किसी
फ़ाइंडिंग को बग तभी बताता है जब उसका टेस्ट फ़ेल हो।

## शुरू करने से पहले

- पक्का करें कि ऐप एक साथ कई एक्सप्लोरर को संभाल सके। एक तरीका: ऐप को एक बार
  शुरू करें और टारगेट के `app.command` पर `reuseExisting: true` सेट करें। दूसरा
  तरीका: ऐप URL में पोर्ट `0` रखें, ताकि हर रन ऐप की अपनी कॉपी शुरू करे। `CI` सेट
  हो, तो e2e `reuseExisting` को नज़रअंदाज़ करता है। पोर्ट `0` इस्तेमाल करें।
  [अपना ऐप शुरू करना](/web#starting-your-app) देखें।
- मोबाइल पर हर सिम्युलेटर या एम्युलेटर के लिए एक अलग टारगेट बनाएँ। हर
  एक्सप्लोरर को अपना डिवाइस चाहिए।
- हर explore सेशन मॉडल कॉल करता है। हर रन के आख़िर में उसके टोकन, खर्च और लगा
  समय दिखता है।
- अगर साइट डिप्लॉय हो चुकी है और दूसरे लोग उसे इस्तेमाल करते हैं, तो उस पर डेटा
  न बदलें।

बाकी सेटअप, जैसे सीड किए गए अकाउंट और साइन इन, एजेंट स्किल देखकर खुद कर लेता है।

## स्किल इंस्टॉल करें

कोडिंग एजेंट Bug Bash को [`e2e` स्किल](/coding-agents) से चलाता है। यह स्किल
`e2e init` इंस्टॉल करता है। `init` के बिना इंस्टॉल करना हो, तो:

<CodeGroup>
```bash npm
npx skills add e2e-inc/e2e
```

```bash pnpm
pnpm dlx skills add e2e-inc/e2e
```

```bash bun
bunx skills add e2e-inc/e2e
```
</CodeGroup>

## Bug Bash शुरू करें

अपने कोडिंग एजेंट को एक प्रॉम्प्ट दें:

```text
Bug bash the checkout and account settings on this branch.
```

## एजेंट क्या करता है

<ShowMore id="bug-bash-steps">

1. ऐप के रूट पढ़ता है। ब्रांच पर हो, तो डिफ़ भी पढ़ता है।
2. 5 से 10 चार्टर लिखता है। चार्टर ऐप के किसी एक हिस्से के लिए एक वाक्य का लक्ष्य
   है। हर चार्टर का एक नज़रिया होता है: पहली बार आया यूज़र, नंबर और UI टेक्स्ट,
   एज इनपुट, रीलोड के बाद की स्थिति, या एरर पाथ।
3. हर चार्टर के लिए एक `e2e explore` चलाता है, एक साथ 4। हर रन का अपना पर्सोना
   (`--agent`) और अपनी आउटपुट डायरेक्टरी (`--output`) होती है।
4. सारे चार्टर की फ़ाइंडिंग एक जगह मिलाता है।
5. जिन फ़ाइंडिंग की वजह पहले से पता है, उन्हें खारिज कर देता है। वजह इनमें से कुछ
   भी हो सकती है: एक्सप्लोरर की कोई सीमा (जैसे नए टैब में खुलने वाला लिंक), लोकल
   एनवायरनमेंट, जानबूझकर किया गया डिज़ाइन, या सीड डेटा।
6. बची हुई हर फ़ाइंडिंग के लिए एक रिप्रो टेस्ट लिखता है। फ़ाइंडिंग के स्टेप
   `agent.act` कॉल बनते हैं, और उम्मीद के मुताबिक व्यवहार आख़िरी `agent.assert`
   बनता है। एजेंट हर हिस्से के लिए एक सबएजेंट शुरू कर सकता है।
7. रिप्रो टेस्ट चलाता है। फ़ाइंडिंग तभी बग मानी जाती है जब उसका टेस्ट रिपोर्ट किए
   गए डिफ़ेक्ट पर ही फ़ेल हो। यानी आख़िरी जाँच से `ASSERTION_FAILED` आए, या कोई
   `act` उसी डिफ़ेक्ट पर फ़ेल हो।
8. रिपोर्ट इस क्रम में देता है: कन्फ़र्म हुए बग, प्रोडक्शन के वे रिस्क जिन्हें वह
   लोकल पर जाँच नहीं सकता, वजह के हिसाब से खारिज की गई फ़ाइंडिंग, और वॉर्निंग।

</ShowMore>

हर कन्फ़र्म बग के साथ उसका रिप्रो टेस्ट और स्टेप मिलते हैं। अगर इंजन स्क्रीनशॉट
और वीडियो रिकॉर्ड करता है, तो एक्सप्लोरर का स्क्रीनशॉट और वीडियो भी साथ होते हैं।

<Warning>
वीडियो मास्क नहीं होता। अगर एक्सप्लोरर ने पासवर्ड टाइप किया था, तो शेयर करने से
पहले वीडियो देख लें।
</Warning>

पूरी प्रक्रिया पढ़नी हो, तो `npx e2e guide bug-bash` चलाएँ।

## रिप्रो टेस्ट

रिप्रो टेस्ट तब तक फ़ेल होता है जब तक बग ठीक न हो। एजेंट हर रिप्रो टेस्ट पर
`bugbash` टैग लगाता है। जिस रन के पास होने पर ही मर्ज होता है, उससे इन्हें बाहर
रखें:

<CodeGroup>
```bash npm
npx e2e run --exclude-tag bugbash
```

```bash pnpm
pnpm exec e2e run --exclude-tag bugbash
```

```bash bun
bunx e2e run --exclude-tag bugbash
```
</CodeGroup>

फ़िक्स के बाद टेस्ट पास होने लगता है। तब टैग हटा दें और टेस्ट को रिग्रेशन टेस्ट
की तरह रख लें।
