Bug Bash एक साथ कई `e2e explore` सेशन चलाता है, और हर सेशन ऐप के एक हिस्से पर
काम करता है। फिर एक कोडिंग एजेंट हर फ़ाइंडिंग के लिए एक टेस्ट लिखता है, और उसे
बग तभी बताता है जब वह टेस्ट फ़ेल हो।

## शुरू करने से पहले

- पक्का करें कि ऐप एक साथ कई एक्सप्लोरर को सर्व कर सके। ऐप को एक बार शुरू करें
  और टारगेट के `app.command` पर `reuseExisting: true` सेट करें। या ऐप URL में
  पोर्ट `0` सेट करें, ताकि हर रन ऐप की अपनी कॉपी शुरू करे। जब `CI` सेट हो, तो
  e2e `reuseExisting` को अनदेखा करता है। पोर्ट `0` इस्तेमाल करें।
  [अपना ऐप शुरू करना](/web#starting-your-app) देखें।
- मोबाइल पर हर सिम्युलेटर या एम्युलेटर के लिए एक टारगेट घोषित करें। हर
  एक्सप्लोरर को अपना अलग डिवाइस चाहिए।
- हर explore सेशन मॉडल कॉल इस्तेमाल करता है। हर रन अपने टोकन, लागत और अवधि
  बताकर खत्म होता है।
- जिस डिप्लॉय की गई साइट को दूसरे लोग इस्तेमाल करते हैं, उस पर डेटा न बदलें।

बाकी सेटअप, जैसे सीड किए गए खाते और साइन इन, एजेंट स्किल के अनुसार करता है।

## स्किल इंस्टॉल करें

कोडिंग एजेंट Bug Bash को [`e2e` स्किल](/coding-agents) से चलाता है, जिसे
`e2e init` इंस्टॉल करता है। इसे `init` के बिना इंस्टॉल करने के लिए:

<CodeGroup>
```bash npm
npx skills add e2e-inc/e2e
```

```bash pnpm
pnpm dlx skills add e2e-inc/e2e
```

```bash bun
bunx skills add e2e-inc/e2e
```
</CodeGroup>

## Bug Bash शुरू करें

अपने कोडिंग एजेंट को एक प्रॉम्प्ट दें:

```text
Bug bash the checkout and account settings on this branch.
```

## एजेंट क्या करता है

<ShowMore id="bug-bash-steps">

1. ऐप के रूट पढ़ता है। किसी ब्रांच पर वह डिफ़ भी पढ़ता है।
2. 5 से 10 चार्टर लिखता है। चार्टर ऐप के एक हिस्से के लिए एक वाक्य का लक्ष्य
   होता है, जिसका एक नज़रिया होता है: पहली बार आने वाला यूज़र, संख्याएँ और UI
   टेक्स्ट, एज इनपुट, रीलोड के बाद की स्थिति, या एरर पाथ।
3. हर चार्टर के लिए एक `e2e explore` चलाता है, एक समय में 4। हर रन को अपना
   पर्सोना (`--agent`) और अपनी आउटपुट डायरेक्टरी (`--output`) मिलती है।
4. सभी चार्टर की फ़ाइंडिंग मिलाता है।
5. उन फ़ाइंडिंग को खारिज करता है जिनकी वजह पहले से पता है। वजह एक्सप्लोरर की
   कोई सीमा (उदाहरण के लिए, ऐसा लिंक जो नए टैब में खुलता है), लोकल एनवायरनमेंट,
   जानबूझकर रखा गया डिज़ाइन, या सीड डेटा हो सकती है।
6. हर बची हुई फ़ाइंडिंग के लिए एक रिप्रो टेस्ट लिखता है: फ़ाइंडिंग के चरण
   `agent.act` कॉल के रूप में, और उसका अपेक्षित व्यवहार आख़िरी `agent.assert` के
   रूप में। कोडिंग एजेंट ऐप के हर हिस्से के लिए एक सबएजेंट शुरू कर सकता है।
7. रिप्रो टेस्ट चलाता है। फ़ाइंडिंग तभी बग है जब उसका टेस्ट रिपोर्ट किए गए दोष
   पर फ़ेल हो: आख़िरी जाँच से `ASSERTION_FAILED`, या कोई `act` जो खुद उस दोष पर
   फ़ेल हो।
8. इस क्रम में रिपोर्ट करता है: वे बग जिनकी पुष्टि हुई है, प्रोडक्शन के वे जोखिम
   जिन्हें वह लोकल पर नहीं जाँच सकता, वजह के हिसाब से खारिज की गई फ़ाइंडिंग, और
   चेतावनियाँ।

</ShowMore>

जिस बग की पुष्टि हुई है, उसके साथ उसका रिप्रो टेस्ट और चरण होते हैं। जब इंजन
स्क्रीनशॉट और वीडियो रिकॉर्ड करता है, तो बग के साथ एक्सप्लोरर का स्क्रीनशॉट और
वीडियो भी होते हैं।

<Warning>
वीडियो मास्क नहीं किया जाता। अगर एक्सप्लोरर ने पासवर्ड टाइप किया था, तो वीडियो
शेयर करने से पहले उसे जाँच लें।
</Warning>

पूरी प्रक्रिया पढ़ने के लिए `npx e2e guide bug-bash` चलाएँ।

## रिप्रो टेस्ट

रिप्रो टेस्ट तब तक फ़ेल होता है जब तक बग ठीक न हो जाए। एजेंट हर रिप्रो टेस्ट पर
`bugbash` टैग लगाता है। उन्हें उस रन से बाहर रखें जिसके पास होने पर ही मर्ज
होता है:

<CodeGroup>
```bash npm
npx e2e run --exclude-tag bugbash
```

```bash pnpm
pnpm exec e2e run --exclude-tag bugbash
```

```bash bun
bunx e2e run --exclude-tag bugbash
```
</CodeGroup>

बग ठीक होने के बाद टेस्ट पास होता है। टैग हटा दें और टेस्ट को रिग्रेशन टेस्ट के
रूप में रखें।
