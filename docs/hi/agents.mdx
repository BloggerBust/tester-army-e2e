एजेंट `agents` में नाम वाली एक एंट्री है। उसका अपना मॉडल, अपने निर्देश और अपने
टूल होते हैं। अगर आप कोई और एजेंट न चुनें, तो टेस्ट `default` इस्तेमाल करते हैं।
मॉडल की तुलना करनी हो, या एक ही फ़्लो कई पर्सोना बनकर चलाना हो, तो और एजेंट
नाम देकर जोड़ें।

## नाम वाले एजेंट डिफ़ाइन करें

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

const vocabulary = 'Plans are called tiers. Billing lives under Settings. "Approve" on an order refunds it.';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: {
    default: { model: gateway('openai/gpt-6-luna-fast'), context: vocabulary },
    thorough: {
      model: gateway('anthropic/claude-opus-5'),
      system: 'Verify every claim on screen before concluding a step.',
      context: vocabulary,
    },
    buyer: { model: gateway('openai/gpt-6-luna-fast'), system: 'You are a first-time buyer.', context: vocabulary },
    admin: { model: gateway('openai/gpt-6-luna-fast'), system: 'You manage orders and approve refunds.', context: vocabulary },
  },
} satisfies E2EConfig;
```

एक एंट्री में `model`, एक ऑप्शनल [`judge`](/models#a-judge-of-its-own),
`system`, `context`, [टूल](/tools), बजट और `providerOptions` होते हैं।
`maxSteps` एक स्टेप के एक्शन की लिमिट तय करता है, और `maxModelCalls` उसकी मॉडल
कॉल की: डिफ़ॉल्ट 25, ज़्यादा से ज़्यादा 100।
[कॉन्फ़िग रेफ़रेंस](/reference/config#agents) देखें।

एंट्री `default` से कुछ भी इनहेरिट नहीं करतीं। हर एंट्री को उसका ज़रूरी मॉडल और
कॉन्टेक्स्ट खुद दें, जैसे ऊपर एक शेयर्ड कॉन्स्टेंट से दिया गया है।

[कस्टम एक्ज़ीक्यूटर](/executors) `executor` में जाता है। मॉडल, जज मॉडल,
कॉन्टेक्स्ट और बजट तब भी लागू रहते हैं। लेकिन `system` और `tools` रिजेक्ट हो
जाते हैं, क्योंकि एक्ज़ीक्यूटर अपना प्रॉम्प्ट और टूल खुद लाता है।

## निर्देश और शब्दावली

| | `system` | `context` |
|---|---|---|
| किस सवाल का जवाब | एक्शन करने वाला एजेंट कैसे काम करे? | यह ऐप चीज़ों को क्या कहता है? |
| कौन पढ़ता है | सिर्फ़ act लूप | हर मॉडल कॉल: act टर्न भी, और `assert`, `waitFor` और `extract` के पीछे के जज मॉडल भी |
| यहाँ क्या रखें | पर्सोना, कितनी सावधानी बरतनी है, ख़त्म करने से पहले क्या चेक करना है, अचानक आए डायलॉग से कैसे निपटना है | स्क्रीन और मेन्यू के नाम, कोई फ़ीचर कहाँ है, कौन सा बटन फ़ॉर्म सबमिट करता है, डोमेन के शब्द |
| कहाँ सेट करें | `agents.<name>.system` | `agents.<name>.context`, ज़्यादा से ज़्यादा 16 KiB |

जज मॉडल को `system` कभी नहीं दिखता। इसलिए "फ़ॉर्म बंद होते ही स्टेप पूरा" जैसा
निर्देश फ़ैसले का पैमाना नीचे नहीं कर सकता। सीधा नियम: जो बात इस ऐप पर किसी भी
टेस्टर के लिए सच है, वह `context` में जाती है। जो बात इस टेस्टर के लिए किसी भी
ऐप पर सच है, वह `system` में।

कोई टेस्ट या ग्रुप `agentContext` से `context` में अपनी शब्दावली जोड़ सकता है।
इसे उन बातों के लिए इस्तेमाल करें जो सिर्फ़ उसी टेस्ट को पता हैं, जैसे सीड
किया गया डेटा, या कोई फ़ीचर फ़्लैग जो किसी लेबल को बदल देता है:

```ts title="tests/billing.e2e.ts"
import { describe, test } from 'e2e';

describe('billing', { agentContext: 'The seeded workspace is called "Acme Trial".' }, () => {
  test('upgrades the tier', async ({ agent }) => { /* ... */ });
});
```

`agentContext` में निर्देश न डालें, क्योंकि यह जज मॉडल तक भी पहुँचता है।

`e2e run` में हर प्रॉम्प्ट के साथ टेस्ट का टाइटल पाथ भी जाता है, जैसे
`Test: billing > upgrades the tier`। जज मॉडल भी इसे पढ़ते हैं। इसलिए टेस्ट का
नाम इस पर रखें कि वह क्या कवर करता है, इस पर नहीं कि आप किस फ़ैसले की उम्मीद
करते हैं।

## हर रन के लिए एजेंट चुनें

जो टेस्ट खुद कोई एजेंट नहीं चुनते, उनके लिए `--agent` एजेंट चुनता है। कई नाम
दें, तो हर टेस्ट हर एजेंट के लिए एक बार चलता है:

<CodeGroup>
```bash npm
npx e2e run --agent thorough tests/checkout.e2e.ts
npx e2e run --agent buyer,admin
```

```bash pnpm
pnpm exec e2e run --agent thorough tests/checkout.e2e.ts
pnpm exec e2e run --agent buyer,admin
```

```bash bun
bunx e2e run --agent thorough tests/checkout.e2e.ts
bunx e2e run --agent buyer,admin
```
</CodeGroup>

## सूट में एजेंट पिन करें

कोई टेस्ट, describe ब्लॉक, या एक कॉल एजेंट चुन सकती है। जो सेटिंग सबसे
नज़दीक है, वही चलती है: पहले कॉल, फिर टेस्ट, फिर उसके बाहर के ग्रुप, फिर रन।

```ts title="tests/checkout.e2e.ts"
import { describe, test } from 'e2e';

describe('checkout as a first-time buyer', { agent: 'buyer' }, () => {
  test('pays for one item', async ({ app, agent }) => { /* ... */ });

  describe('refunds', { agent: 'admin' }, () => {
    test('refunds the order', async ({ agent }) => { /* ... */ });
  });

  test('reorders, and the admin approves', async ({ app, agent }) => {
    await app.open('/orders');
    await agent.act('reorder the most recent order');
    // The admin's act call sees what the earlier steps of this test did.
    await agent.act('approve the pending reorder', { agent: 'admin' });
    await agent.assert('the reorder shows as approved');
  });
});
```

किसी टेस्ट ने जो एजेंट चुना है, `--agent` उसकी जगह नहीं लेता। टेस्ट या ग्रुप
पर अनजान एजेंट हो, तो कलेक्शन के दौरान ही फ़ेल हो जाता है। कॉल पर अनजान
एजेंट हो, तो `INVALID_ARGUMENT` थ्रो होता है। रिपोर्ट में हर स्टेप का एजेंट
दर्ज होता है।

कई एजेंट चुनें, तो वही टेस्ट हर एजेंट के साथ एक बार चलता है:

```ts title="tests/checkout.e2e.ts"
import { describe, test } from 'e2e';

describe('checkout', { agent: ['buyer', 'admin'] }, () => {
  test('pays for one item', async ({ app, agent }) => { /* runs once per persona */ });
  test('applies a promo code', async ({ app, agent }) => { /* ... */ });
});
```

हर एजेंट को नतीजों और आर्टिफ़ैक्ट की अपनी डायरेक्टरी मिलती है। टर्मिनल और JUnit
में टेस्ट के नाम के साथ एजेंट भी आता है, जैसे `[admin]`।

`--agent` पिन किए गए एजेंटों में से चुनता है, और कभी कोई एजेंट नहीं
जोड़ता। यहाँ `--agent admin` सिर्फ़ `admin` चलाता है। `--agent thorough` किसी से
मैच नहीं करता, इसलिए दोनों एजेंट फिर भी चलते हैं।

सीरियल ग्रुप हर एजेंट के लिए एक यूनिट बनकर चलता है, और उसके टेस्ट ग्रुप का पिन
शेयर करते हैं। सेटअप टेस्ट ज़्यादा से ज़्यादा एक एजेंट पिन कर सकता है।

हर एजेंट अपनी [रीप्ले कैश](/cache) एंट्री खुद रिकॉर्ड करता है। इन एंट्री की key
में उसका नाम और कॉन्टेक्स्ट होते हैं। `buyer` कभी `admin` के स्टेप रीप्ले
नहीं करता, और `agentContext` बदलते ही स्टेप फिर से रिकॉर्ड होते हैं।

एजेंट कोई साइन इन किया हुआ यूज़र नहीं है। साइन इन वाले पर्सोना चाहिए, तो हर
एजेंट को एक अलग describe ब्लॉक में किसी `session` के साथ जोड़ें।
[ऑथेंटिकेशन](/authentication#several-signed-in-users) देखें।

## एजेंट को अपना बनाएँ

कोई स्टेप फ़ेल हो या बहुत ज़्यादा कॉल ले, तो उसकी रिपोर्ट खोलें, या `--debug` के
साथ चलाकर ट्रांसक्रिप्ट देखें। सबसे पहले निर्देश ठीक करें, और उसमें स्क्रीन पर
दिखने वाले लेबल लिखें। अगर दिक्कत कई टेस्ट में है, तो एजेंट ठीक करें:
शब्दावली `context` में, निर्देश `system` में, या किसी ऑपरेशन के लिए एक
[टूल](/tools), जैसे टेस्ट API से कार्ट में पहले से आइटम डालना। मॉडल या
`providerOptions` की तुलना करनी हो, तो वही टेस्ट `--agent <name>` के साथ चलाएँ।
