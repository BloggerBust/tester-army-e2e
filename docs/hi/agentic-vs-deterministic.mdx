---
title: एजेंटिक या डिटर्मिनिस्टिक
description: अपने एंड-टू-एंड टेस्ट के लिए एजेंटिक या डिटर्मिनिस्टिक एक्शन और असर्शन चुनें।
---

एजेंटिक टेस्टिंग में आप आम भाषा में लिखते हैं कि यूज़र क्या करना चाहता है और
नतीजा क्या होना चाहिए। कौन-से एक्शन करने हैं, यह एजेंट खुद तय कर सकता है। वह
यह भी परख सकता है कि स्क्रीन आपकी उम्मीद के मुताबिक है या नहीं। आपका टेस्ट
नतीजे पर टिका रहता है, और UI बदलने पर कोई सेलेक्टर संभालना नहीं पड़ता।

डिटर्मिनिस्टिक टेस्टिंग में आप एक्शन और चेक कोड में लिखते हैं। दोनों तरीकों से
यूज़र को मिलने वाले नतीजे टेस्ट हो सकते हैं, और e2e में आप एक ही टेस्ट में
दोनों को मिला सकते हैं।

## एजेंटिक टेस्ट कब इस्तेमाल करें?

अगर UI बदलने की वजह से आपको बार-बार टेस्ट के सेलेक्टर अपडेट करने पड़ते हैं, तो
एजेंटिक टेस्ट इस्तेमाल करें। ये ऐसे फ़्लो के लिए भी ठीक हैं जिनमें इंटरैक्शन तो
कई होते हैं, लेकिन उन्हें सीधी अंग्रेज़ी में बताना आसान होता है, जैसे कोई फ़ॉर्म
भरकर सबमिट करना।

`agent.act` में आप बताते हैं कि यूज़र क्या करना चाहता है, जैसे डिस्काउंट कोड
लगाना। कौन-से कंट्रोल इस्तेमाल करने हैं और क्या करना है, यह एजेंट खुद समझ लेता
है। `agent.assert` चेक करता है कि स्क्रीन पर वही नतीजा दिख रहा है या नहीं जो
आपने बताया, जैसे टोटल पर लगा डिस्काउंट।

उदाहरण के लिए, `app` और `agent` फ़िक्स्चर वाले किसी टेस्ट में:

```ts
await app.open('/checkout');
await agent.act('apply the discount code SUMMER');
await agent.assert('the checkout shows code SUMMER applied with a 10% discount');
```

आपको डिस्काउंट फ़ील्ड, उसे लगाने वाले बटन या नतीजा दिखाने वाले एलिमेंट का नाम
नहीं बताना पड़ता।

जो टेस्ट CSS क्लास या टेस्ट id पर टिके हैं, उन्हें ये आइडेंटिफ़ायर बदलते ही
बदलना पड़ता है। लेकिन बटन की जगह बदल दें या फ़ॉर्म को नए सिरे से डिज़ाइन कर दें,
तब भी एजेंट स्क्रीन पर जो है, उसी से यूज़र का काम पूरा कर सकता है।

एजेंटिक टेस्ट से आप स्टेजिंग या प्रोडक्शन पर असली डेटा के साथ मॉनिटरिंग कर सकते
हैं। इसके लिए डिटर्मिनिस्टिक डेटा पहले से डालने की ज़रूरत नहीं, क्योंकि एजेंट
आपके ऐप के हिसाब से खुद को ढाल लेते हैं। वहाँ टेस्ट अकाउंट इस्तेमाल करें: स्क्रीन
पर जो कुछ है, वह मॉडल को दिखता है। [सुरक्षा](/security) देखें।

किसी पेचीदा जर्नी के लिए आम अंग्रेज़ी में एक के बाद एक लक्ष्य लिखें। हर लक्ष्य में
एक ही नतीजा रखें, और आगे बढ़ने से पहले उसे चेक करें। जर्नी को स्टेप में कैसे
बाँटें, यह [लक्ष्य](/core-concepts#goals) में देखें।

## एजेंटिक असर्शन कब इस्तेमाल करें?

एजेंटिक असर्शन तब काम आते हैं जब एक ही ज़रूरत कई तरह के शब्दों या लेआउट से पूरी
हो सकती है। जैसे, कोई वैलिडेशन मैसेज किसी एक तय वाक्य से मेल खाए बिना भी बता
सकता है कि गड़बड़ क्या है:

```ts
await agent.assert('the error message explains that an email address is required');
```

विज़ुअल चेक के लिए `vision: true` जोड़ें, ताकि मॉडल स्क्रीनशॉट भी देखे:

```ts
await agent.assert('the chart trends upward', { vision: true });
```

`agent.assert` मौजूदा स्क्रीन चेक करता है। अगर बात गलत निकले या सबूत काफ़ी न
हो, तो यह फ़ेल होता है। अगर UI को उम्मीद के मुताबिक स्थिति तक पहुँचने में अभी
वक़्त लगेगा, तो `agent.waitFor` इस्तेमाल करें। दोनों मेथड के लिए
[असर्शन](/core-concepts#assertions) देखें।

## डिटर्मिनिस्टिक टेस्ट कब इस्तेमाल करें?

छोटे और स्थिर फ़्लो के लिए लोकेटर इस्तेमाल करें, जहाँ आपको पहले से पता है कि
कौन-से कंट्रोल चाहिए। इसमें आप हर फ़ील्ड और बटन कोड में बताते हैं, जैसे इस
डिस्काउंट टेस्ट में:

```ts
await app.open('/checkout');
await screen.getByLabel('Discount code').fill('SUMMER');
await screen.getByRole('button', 'Apply').tap();
await expect(screen.getByRole('status')).toHaveText('10% off');
```

इन एक्शन और चेक में कोई मॉडल कॉल नहीं होती। जहाँ हो सके, रोल और लेबल इस्तेमाल
करें, ताकि टेस्ट उन कंट्रोल की बात करे जिन्हें यूज़र पहचानता है।
डिटर्मिनिस्टिक टेस्ट के लिए CSS क्लास या टेस्ट id पर टिकना ज़रूरी नहीं है।

अगर उम्मीद के मुताबिक नतीजे को आप किसी सटीक वैल्यू, गिनती या स्थिति के रूप में
लिख सकते हैं, तो डिटर्मिनिस्टिक असर्शन इस्तेमाल करें। ये मॉडल से परखवाए बिना
उसे चेक करते हैं। अगर किसी वैलिडेशन मैसेज में खास शब्द होने चाहिए, तो उस
टेक्स्ट को `expect` से चेक करें।

## एजेंटिक और डिटर्मिनिस्टिक टेस्ट को मिलाएँ

एक्शन और असर्शन को एक-दूसरे से अलग चुनें। जैसे, आप बदलते UI में रास्ता ढूँढने
का काम एजेंट पर छोड़ सकते हैं, फिर `expect` से कोई सटीक वैल्यू चेक कर सकते हैं:

```ts
await agent.act('apply the discount code SUMMER');
await expect(screen.getByRole('status')).toHaveText('10% off');
```

आप लोकेटर से फ़ॉर्म भरकर सबमिट भी कर सकते हैं, और फिर `agent.assert` से चेक कर
सकते हैं कि उसका वैलिडेशन मैसेज समस्या समझाता है या नहीं।

एजेंट उस लक्ष्य के हिसाब से ढलता है जो आप लिखते हैं। निर्देश गोलमोल हो, तो
ऐसा नतीजा भी आ सकता है जो आप नहीं चाहते थे। अगर कोई खास रास्ता मायने रखता है,
तो उसे लक्ष्य में लिख दें, या उन एक्शन के लिए लोकेटर इस्तेमाल करें। `agent.act`
के बाद लगा `expect` उस लक्ष्य को पकड़ लेता है जो गलत तरीके से पास हो गया।

मॉडल से चलने वाले एक्शन और असर्शन में वक़्त और पैसा ज़्यादा लगता है, और ये गलती
भी कर सकते हैं। [रीप्ले कैश](/cache) रिकॉर्ड किए गए `agent.act` एक्शन बिना मॉडल
कॉल के दोबारा चला सकता है। असर्शन हर टेस्ट रन में फिर से चलते हैं। जब कोई
रिकॉर्डिंग अब मेल नहीं खाती, तो एजेंट बदले हुए UI के हिसाब से ढल सकता है,
जब तक स्ट्रिक्ट कैश मोड चालू न हो। यह कैसे काम करता है, यह
[सेल्फ़-हीलिंग टेस्ट](/self-healing) में देखें।
