```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('checkout looks right', async ({ app, screen }) => {
  await app.open('/checkout');
  await expect(screen).toHaveScreenshot('checkout.png');
  await expect(screen.getByRole('button', 'Pay')).toHaveScreenshot('pay-button.png');
});
```

`expect(screen)` पूरी स्क्रीन मिलाता है। `expect(locator)` अपने इकलौते मैच को
स्क्रोल करके सामने लाता है और उस बॉक्स को मिलाता है।

## सेव किए हुए स्क्रीनशॉट

स्क्रीनशॉट टेस्ट के साथ कमिट करें। पहले रन के पास मिलाने के लिए कुछ नहीं
होता। इसलिए वह स्क्रीनशॉट लिखता है और फ़ेल हो जाता है। इमेज देख लें, कमिट करें
और फिर से चलाएँ।

```text
tests/checkout.e2e.ts
tests/checkout.e2e.ts-snapshots/checkout-web-linux.png
tests/checkout.e2e.ts-snapshots/checkout-ios-darwin.png
tests/checkout.e2e.ts-snapshots/pay-button-web-linux.png
```

हर टारगेट और ऑपरेटिंग सिस्टम की फ़ाइल अलग होती है, क्योंकि फ़ॉन्ट और रेंडरिंग
अलग-अलग होते हैं। नाम न दें, तो फ़ाइल को टेस्ट का नाम मिलता है:
`checkout-looks-right-1-web-linux.png`।

ऐप जानबूझकर बदला है, तो जो स्क्रीनशॉट अलग आ रहे हैं उन्हें दोबारा लिखें, और जो
अभी मौजूद नहीं हैं, उन्हें लिख दें। फिर रन पास हो जाता है:

<CodeGroup>
```bash npm
npx e2e run --update-snapshots
```

```bash pnpm
pnpm exec e2e run --update-snapshots
```

```bash bun
bunx e2e run --update-snapshots
```
</CodeGroup>

## CI में

स्क्रीनशॉट उसी मशीन पर लें जो CI में उन्हें रेंडर करती है। वेब और Android के
लिए Linux रनर, और iOS के लिए उसी सिम्युलेटर वाला macOS रनर।

`--update-snapshots` के बिना CI रन प्रोजेक्ट में कभी कुछ नहीं लिखता। कोई
स्क्रीनशॉट न हो, तो टेस्ट फ़ेल होता है। रन वह स्क्रीनशॉट टेस्ट के नतीजों में
`snapshots/<path in the project>` पर सेव कर देता है, ताकि आप डाउनलोड करके कमिट
कर सकें। सारे स्क्रीनशॉट एक साथ लिखने हैं, तो टेस्ट जॉब जैसे ही एक जॉब में
`--update-snapshots` चलाएँ:

```yaml title=".github/workflows/screenshots.yml"
name: Update screenshots
on: workflow_dispatch
jobs:
  screenshots:
    runs-on: ubuntu-latest
    steps:
      # the same checkout, setup, and install steps as the test job
      - run: npx e2e run --update-snapshots
      - uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: screenshots
          path: tests/**/*-snapshots/
```

आर्टिफ़ैक्ट को प्रोजेक्ट में डाउनलोड करें, इमेज चेक करें और कमिट कर दें।

## जब यह फ़ेल हो

मैचर तब तक स्क्रीनशॉट लेता रहता है, जब तक कोई एक मैच न हो जाए या असर्शन
टाइमआउट (`assertionTimeout`, 5 s) ख़त्म न हो जाए। मैच न हो, तो फ़ेलियर में लिखा
आता है कि कितने पिक्सल अलग हैं। साथ में टेस्ट के नतीजों में तीन इमेज मिलती हैं:
`-diff`, जिसमें बदले हुए पिक्सल लाल होते हैं, `-actual` और `-expected`।

```text
2173 pixels (0.24% of the image) differ from tests/home.e2e.ts-snapshots/screen-web-darwin.png; run with --update-snapshots to keep this run's
diff: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-diff.png
actual: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-actual.png
expected: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-expected.png
```

स्क्रीनशॉट लिखने से पहले मैचर लगातार दो एक जैसे स्क्रीनशॉट का इंतज़ार करता
है। स्क्रीन कभी रुकती ही नहीं, तो मैचर फ़ेल होता है। तब आपको आख़िरी दो स्क्रीनशॉट
और उनकी डिफ़ इमेज मिलती है।

## टॉलरेंस और मास्क

```ts
await expect(screen).toHaveScreenshot('dashboard.png', {
  maxDiffPixelRatio: 0.01,
  mask: [screen.getByTestId('last-updated')],
});
```

| ऑप्शन | डिफ़ॉल्ट | मतलब |
| --- | --- | --- |
| `threshold` | `0.2` | एक पिक्सल का रंग कितना खिसके और फिर भी वैसा ही गिना जाए, 0 से 1 |
| `maxDiffPixels` | `0` | कितने पिक्सल अलग हो सकते हैं |
| `maxDiffPixelRatio` | `0` | कुल पिक्सल का कितना हिस्सा अलग हो सकता है, 0 से 1 |
| `mask` | कुछ नहीं | रन-दर-रन बदलने वाले कंटेंट के लोकेटर, जिन पर तुलना से पहले रंग पोत दिया जाता है |
| `maskColor` | `#ff00ff` | मास्क वाले बॉक्स का रंग |
| `timeout` | `assertionTimeout` | असर्शन का बजट, मिलीसेकंड में |

वेब पर e2e एनिमेशन रोक देता है और टेक्स्ट कैरेट छिपा देता है। iOS और Android
पर यह स्टेटस बार को एक जैसा रखता है, ताकि हर रन में घड़ी और बैटरी मैच करें।

e2e हर स्क्रीनशॉट में सिक्योर फ़ील्ड मास्क करता है, सीक्रेट भरने के बाद भी।
अगर इंजन यह साबित न कर पाए कि स्क्रीन पर हर सिक्योर फ़ील्ड मास्क है, तो मैचर
`POLICY_DENIED` के साथ फ़ेल होता है।
