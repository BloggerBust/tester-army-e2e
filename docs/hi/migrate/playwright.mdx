1. ऊपर दी गई माइग्रेशन गाइड पढ़ें। इसमें वे Playwright कॉन्फ़िग key, API और CLI फ़्लैग मैप किए गए हैं जो e2e में काम करते हैं, और यह भी लिखा है कि e2e में अभी क्या नहीं है।
2. अगर प्रोजेक्ट में कोई e2e कॉन्फ़िग (\`e2e.config.ts\`, \`.mts\`, \`.js\`, या \`.mjs\`) नहीं है, तो \`npx e2e init --yes\` (या pnpm या bun की बराबर कमांड) चलाएँ। यह कॉन्फ़िग और एक उदाहरण टेस्ट लिखता है, और अभी कुछ इंस्टॉल नहीं करता।
3. e2e स्किल पढ़ें (\`npx e2e guide\` इसे प्रिंट करता है, \`npx e2e guide <topic>\` एक टॉपिक प्रिंट करता है) और नीचे के हर स्टेप में इसका पालन करें।
4. अगर आपने init चलाया है, तो मुझसे पूछें कि एजेंट स्टेप के लिए कौन-सा मॉडल इस्तेमाल करना है: ChatGPT, GitHub Copilot, OpenCode Console या SuperGrok सब्सक्रिप्शन, कोई API key, या लोकल मॉडल। उसे उसके प्रोवाइडर पैकेज से कॉन्फ़िगर करें। अगर इसमें साइन इन चाहिए, तो मुझे \`npx e2e login\` कमांड दें और मेरे कन्फ़र्म करने तक रुकें।
5. गाइड की कॉन्फ़िग टेबल देखकर \`playwright.config.ts\` को e2e कॉन्फ़िग में पोर्ट करें। \`@playwright/test\` इंस्टॉल रहने दें और दोनों फ़ाइल पैटर्न अलग रखें।
6. डिपेंडेंसी इंस्टॉल करें।

8. उस स्पेक के हर Playwright API को "e2e में अभी क्या नहीं है" से मिलाएँ। "अभी क्या इस्तेमाल करें" या "इसकी जगह क्या इस्तेमाल करें" वाली एंट्री इस्तेमाल करें, या वह टेस्ट Playwright में ही रहने दें और मुझे वजह बताएँ। फिर स्पेक को \`tests/\` के अंदर \`.e2e.ts\` फ़ाइल में दोबारा लिखें (e2e डिफ़ॉल्ट रूप से \`tests/**/*.e2e.ts\` चलाता है)। गाइड देखकर हर \`page\` कॉल को \`screen\`, \`app\`, या \`browser\` पर मैप करें। जहाँ Playwright क्वेरी टेक्स्ट के हिस्से से मैच करती थी, वहाँ \`{ exact: false }\` या RegExp जोड़ें।
9. नेविगेशन और आख़िरी असर्शन को \`app.open()\` और लोकेटर असर्शन के साथ डिटर्मिनिस्टिक रखें। जहाँ स्क्रिप्ट किए हुए इंटरैक्शन की कतार बार-बार टूटती है, वहाँ उसके लिए एक \`agent.act\` लक्ष्य सुझाएँ।
10. नई फ़ाइल को \`npx e2e run <file>\` से चलाएँ और पास होने तक ठीक करें। मेरे कन्फ़र्म करने तक Playwright स्पेक को न हटाएँ।
11. संक्षेप में बताएँ कि कौन-से टेस्ट माइग्रेट हुए, कौन-से Playwright में ही रहे, और क्यों।`;

एक ही प्रोजेक्ट में Playwright के साथ-साथ e2e चलाया जा सकता है, ताकि आप एक बार में
एक फ़ाइल करके टेस्ट माइग्रेट कर सकें। `@e2e-dev/web` अपना पिन किया हुआ
`playwright-core` साथ लाता है, इसलिए आपका `@playwright/test` वर्ज़न वैसा ही
रहता है। e2e `e2e.config.ts` पढ़ता है और डिफ़ॉल्ट रूप से `tests/**/*.e2e.ts`
ढूँढता है, इसलिए दोनों फ़ाइल पैटर्न अलग रखें।

## कॉन्फ़िग पोर्ट करें

<Note>[क्विकस्टार्ट](/quickstart) से e2e इंस्टॉल करें और एक मॉडल कॉन्फ़िगर करें।</Note>

Playwright की `testDir`, `baseURL`, `use`, `webServer` या `projects` जैसी कोई
key देने पर एरर आता है, जिसमें सही e2e key का नाम लिखा होता है। हर key की लिस्ट
[कॉन्फ़िग रेफ़रेंस](/reference/config) में है।

| Playwright | e2e |
| --- | --- |
| `use.baseURL`, `webServer` | टारगेट पर `app: { url, command }`, [ऐप शुरू करना](/web#starting-your-app) देखें |
| `webServer.reuseExistingServer` | `app.command: { reuseExisting: true }`; CI इसे अनदेखा करता है |
| `projects` | `targets`, हर एक का अपना इंजन इंस्टेंस |
| `testDir`, `testMatch`, `testIgnore` | `tests`, प्रोजेक्ट रूट से ग्लॉब; शुरुआत में `!` से फ़ाइलें बाहर रखी जाती हैं |
| `retries`, `workers`, `timeout` | वही नाम, [अलग डिफ़ॉल्ट](#defaults-that-differ) के साथ; `workers` एक इंटीजर है |
| `expect.timeout`, `use.actionTimeout`, `globalTimeout` | `assertionTimeout`, `actionTimeout`, `maxDuration`; `maxDuration` की घड़ी ऐप शुरू होने पर नहीं, टेस्ट शुरू होने पर चलती है |
| `expect.toPass` | टॉप-लेवल [`toPass`](/reference/config#topass) |
| `maxFailures`, `use.headless: false` | CLI पर `--max-failures <n>` और `--headed` |
| `reporter`, `outputDir` | `reporters: ['list', 'junit', htmlReporter()]`, जहाँ `htmlReporter` `@e2e-dev/html-reporter` से आता है; साथ में `dot`, `line`, `json`, `markdown` और `ctrf` भी; `output`, डिफ़ॉल्ट `.e2e` |
| `use.viewport`, `deviceScaleFactor`, `locale`, `timezoneId`, `colorScheme`, `reducedMotion`, `userAgent`, `testIdAttribute` | `web({ ... })` में वही key |
| `use.browserName`, `httpCredentials`, `extraHTTPHeaders` | `web({ browser, basicAuth, headers })`; `basicAuth` और `headers` सिर्फ़ ऐप के ऑरिजिन पर लागू होते हैं, [`credentialOrigins`](/reference/web#credentialorigins) से और ऑरिजिन जुड़ते हैं |
| `chromium.connectOverCDP(url)` | `web({ connect: { cdpEndpoint: () => url } })`, सिर्फ़ chromium के लिए |
| `use.trace`, `use.video` | `trace`, `video`: कॉन्फ़िग, टारगेट या टेस्ट पर एक मोड। `web({ screencast: { size } })` वीडियो का साइज़ तय करता है |
| `use.permissions` | टारगेट पर `app.permissions`, [ब्राउज़र परमिशन देना](/web#granting-browser-permissions) देखें |
| `setup` प्रोजेक्ट से `use.storageState` | `session.save(name)` के साथ `test.setup`, फिर टेस्ट पर `{ session }`, [ऑथेंटिकेशन](/authentication) देखें |
| तय वैल्यू के साथ `use.storageState: { cookies }` | फ़िक्स्चर में `browser.setCookies(cookies)` |

## एक स्पेक दोबारा लिखें

ऐसे फ़्लो से शुरू करें जिसके स्टेप अक्सर बदलते हैं, जैसे विज़ार्ड या चेकआउट।
जो Playwright टेस्ट स्थिर हैं, वे वहीं रह सकते हैं।

```ts title="Playwright"
import { test, expect } from '@playwright/test';

test('checkout', async ({ page }) => {
  await page.goto('/cart');
  await page.getByRole('button', { name: 'Checkout' }).click();
  await page.getByLabel('Card number').fill('4242424242424242');
  await page.getByLabel('Expiry').fill('12/30');
  await page.getByLabel('CVC').fill('123');
  await page.getByRole('button', { name: 'Pay' }).click();
  await expect(page.getByRole('heading')).toHaveText('Order confirmed');
});
```

```ts title="e2e"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('checkout', async ({ app, agent, screen }) => {
  await app.open('/cart');
  await agent.act('pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123');
  await expect(screen.getByRole('heading')).toHaveText('Order confirmed');
});
```

एजेंट चेकआउट के स्टेप खुद करता है और फ़ॉर्म बदलने पर ढल जाता है। आप चाहें तो
टेस्ट को पूरी तरह डिटर्मिनिस्टिक भी रख सकते हैं, हर `page.getBy*` लाइन की जगह
`screen.getBy*` लिखकर।

## हर API मैप करें

यहाँ दी गई हर रो आज काम करती है। जो API यहाँ नहीं है, उसके लिए
[e2e में अभी क्या नहीं है](#what-e2e-doesnt-have-yet) देखें। `browser` पर कॉल
सिर्फ़ ब्राउज़र में चलती हैं, इसलिए जो टेस्ट इसे इस्तेमाल करता है वह
`platforms: ['web']` लिखता है और बाकी टारगेट उसे छोड़ देते हैं।

## पेज ऑब्जेक्ट पोर्ट करें

पेज ऑब्जेक्ट क्वेरी और एक्शन के लिए `screen` लेता है, और कीबोर्ड, माउस, CSS
सेलेक्टर और `evaluate` के लिए `browser`। इसे फ़िक्स्चर के ज़रिए टेस्ट को दें:

```ts title="tests/page-models/account-page.ts"
import type { Locator, Screen } from 'e2e';
import type { Browser } from '@e2e-dev/web';

export class AccountPage {
  readonly accountName: Locator;

  constructor(
    readonly screen: Screen,
    readonly browser: Browser,
  ) {
    this.accountName = screen.getByTestId('account-name');
  }

  async filterByNote(note: string) {
    await this.screen.getByRole('button', 'Filter').click();
    await this.screen.getByRole('button', 'Note').click();
    await this.browser.keyboard.type(note);
  }
}
```

```ts title="tests/fixtures.ts"
import { test as base } from '@e2e-dev/web';
import { AccountPage } from './page-models/account-page.ts';

export const test = base.extend<{ accountPage: AccountPage }>({
  accountPage: async ({ screen, browser }, use) => {
    await use(new AccountPage(screen, browser));
  },
});
```

जिस फ़िक्स्चर में `browser` आता है, उसे इस्तेमाल करने वाला हर टेस्ट सिर्फ़ वेब पर
चलता है, [पोर्टेबल रखें](/page-object-model#keep-it-portable) देखें। हुक से
`newPage()` और `page.close()` हटा दें: हर अटेम्प्ट नए कॉन्टेक्स्ट में शुरू होता है।

| `getByRole(role, { includeHidden })` | `browser.locator('role=button[include-hidden=true]')`। रोल क्वेरी ऐक्सेसिबिलिटी ट्री के हिसाब से चलती है |
| टैग के लिए `--grep @smoke`, रेगेक्स पोज़िशनल, `file:line:column` | `--tag smoke`; ग्लॉब या सीधा नाम; `file:line` |
| `getByTitle()` | `browser.locator('[title="Close"]')`। title एक DOM एट्रीब्यूट है, इसलिए इसकी कोई `screen` क्वेरी नहीं है |
| `page.waitForLoadState()` | अगले पेज पर जो दिखता है उस पर असर्शन। नेविगेशन `load` का इंतज़ार करता है, और हर एक्शन और असर्शन अपने नोड का |
| `npx playwright codegen`, Inspector | [`npx e2e mcp`](/mcp-server) से कोडिंग एजेंट टेस्ट लिखते समय ऐप चला सकता है; `screen.debug()` ट्री प्रिंट करता है |
| `{ force: true }`, `{ trial: true }` | `tap({ position })` एक्शनबिलिटी जाँच छोड़ देता है; ट्रायल के लिए `toBeVisible()` और `toBeEnabled()` |
| `ariaSnapshot()`, `toMatchAriaSnapshot()`, `toMatchSnapshot()` | `expect(await screen.tree()).toContain(...)`; एक फ़िक्स्चर फ़ाइल और `toEqual` |
| `keyboard.insertText()`, `<label>` पर `inputValue()` | `fill()`; `getByLabel` से ढूँढा गया खुद कंट्रोल |
| `use.connectOptions`, ट्रेस मोड `retain-on-first-failure` और `retain-on-failure-and-retries` | CDP पर `web({ connect })`, सिर्फ़ chromium; `retain-on-failure` |

## जानबूझकर रखे गए फ़र्क

- स्ट्रिंग पूरे टेक्स्ट से मैच करती है और केस-सेंसिटिव होती है। Playwright के
  `getByRole` नाम, `getByLabel`, `getByPlaceholder` और `getByText` केस-इनसेंसिटिव
  सबस्ट्रिंग से मैच करते हैं। टेक्स्ट के हिस्से के लिए `{ exact: false }` या
  `RegExp` पास करें। [क्वेरी](/reference/screen#queries) देखें।

  ```ts
  // <button>Save changes</button>, <label>Email address <input></label>
  screen.getByRole('button', 'Save');                  // no match
  screen.getByRole('button', { name: 'Save', exact: false });    // matches
  screen.getByRole('button', 'save changes');          // no match, case differs
  screen.getByLabel('Email');                                    // no match
  ```
- टेक्स्ट रीड रेंडर हुआ टेक्स्ट पढ़ते हैं। `textContent()`, `toHaveText` और
  `toContainText` वही पढ़ते हैं जो `innerText` लौटाता है, इसलिए छिपा हुआ टेक्स्ट
  छूट जाता है और `text-transform` लागू होता है।
  [लोकेटर रीड](/reference/screen#locator-reads) देखें। इसके बजाय `toBeEmpty`
  Playwright का नियम रखता है, इसलिए छिपे टेक्स्ट से नोड खाली नहीं माना जाता।
- `toHaveRole` में `getByRole` की शब्दावली चलती है, इसलिए `paragraph`, `generic`
  और बाकी छोड़े गए रोल टाइप एरर देते हैं, और `img` को `image` पढ़ा जाता है। यह
  उस रोल से तुलना करता है जो ट्री पढ़ता है, जहाँ `contenteditable` एडिटर
  `textbox` होता है।
- लोकेटर स्ट्रिक्ट होता है। एक से ज़्यादा मैच पर एक्शन, रीड या पॉज़िटिव मैचर
  `LOCATOR_AMBIGUOUS` देता है, जबकि Playwright के `page.click(selector)` और
  `isVisible()` पहला मैच लेते हैं। `filter` या `first()` से दायरा छोटा करें।
- `.not.toBeChecked()` किसी बटन या हेडिंग पर भी पास हो जाता है। कंट्रोल को उसके
  रोल से ढूँढें, ताकि कंट्रोल का प्रकार बदलने पर असर्शन फ़ेल हो।
- अगर `expect.poll` की रीड एरर फेंकती है, तो उसे रीट्राई किया जाता है।
- `toPass` के लिए रिपोर्ट में हर कोशिश के अंदर वाले स्टेप ही दिखते हैं।
- सेशन एक रन तक चलते हैं। `test.setup` स्टेट को एक नाम से सेव करता है और
  `{ session }` उसे रिस्टोर करता है। फ़ाइल एन्क्रिप्ट होती है और क्लीनअप पर डिलीट
  हो जाती है, इसलिए दोबारा इस्तेमाल के लिए कोई `.auth/user.json` नहीं होती।
- टेस्ट को रॉ `Page` नहीं मिलता, क्योंकि उस पर कुछ भी रिकॉर्ड, छिपाया या मास्क
  नहीं होता। `surfaceOf(engine)` टेस्ट कोड के लिए नहीं,
  [कस्टम एक्ज़ीक्यूटर](/executors#driving-the-page-yourself) के लिए है।

| सेटिंग | Playwright | e2e |
