1. ऊपर दी गई माइग्रेशन गाइड पढ़ें। इसमें Appium की कैपेबिलिटी, सेलेक्टर और कमांड को e2e से मैप किया गया है, और यह भी लिखा है कि e2e में अभी क्या नहीं है। मोबाइल गाइड में डिवाइस और ऐप बिल्ड के बारे में बताया गया है।
2. e2e टेस्ट Node में चलते हैं, डिफ़ॉल्ट रूप से TypeScript में या JavaScript में। अगर Appium टेस्ट सूट Java, Python या किसी और भाषा में है, या प्रोजेक्ट में \`package.json\` नहीं है, तो ऐप के बगल में एक \`e2e/\` फ़ोल्डर में टेस्ट प्रोजेक्ट बनाएँ।
3. अगर टेस्ट प्रोजेक्ट में कोई e2e कॉन्फ़िग (\`e2e.config.ts\`, \`.mts\`, \`.js\`, या \`.mjs\`) नहीं है, तो वहाँ \`npx e2e init --yes --engine mobile\` (या pnpm या bun की बराबर कमांड) चलाएँ। यह इस मशीन के प्लेटफ़ॉर्म के लिए एक टारगेट वाला मोबाइल कॉन्फ़िग और Settings ऐप पर एक उदाहरण टेस्ट लिखता है, और अभी कुछ इंस्टॉल नहीं करता। \`tests/example.e2e.ts\` को अपने ऐप के लिए दोबारा लिखें या हटा दें।
4. e2e स्किल पढ़ें (\`npx e2e guide\` इसे प्रिंट करता है, \`npx e2e guide <topic>\` एक टॉपिक प्रिंट करता है) और नीचे के हर स्टेप में इसका पालन करें।
5. अगर आपने init चलाया है, तो मुझसे पूछें कि एजेंट स्टेप के लिए कौन-सा मॉडल इस्तेमाल करना है: ChatGPT, GitHub Copilot, OpenCode Console या SuperGrok सब्सक्रिप्शन, कोई API key, या लोकल मॉडल। उसे उसके प्रोवाइडर पैकेज से कॉन्फ़िगर करें। अगर इसमें साइन इन चाहिए, तो मुझे \`npx e2e login\` कमांड दें और मेरे कन्फ़र्म करने तक रुकें।
6. गाइड की टेबल देखकर कैपेबिलिटी को e2e कॉन्फ़िग में पोर्ट करें: हर प्लेटफ़ॉर्म के लिए \`mobile({ platform, device })\` के साथ एक टारगेट, और हर टारगेट पर \`app: { bundleId, appPath, launchArguments, permissions }\`। पासवर्ड और टोकन को \`credentials\` या \`secrets\` में ले जाएँ।
7. डिपेंडेंसी इंस्टॉल करें, फिर \`npx e2e doctor\` (e2e 0.23.0 या नया) चलाएँ और जो भी वह बताए उसे ठीक करें।
8. Appium टेस्ट की लिस्ट दिखाएँ और मुझसे पूछें कि पहले किसे माइग्रेट करना है। ऐसा टेस्ट सुझाएँ जिसके XPath सेलेक्टर या एक्सप्लिसिट वेट बार-बार टूटते हों।
9. उस टेस्ट को \`tests/\` के अंदर \`.e2e.ts\` फ़ाइल में दोबारा लिखें (e2e डिफ़ॉल्ट रूप से \`tests/**/*.e2e.ts\` चलाता है)। इसकी शुरुआत \`app.open()\` से करें, क्योंकि कोई भी ऐप अपने आप लॉन्च नहीं होता। गाइड के "सेलेक्टर दोबारा लिखें" सेक्शन का पालन करें: XPath का कोई पोर्ट नहीं है, और कई मैच मिलने पर e2e फ़ेल हो जाता है। टेस्ट पोर्ट करने से पहले टेस्ट में इस्तेमाल होने वाली हर कैपेबिलिटी और कमांड के लिए "e2e में अभी क्या नहीं है" सेक्शन देखें। "अभी क्या इस्तेमाल करें" वाला वर्कअराउंड इस्तेमाल करें, या उस टेस्ट को Appium में ही रहने दें और मुझे वजह बताएँ।
10. लॉन्च और आख़िरी असर्शन को \`app.open()\` और लोकेटर असर्शन के साथ डिटर्मिनिस्टिक रखें। जहाँ स्क्रिप्ट किए हुए टैप की कतार बार-बार टूटती है, वहाँ उसके लिए एक \`agent.act\` लक्ष्य सुझाएँ।
11. ऐप बिल्ड और इंस्टॉल करें, हर प्लेटफ़ॉर्म टारगेट पर नई फ़ाइल को \`npx e2e run <file>\` से चलाएँ, और पास होने तक ठीक करें। मेरे कन्फ़र्म करने तक Appium टेस्ट को न हटाएँ।
12. संक्षेप में बताएँ कि कौन-से टेस्ट माइग्रेट हुए, कौन-से Appium में ही रहे, और क्यों।`;

e2e Appium सर्वर, उसके ड्राइवर और क्लाइंट लाइब्रेरी की जगह एक Node पैकेज
देता है। `@e2e-dev/mobile` अपने साथ आने वाले
[agent-device](https://github.com/callstack/agent-device) के ज़रिए iOS
सिम्युलेटर, Android एम्युलेटर और जुड़े हुए फ़ोन चलाता है। कैपेबिलिटी
`e2e.config.ts` में एक टारगेट बन जाती हैं, और `driver` कमांड `app` और
`device` फ़िक्स्चर बन जाते हैं। आपका ऐप बिल्ड और उसकी ऐक्सेसिबिलिटी id वैसी
ही रहती हैं।

उदाहरणों में WebdriverIO इस्तेमाल किया गया है। Java या Python क्लाइंट भी इसी
तरह मैप होता है।

## कैपेबिलिटी पोर्ट करें

<Note>[मोबाइल गाइड](/mobile) से एक टारगेट और [क्विकस्टार्ट](/quickstart) से एक मॉडल सेटअप करें। मॉडल सिर्फ़ एजेंट स्टेप के लिए ज़रूरी है।</Note>

| Appium | e2e |
| --- | --- |
| `platformName`, `appium:automationName` | `mobile({ platform: 'ios' })` या `'android'` |
| `appium:deviceName`, `appium:udid` | `mobile({ device: 'iPhone 17' })`: कोई नाम, सिम्युलेटर UDID, या `emulator-5554` सीरियल। फ़ोन उसके नाम से चुना जाता है |
| `appium:app` | `app: { appPath }`। बिल्ड खुद इंस्टॉल करें, [अपने ऐप को टारगेट करें](/mobile#point-at-your-app) देखें |
| `appium:bundleId`, `appium:appPackage` | `app: { bundleId }`, वह ऐप जिसे `app.open()` लॉन्च करता है |
| `appium:processArguments`, `appium:optionalIntentArguments` | `app.launchArguments`, स्ट्रिंग की लिस्ट या आर्ग्युमेंट नाम से वैल्यू का ऑब्जेक्ट |
| `appium:permissions` | `app.permissions: { camera: 'grant' }`। हर [`DevicePermission`](/reference/mobile#device-fixture) नाम `grant`, `deny` या `reset` लेता है |
| `appium:noReset` | `true` डिफ़ॉल्ट है, इसलिए ऐप का डेटा साफ़ नहीं होता। `false` के लिए टेस्ट की शुरुआत में `app.clearState()` कॉल करें |
| `appium:fullReset` | `device.installApp(path, { reinstall: true })` |
| `appium:newCommandTimeout`, WebDriverAgent टाइमआउट | ज़रूरत नहीं। एक्शन `actionTimeout`, असर्शन `assertionTimeout` और टेस्ट `timeout` इस्तेमाल करते हैं |
| `bstack:options`, `lt:options` | डिवाइस प्रोवाइडर: [`browserstack()`](/integrations/browserstack) या [`testmu()`](/integrations/testmu) |
| होस्टेड डिवाइस पर `appium:platformVersion`, `appium:language`, `appium:locale` | `browserstack()` और `testmu()` पर `osVersion`, `language` और `locale`; [`limrun()`](/integrations/limrun) पर `android.osVersion` |
| कई कैपेबिलिटी, `maxInstances` | हर प्लेटफ़ॉर्म के लिए एक टारगेट, `workers`, और हर डिवाइस के लिए एक वर्कर के साथ `device` लिस्ट |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    {
      name: 'ios',
      engine: mobile({ platform: 'ios', device: 'iPhone 17' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'ios/build/MyApp.app',
        launchArguments: ['-e2e', 'YES'],
        permissions: { notifications: 'grant' },
      },
    },
    {
      name: 'android',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'android/app/build/outputs/apk/release/app-release.apk',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { notifications: 'grant' },
      },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

## एक टेस्ट दोबारा लिखें

ऐसे टेस्ट से शुरू करें जिसके XPath सेलेक्टर या एक्सप्लिसिट वेट बार-बार टूटते हैं।

```js title="Appium (WebdriverIO)"
describe('login', () => {
  it('signs in', async () => {
    await $('~email').setValue('ada@example.test');
    await $('~password').setValue('hunter2');
    await $('//XCUIElementTypeButton[@name="Sign in"]').click();
    await $('~welcome').waitForDisplayed({ timeout: 10000 });
    await expect($('~welcome')).toHaveText('Welcome, Ada');
  });
});
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('email').fill('ada@example.test');
  await screen.getByTestId('password').fill('hunter2');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByText('Welcome, Ada')).toBeVisible({ timeout: 10_000 });
});
```

- कुछ भी अपने आप लॉन्च नहीं होता, इसलिए टेस्ट `app.open()` से शुरू होता है।
- एक्शन अपने एलिमेंट का इंतज़ार करते हैं और असर्शन रीट्राई होते हैं, इसलिए
  एक्सप्लिसिट वेट की ज़रूरत नहीं रहती।

जहाँ स्क्रिप्ट किए हुए टैप की कतार बार-बार टूटती है, वहाँ एक `agent.act` लक्ष्य
उसकी जगह ले सकता है। बाद की जाँच पास होते ही [रीप्ले कैश](/cache) उसके एक्शन
रिकॉर्ड कर लेता है, और अगले रन में उन्हें बिना मॉडल कॉल के रीप्ले करता है।
पासवर्ड [कॉन्फ़िगर किए हुए क्रेडेंशियल](/authentication) में जाता है, जिसे मॉडल
कभी नहीं देखता:

```ts
import { credentials } from 'e2e';

const ada = credentials.user('ada');
await agent.act('sign in as {username}', { params: { username: ada.username, password: ada.password } });
```

## सेलेक्टर दोबारा लिखें

| Appium | e2e |
| --- | --- |
| iOS पर `$('~login')`, ऐक्सेसिबिलिटी आइडेंटिफ़ायर या React Native `testID` | `screen.getByTestId('login')` |
| Android पर `$('~Log in')`, कंटेंट डिस्क्रिप्शन या React Native `accessibilityLabel` | `screen.getByLabel('Log in')` |
| `$('id=com.example:id/email')`, `resourceId` | `screen.getByTestId('email')`; `com.example:id/` प्रीफ़िक्स ऑप्शनल है |
| `-ios predicate string:label == "Sign in"`, `android=new UiSelector().text("Sign in")` | `screen.getByText('Sign in')` या `getByLabel('Sign in')` |
| `-ios class chain`, क्लास नाम (`XCUIElementTypeButton`, `android.widget.Button`) | `screen.getByRole('button', 'Sign in')` |
| `$$(selector)[2]` | `.nth(2)`; `.all()` हर मैच लौटाता है |
| ऐसा सेलेक्टर जो क्वेरी से न लिखा जा सके | `device.locator('role=text label="Total"')`, agent-device का सेलेक्टर सिंटैक्स |

- `getByText`, `getByLabel` और `getByTestId` केस समेत पूरी स्ट्रिंग से मैच
  करते हैं। टेक्स्ट या लेबल के केस-इनसेंसिटिव हिस्से के लिए `RegExp` या
  `{ exact: false }` पास करें।
- Appium का `$()` पहला मैच लौटाता है। e2e एक्शन को ठीक एक मैच चाहिए और कई
  मैच पर `LOCATOR_AMBIGUOUS` के साथ फ़ेल होता है। `.filter()`, `.first()` या
  `.nth()` से दायरा छोटा करें।
- `button`, `textbox` और `switch` जैसे रोल iOS और Android पर एक जैसे हैं,
  इसलिए एक ही टेस्ट दोनों पर चलता है। [रोल](/reference/mobile#roles) देखें।

## हर कमांड मैप करें

`device` पर कॉल सिर्फ़ डिवाइस पर चलती हैं। जो टेस्ट सूट वेब पर भी चलता है, वह
इन टेस्ट पर `platforms: ['ios', 'android']` लिखता है।

## परमिशन और डीप लिंक

`app.open()` से पहले परमिशन सेट करें, क्योंकि iOS पर परमिशन बदलने से चलता हुआ
ऐप बंद हो जाता है। जो परमिशन हर टेस्ट को चाहिए वे `app.permissions` में जाती हैं।

```js title="Appium (WebdriverIO)"
await driver.execute('mobile: setPermission', {
  bundleId: 'com.example.app',
  access: { location: 'yes' },
});
await driver.activateApp('com.example.app');
await driver.url('myapp://orders/42');
await expect($('~order-title')).toHaveText('Order #42');
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('opens an order from a link', async ({ app, device, screen }) => {
  await device.setPermission('location', 'grant');
  await app.open();
  await device.openLink('myapp://orders/42');
  await expect(screen.getByText('Order #42')).toBeVisible();
});
```

## e2e में अभी क्या नहीं है

"प्लान में है" वाली रो रोडमैप पर हैं, और "अभी नहीं" वालों की कोई तारीख़ नहीं है।
"प्लान में नहीं" वाली रो जानबूझकर बाहर रखी गई हैं। [`unstable_raw`](/reference/mobile#unstable_raw)
के ज़रिए की गई कॉल स्टेप नहीं होती, इसलिए वह रिपोर्ट और सीक्रेट रेडैक्शन को छोड़
देती है।
