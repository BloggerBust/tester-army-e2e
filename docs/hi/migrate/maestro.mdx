## एक फ़्लो दोबारा लिखें

ऐसे फ़्लो से शुरू करें जिसके `optional` स्टेप और `runFlow: { when }` ब्रांच
बार-बार अपडेट करने पड़ते हैं।

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

## सेलेक्टर दोबारा लिखें

- Maestro टेक्स्ट और id को केस-इनसेंसिटिव रेगुलर एक्सप्रेशन की तरह पढ़ता है।
  `getByText` और `getByTestId` केस समेत पूरी स्ट्रिंग से मैच करते हैं।
  `getByText(/^mute account$/i)` लिखें, या टेक्स्ट के हिस्से के लिए
  `{ exact: false }`।
- कई मैच मिलने पर Maestro पहले पर टैप करता है। e2e `LOCATOR_AMBIGUOUS` के साथ
  फ़ेल होता है, इसलिए जब आपका मतलब पहला मैच हो तो `.first()` जोड़ें।
- `optional` और `runFlow: { when }` की जगह `isVisible()` लेता है। यह स्क्रीन को
  एक बार पढ़ता है और इंतज़ार नहीं करता। यह कई मैच पर फ़ेल होता है, इसलिए जब कोई
  छिपा हुआ डुप्लिकेट हो सकता हो तो `{ visible: true }` या `.first()` जोड़ें।
- `below`, `above`, `leftOf` और `rightOf` का कोई पोर्ट नहीं है,
  [अभी नहीं](#not-yet) देखें। iOS पर प्लेन React Native `View` पर
  `filter({ has })` और चेनिंग कुछ भी मैच नहीं करते,
  [डिवाइस की जानी-पहचानी सीमाएँ](/mobile#known-device-limitations) देखें।

## e2e में अभी क्या नहीं है

"प्लान में है" रोडमैप पर है, और "अभी नहीं" की कोई तारीख़ नहीं है। "प्लान में
नहीं" को जानबूझकर बाहर रखा गया है।

### प्लान में है

| Maestro | अभी क्या इस्तेमाल करें |
| --- | --- |
| `permissions: { all }`, सबको परमिशन देने वाला डिफ़ॉल्ट, `bluetooth` और `storage` जैसे नाम | हर परमिशन का नाम `app.permissions` में लिखें, या `device.alert('accept')` से प्रॉम्प्ट स्वीकार करें |
| बिना फ़ील्ड के `inputText` और `pressKey: Enter`, `eraseText: N`, `pressKey: backspace`, `tab` | फ़ील्ड के लोकेटर पर `fill` या `press`; मिटाने के लिए छोटा किया हुआ `inputValue()` `fill` करें; Tab के लिए अगला फ़ील्ड टैप करें |
| `addMedia` | iOS सिम्युलेटर पर `app.open()` से पहले `xcrun simctl addmedia`; Android की जाँच नहीं हुई है। [device फ़िक्स्चर](/mobile#the-device-fixture) के नीचे "पिकर टेस्ट के लिए फ़ोटो" देखें |
| कमांड पर `label` | `-`। हर स्टेप का नाम उसकी कॉल से आता है |
| `scrollUntilVisible: { centerElement, visibilityPercentage }` | सटीक बराबर कुछ नहीं। इसके पूरा होने के बाद `boundingBox()` पढ़ें, और अगर नोड बीच में नहीं है तो `screen.swipe({ direction, momentum: 'slow' })` चलाएँ |
| फ़ेलियर के बगल में डिवाइस लॉग और क्रैश रिपोर्ट | फ़िक्स्चर में इकट्ठा किया गया `adb logcat` या `xcrun simctl spawn <udid> log stream` |
| टर्मिनल कमांड के रूप में `maestro hierarchy` | एक लाइन का टेस्ट जो `screen.debug()` कॉल करे |
| `--device-locale` | iOS पर `app.launchArguments: { AppleLanguages: ['de'], AppleLocale: 'de_DE' }`, [ऐप को दूसरी भाषा में चलाएँ](/mobile#run-the-app-in-another-language) देखें; Android पर रन से पहले डिवाइस की भाषा सेट करें |
| Maestro Cloud | [होस्टेड डिवाइस प्रोवाइडर](/mobile#hosted-devices) के साथ आपका [CI](/ci) |
| `pressKey: lock`, `power`, `volume up`, `volume down` | [`unstable_raw`](/reference/mobile#unstable_raw) पर `client.command.hardwareButton`: Android पर पावर और वॉल्यूम, असली iPhone पर वॉल्यूम |
| JUnit `properties`, `--output` के साथ JUnit पाथ | टैग या टाइटल में id; रन के बाद `.e2e/junit.xml` कॉपी करें |

### अभी नहीं

| Maestro | अभी क्या इस्तेमाल करें |
| --- | --- |
| `optional: true` | `if (await locator.isVisible())` या try/catch; रिपोर्ट में कोई चेतावनी नहीं दिखती |
| `executionOrder` | एक `describe(..., { serial: true })` जो हर फ़्लो को फ़ंक्शन की तरह कॉल करे |
| `retry: { maxRetries, commands }` | try/catch वाला `for` लूप; वैल्यू के लिए `expect.poll`, पूरे टेस्ट के लिए `{ retries }` |
| `killApp` से Android प्रोसेस बंद करना | `device.home()`, फिर `adb shell am kill <package>`, फिर `device.openApp(id)` |
| `assertDarkMode`, `assertLightMode` | थीम वाले कंट्रोल पर असर्ट करें, या `toHaveScreenshot` |
| `Remote System Navigation Up`, `Down`, `Remote Button A`, `B` | `-` |

### प्लान में नहीं

| Maestro | इसकी जगह क्या इस्तेमाल करें |
| --- | --- |
| रेगेक्स के रूप में टेक्स्ट और id, पहला मैच जीतता है | एक `RegExp` और `.first()`, [सेलेक्टर दोबारा लिखें](#rewrite-selectors) देखें |
| `retryTapIfNoChange` | नतीजे पर असर्ट करें, फिर टेस्ट में दोबारा टैप करें। बिना देखे दूसरा टैप किसी कंट्रोल को दो बार चला सकता है |
| `waitToSettleTimeoutMs` | एक्शन के बाद अपने `timeout` के साथ एक असर्शन; वही असर्शन वेट है |
| `toggleAirplaneMode`, `toggleDarkMode` | सीधे वह स्टेट सेट करें जो आपको चाहिए: `device.setAirplaneMode(true)`, `device.setAppearance('dark')` |
| Maestro Studio | [`npx e2e mcp`](/mcp-server) पर कोडिंग एजेंट, या `npx e2e run --watch` या `--step` के साथ `screen.debug()` |
| `waitForAnimationToEnd` | एनिमेशन जिस चीज़ पर ख़त्म होता है उस पर `await expect(locator).toBeVisible()` |
| `below`, `above`, `leftOf`, `rightOf` | `getByLabel`, एक टेस्ट id, शेयर किए हुए कंटेनर पर `filter({ has })`, या एक `agent.act` लक्ष्य |

## जानबूझकर रखे गए फ़र्क

- Maestro ऐप लॉन्च करते समय हर परमिशन दे देता है। e2e तब तक कोई परमिशन नहीं
  देता जब तक आप उसका नाम न लिखें, इसलिए पोर्ट किए हुए फ़्लो में वे सिस्टम
  प्रॉम्प्ट आ सकते हैं जो Maestro में कभी नहीं दिखे। हर परमिशन का नाम
  [`app.permissions`](/mobile#launch-arguments-and-permissions) में लिखें,
  जहाँ Maestro के `allow`, `deny` और `unset` के लिए `grant`, `deny` और
  `reset` होते हैं।
- [`device.unstable_raw`](/reference/mobile#unstable_raw) के ज़रिए की गई कॉल
  स्टेप नहीं होतीं। रिपोर्ट, ट्रेस, एजेंट कैश और रेडैक्शन उन्हें छोड़ देते हैं।
- डिवाइस में `test.setup` या `{ session }` नहीं होता,
  [वेब से क्या अलग है](/mobile#what-differs-from-the-web) देखें।
