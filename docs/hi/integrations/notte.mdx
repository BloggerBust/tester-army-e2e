`@e2e-dev/notte` का `notte()` [Notte](https://notte.cc) के लिए एक
[ब्राउज़र प्रोवाइडर](/browser#hosted-browsers) है। हर टेस्ट अटेम्प्ट को अपना
क्लाउड ब्राउज़र सेशन मिलता है। टेस्ट वैसे ही रहते हैं। सिर्फ़ टारगेट का
`browser` बदलता है।

## सेटअप

प्रोवाइडर और Notte SDK इंस्टॉल करें:

<CodeGroup>
```bash npm
npm install --save-dev @e2e-dev/notte notte-sdk
```

```bash pnpm
pnpm add -D @e2e-dev/notte notte-sdk
```

```bash bun
bun add -d @e2e-dev/notte notte-sdk
```
</CodeGroup>

टारगेट के `browser` को `notte()` पर सेट करें:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { notte } from '@e2e-dev/notte';

export default {
  targets: [
    {
      name: 'notte',
      engine: web({ browser: notte() }),
      app: { url: 'https://staging.example.com' },
    },
  ],
} satisfies E2EConfig;
```

`NOTTE_API_KEY` को उस एनवायरनमेंट में सेट करें जिसमें `e2e run` शुरू होता है,
जैसे CI सीक्रेट से। Key [Notte कंसोल](https://console.notte.cc/apikeys) से कॉपी
करें। `workers` तय करता है कि एक साथ कितने सेशन चलें। ऐप तक क्लाउड ब्राउज़र
का पहुँचना ज़रूरी है। इसलिए `app.url` को किसी डिप्लॉय किए हुए या टनल वाले URL पर
रखें, `localhost` पर नहीं।

Key न हो, या Notte कोई एरर दे, तो अटेम्प्ट उसी मैसेज के साथ फ़ेल हो जाता है।

## ऑप्शन

`notte(options)` Notte की start-session बॉडी को जैसी है वैसी ही लेता है:
`solve_captchas`, `proxies`, `browser_type`, `idle_timeout_minutes`,
`max_duration_minutes`, `viewport_width` और `viewport_height`, `profile`,
`user_agent`, `extra_http_headers`, `block_ads`, और आपके `notte-sdk` में
`ApiSessionStartRequest` का बाकी हिस्सा:

```ts
web({
  browser: notte({ solve_captchas: true, proxies: true, idle_timeout_minutes: 5 }),
})
```

`cdp_url` और मैनेज्ड ऑथेंटिकेशन वाले फ़ील्ड (`auth_ids`, `auth_retry`,
`wait_for_authentication`) इसमें नहीं लिए जाते। पहला किसी दूसरे प्रोवाइडर का
ब्राउज़र बताता है। बाकी फ़ील्ड सेशन तब लौटा देते हैं, जब उससे अभी जुड़ा नहीं जा सकता।

## हर अटेम्प्ट का एक सेशन

प्रोवाइडर सिर्फ़ `attempt` स्कोप में लीज़ पर लेता है। Notte सेशन के पास अपना एक ही
ब्राउज़र कॉन्टेक्स्ट होता है, और वह नए कॉन्टेक्स्ट बनाने नहीं देता। लेकिन टेस्ट
को एक-दूसरे से अलग रखने के लिए `worker` स्कोप को नए कॉन्टेक्स्ट ही चाहिए। हर
अटेम्प्ट, रीट्राई भी, एक नए सेशन के डिफ़ॉल्ट कॉन्टेक्स्ट में, उसके पहले टैब पर
चलता है। हर टेस्ट को नया सेशन शुरू करने की कीमत चुकानी पड़ती है। साथ ही
[हर अटेम्प्ट वाली लीज़ की सीमाएँ](/browser#hosted-browsers) लागू होती हैं, जिनमें
सेव किए गए सेशन वाली सीमा भी है।

## सेशन पर नज़र रखें और क्लीनअप करें

रिपोर्टर हर नए सेशन के लिए `session <id>, watch at <console URL>` लॉग करता
है। लिंक सेशन को Notte कंसोल में खोलता है: टेस्ट चलते समय लाइव, और ख़त्म होने के
बाद रीप्ले की तरह। इसे खोलने के लिए कंसोल में साइन इन करना पड़ता है, इसलिए यह
पब्लिक CI लॉग में भी सुरक्षित है। `NOTTE_API_URL` सेट हो, तो रिपोर्टर सिर्फ़
`session <id>` लॉग करता है, क्योंकि प्रोवाइडर नहीं जान सकता कि उस API का कंसोल
कौन-सा है।

अटेम्प्ट चाहे जिस रास्ते से ख़त्म हो, प्रोवाइडर उसका सेशन बंद कर देता है। रन
ख़त्म होने पर यह उन वर्करों के सेशन भी बंद करता है जो ऐसा करने से पहले ही अचानक
बंद हो गए। अगर रन खुद अचानक बंद हो जाए, तो Notte हर सेशन को
`idle_timeout_minutes` तक कोई एक्टिविटी न होने पर बंद कर देता है, डिफ़ॉल्ट रूप से
3 मिनट। Notte हर सेशन को `max_duration_minutes` के बाद भी ख़त्म कर देता है,
डिफ़ॉल्ट रूप से 15 मिनट। इसलिए जो टेस्ट इससे ज़्यादा देर चलता है, उसके लिए इसे
बढ़ा दें।

## डाउनलोड

`browser.waitForDownload` वैसे ही काम करता है जैसे लोकल में। ब्राउज़र जो भी फ़ाइल
डाउनलोड करता है, Notte उसे सेशन के फ़ाइल स्टोरेज में रखता है, उसी नाम से जो साइट
ने सुझाया था। प्रोवाइडर उस नाम की फ़ाइल अटेम्प्ट के आर्टिफ़ैक्ट में कॉपी करता है।

## लोकल ब्राउज़र से फ़र्क

- Notte JavaScript डायलॉग का जवाब खुद दे देता है। टेस्ट का डायलॉग हैंडलर उन्हें
  ऐक्सेप्ट कर पाए, उससे पहले ही `confirm` `false` लौटा देता है और `prompt` `null`।
- ब्राउज़र Windows वाले कीबोर्ड कॉम्बिनेशन लेता है। `ControlOrMeta` रनर के सिस्टम
  के हिसाब से चलता है, इसलिए Mac पर यह `Meta` भेजता है, जिसे ब्राउज़र नज़रअंदाज़
  कर देता है। जो टेस्ट Mac से भी चलता है, उसमें `Control+A` लिखें।
- `setInputFiles` 50 MB तक की फ़ाइलें अपलोड करता है। फ़ोल्डर अपलोड नहीं होते।
- ऐप तक Notte के क्लाउड का पहुँचना ज़रूरी है, इसलिए `localhost` वाले पते लोड नहीं
  होते। `app.url` को किसी डिप्लॉय किए हुए या टनल वाले URL पर रखें।
- `app.clearState()` और सेव किए गए [सेशन](/authentication) काम नहीं करते, जैसे
  हर अटेम्प्ट वाली किसी भी लीज़ में। हर अटेम्प्ट वैसे भी नए सेशन पर शुरू होता है।
