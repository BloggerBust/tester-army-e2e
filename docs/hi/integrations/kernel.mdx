`@e2e-dev/kernel` का `kernel()` [Kernel](https://kernel.sh) के लिए एक
[ब्राउज़र प्रोवाइडर](/browser#hosted-browsers) है। हर वर्कर स्लॉट को, या हर
अटेम्प्ट को, अपना होस्टेड Chromium मिलता है। टेस्ट वैसे ही रहते हैं। सिर्फ़
टारगेट का `browser` बदलता है।

## सेटअप

प्रोवाइडर और Kernel SDK इंस्टॉल करें:

<CodeGroup>
```bash npm
npm install --save-dev @e2e-dev/kernel @onkernel/sdk
```

```bash pnpm
pnpm add -D @e2e-dev/kernel @onkernel/sdk
```

```bash bun
bun add -d @e2e-dev/kernel @onkernel/sdk
```
</CodeGroup>

टारगेट के `browser` को `kernel()` पर सेट करें:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { kernel } from '@e2e-dev/kernel';

export default {
  targets: [
    {
      name: 'kernel',
      engine: web({ browser: kernel() }),
      app: { url: 'https://staging.example.com' },
    },
  ],
} satisfies E2EConfig;
```

`KERNEL_API_KEY` को उस एनवायरनमेंट में सेट करें जिसमें `e2e run` शुरू होता है,
जैसे CI सीक्रेट से। `workers` तय करता है कि एक साथ कितने ब्राउज़र चलें।

Key न हो, या Kernel कोई एरर दे, तो लीज़ उसी मैसेज के साथ फ़ेल हो जाती है।
`worker` स्कोप में रन किसी भी टेस्ट से पहले ख़त्म हो जाता है। `attempt` स्कोप में
सिर्फ़ वह अटेम्प्ट फ़ेल होता है।

## स्क्रीन भरें

स्क्रीन का साइज़ Kernel के `viewport` से सेट करें। साथ में वेब इंजन का
`viewport: null` भी दें, ताकि पेज विंडो का साइज़ ले ले:

```ts
web({
  browser: kernel({ viewport: { width: 1920, height: 1080 } }),
  viewport: null,
})
```

विंडो मैक्सिमाइज़ होकर खुलती है, और पेज [उसे भर देता है](/web#fill-the-window):
1920 बाय 1080 की स्क्रीन पर 1920 बाय 993। वेब का `viewport` तय हो, तो लाइव
व्यू में पेज कटा हुआ दिखता है, या विंडो के सिर्फ़ एक हिस्से में।

## ऑप्शन

`kernel(options)` Kernel की create-browser बॉडी को जैसी है वैसी ही लेता है:
`stealth`, `headless`, `timeout_seconds`, `profile`, `proxy_id`, `viewport`,
`tags`, और आपके `@onkernel/sdk` में `BrowserCreateParams` का बाकी हिस्सा। यह दो
ऑप्शन अपनी तरफ़ से जोड़ता है:

| ऑप्शन   | डिफ़ॉल्ट    | मतलब |
| -------- | ---------- | ------- |
| `scope`  | `'worker'` | हर वर्कर स्लॉट पर एक ब्राउज़र, या हर अटेम्प्ट पर एक। [स्कोप](#scopes) देखें। |
| `replay` | `true`     | Kernel का रीप्ले या इंजन का स्क्रीनकास्ट। [रिकॉर्डिंग](#recordings) देखें। |

## स्कोप

`scope: 'worker'` पूरे रन के लिए हर वर्कर स्लॉट पर एक ब्राउज़र रखता है। हर
अटेम्प्ट को उस पर एक नया ब्राउज़र कॉन्टेक्स्ट मिलता है, जैसे लोकल रन में।
इसलिए कोई टेस्ट किसी दूसरे टेस्ट की कुकी, स्टोरेज या परमिशन कभी नहीं देखता।
Kernel का पहला टैब इसके पीछे खुला रहता है। Kernel `profile` का यहाँ कोई असर नहीं
होता, क्योंकि वह सिर्फ़ ब्राउज़र के डिफ़ॉल्ट कॉन्टेक्स्ट पर लागू होता है।

`scope: 'attempt'` हर अटेम्प्ट के लिए नया ब्राउज़र लीज़ पर लेता है, रीट्राई के
लिए भी। अटेम्प्ट उस ब्राउज़र के डिफ़ॉल्ट कॉन्टेक्स्ट में, उसके पहले टैब पर चलता
है। इसलिए `profile` लागू होता है, और लाइव व्यू में एक ही टैब दिखता है। हर टेस्ट
को नया ब्राउज़र शुरू करने की कीमत चुकानी पड़ती है। साथ ही
[हर अटेम्प्ट वाली लीज़ की सीमाएँ](/browser#hosted-browsers) लागू होती हैं, जिनमें
सेव किए गए सेशन वाली सीमा भी है।

## रिकॉर्डिंग

जो अटेम्प्ट [वीडियो](/reference/config#video) रिकॉर्ड करता है, उसे ब्राउज़र की
स्क्रीन का Kernel रीप्ले मिलता है। यह उसकी आर्टिफ़ैक्ट डायरेक्टरी में
`video/replay.mp4` के नाम से सेव होता है। रीप्ले में पूरी विंडो दिखती है, टैब और
एड्रेस बार समेत, उस साइज़ पर जो Kernel का `viewport` सेट करता है।

रीप्ले Kernel के डिफ़ॉल्ट 10 fps पर चलते हैं। इसे बदलना है, तो Kernel की
start-replay बॉडी (`framerate`, `max_duration_in_seconds`, `record_audio`) पास
करें: `kernel({ replay: { framerate: 20 } })`। 20 से ज़्यादा `framerate` के लिए
ब्राउज़र पर `gpu: true` चाहिए।

Kernel सिर्फ़ हेडेड ब्राउज़र का रीप्ले बनाता है, और हेडेड ही उसका डिफ़ॉल्ट है।
`headless: true` या `replay: false` के साथ इसकी जगह वेब इंजन पेज का
स्क्रीनकास्ट खुद रिकॉर्ड करता है।

## डाउनलोड

`browser.waitForDownload` दोनों स्कोप में वैसे ही काम करता है जैसे लोकल में।
प्रोवाइडर हर फ़ाइल ब्राउज़र की डिस्क से अटेम्प्ट के आर्टिफ़ैक्ट में कॉपी करता है।

## ब्राउज़र पर नज़र रखें और क्लीनअप करें

रिपोर्टर हर नए ब्राउज़र के लिए `browser <id>` लॉग करता है। लाइव व्यू का URL लॉग
में नहीं आता: उसमें ऐसे टोकन होते हैं जिनसे सेशन पर एक्शन लिए जा सकते हैं, और
रन का लॉग अक्सर पब्लिक CI आउटपुट होता है। हर ब्राउज़र पर आपके `tags` के अलावा
`e2e_run`, `e2e_target` और `e2e_slot` टैग होते हैं, और `'attempt'` स्कोप में
`e2e_attempt` भी। Kernel का डैशबोर्ड इन टैगों से ब्राउज़र ढूँढता है, और फिर
बताता है कि उसे किस रन ने शुरू किया।

रन ख़त्म होने पर प्रोवाइडर रन और टारगेट के टैग वाला हर एक्टिव ब्राउज़र डिलीट कर
देता है, उस वर्कर का ब्राउज़र भी जो बीच में अचानक बंद हो गया। अगर रन खुद पहले
अचानक बंद हो जाए, तो Kernel हर ब्राउज़र को `timeout_seconds` तक आइडल रहने के बाद
डिलीट कर देता है। आप अपनी वैल्यू न दें, तो यह 600 होता है।
