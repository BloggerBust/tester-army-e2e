`e2e mcp` Claude Code, Codex या Cursor जैसे कोडिंग एजेंट को आपके ऐप का लाइव
सेशन देता है, वेब, iOS या Android पर। एजेंट स्क्रीन देखता है, उस पर एक्शन
लेता है, और अपना काम खुद चेक करता है।

## इससे क्यों फ़र्क़ पड़ता है

| काम | `e2e mcp` के बिना | `e2e mcp` के साथ |
| --- | --- | --- |
| टेस्ट लिखना | लोकेटर का अंदाज़ा लगाता है, चलाता है, फ़ेल होता है, फिर से अंदाज़ा लगाता है | फ़्लो चलाते-चलाते टेस्ट लिखता है, चेक की हुई टेस्ट लाइनों और `run_code` से चलाई लाइनों से |
| UI बदलना | कंपाइल हो गया, तो काम ख़त्म | पेज खोलकर नतीजा देखता है |
| बग रीप्रोड्यूस करना | कोड देखकर अंदाज़ा लगाता है | ऐप में एक-एक स्टेप करके देखता है |
| फ़ेल हो रहा टेस्ट ठीक करना | फ़्लो फिर से क्लिक करके चलाता है | टेस्ट चलाता है और फ़ेलियर पर रुक जाता है |
| PR में बदलाव दिखाना | लिखकर बताता है | वीडियो रिकॉर्ड करता है |

सर्वर को कोई मॉडल नहीं चाहिए। इससे चलाए टेस्ट को मॉडल सिर्फ़ तब चाहिए जब
किसी एजेंट स्टेप की रिकॉर्डिंग न हो।

## इसे सेट अप करें

Codex और Cursor वाले [e2e प्लगइन](/coding-agents) में सर्वर पहले से है,
`npx -y e2e@<version> mcp` के रूप में। प्रोजेक्ट में e2e का कोई और वर्ज़न
इंस्टॉल हो, तब भी यह प्लगइन वाली e2e रिलीज़ ही चलाता है। Claude Code में, या
प्लगइन के बिना, सर्वर को प्रोजेक्ट में रजिस्टर करें। `e2e init` पूछता है कि
सर्वर को `.mcp.json` (Claude Code), `.cursor/mcp.json` (Cursor) और
`.codex/config.toml` (Codex) में रजिस्टर कर दे या नहीं। प्रोजेक्ट की
डिपेंडेंसी इंस्टॉल करें, और MCP क्लाइंट प्रोजेक्ट की डायरेक्टरी में शुरू करें,
ताकि `npx` (Bun प्रोजेक्ट में `bunx`) e2e का इंस्टॉल किया हुआ वर्ज़न ले। हाथ
से करना हो, तो:

<Tabs>
  <Tab title="Claude Code">
    <CodeGroup>
    ```bash npm
    claude mcp add --scope project e2e -- npx e2e mcp
    ```

    ```bash pnpm
    claude mcp add --scope project e2e -- pnpm exec e2e mcp
    ```

    ```bash bun
    claude mcp add --scope project e2e -- bunx e2e mcp
    ```
    </CodeGroup>
  </Tab>
  <Tab title="Codex">
    इंस्टॉल किए CLI से `e2e init --yes --skills none --mcp .codex/config.toml` चलाएँ,
    या नीचे वाली एंट्री जोड़ दें। प्रोजेक्ट को ट्रस्ट करें और नया Codex सेशन शुरू
    करें। प्रोजेक्ट में `codex mcp list` चलाएँगे, तो रजिस्ट्रेशन दिख जाएगा:

    ```toml title=".codex/config.toml"
    [mcp_servers.e2e]
    command = "npx"
    args = ["e2e", "mcp"]
    ```
  </Tab>
  <Tab title="Cursor">
    सर्वर को `.cursor/mcp.json` में जोड़ें। जो दूसरे क्लाइंट `mcpServers` मैप
    पढ़ते हैं, उनमें भी यही ब्लॉक चलता है।

    ```json title=".cursor/mcp.json"
    {
      "mcpServers": {
        "e2e": { "command": "npx", "args": ["e2e", "mcp"] }
      }
    }
    ```
  </Tab>
  <Tab title="OpenCode">
    सर्वर को प्रोजेक्ट की `opencode.json` में जोड़ें। प्रोजेक्ट में
    `opencode mcp list` चलाएँगे, तो यह कनेक्टेड दिखेगा:

    ```json title="opencode.json"
    {
      "$schema": "https://opencode.ai/config.json",
      "mcp": {
        "e2e": { "type": "local", "command": ["npx", "e2e", "mcp"] }
      }
    }
    ```
  </Tab>
</Tabs>

टारगेट में ऐप कमांड हो, तो सेशन उसे चालू कर देता है और ऐप का URL और पोर्ट
बता देता है। कॉन्फ़िग सर्वर का एनवायरनमेंट पढ़ता है, एजेंट का शेल नहीं।

## कॉन्फ़िग के बिना आज़माएँ

जिस डायरेक्टरी में e2e कॉन्फ़िग फ़ाइल नहीं है, वहाँ एजेंट सेशन खोलते वक़्त
इंजन का नाम देता है:

```txt
open_session {engine: "@e2e-dev/web", app: {url: "http://localhost:3000"}}
```

लेकिन `e2e run` को कॉन्फ़िग फिर भी चाहिए। इंजन के ऑप्शन, डिवाइस प्रोवाइडर
और इंजन इंस्टॉल करने के लिए [कॉन्फ़िग के बिना](/reference/mcp#without-a-config)
देखें।

## एजेंट से कहें

- "लॉगिन फ़ॉर्म में Remember me चेकबॉक्स जोड़ें। फिर e2e से ऐप में चेक करें।"
- "ऐप में चेकआउट चलाते-चलाते उसका टेस्ट लिखें।"
- "ऐप में issue #123 रीप्रोड्यूस करें और उसका वीडियो रिकॉर्ड करें।"

लोकल ब्राउज़र या सिम्युलेटर में सब चलते हुए देखना है, तो प्रॉम्प्ट में "headed" जोड़ दें।

## यह टेस्ट लाइन कैसे लिखता है

सेशन में हर एक्शन के जवाब में एक टेस्ट लाइन आती है, जो वही एक्शन दोहराती
है। उस लाइन का लोकेटर लाइव स्क्रीन पर सिर्फ़ उसी कंट्रोल से मैच हुआ था
जिस पर एक्शन हुआ:

```text wrap
Tapped #n31.
Test line: await screen.getByRole("button", "Sign in").tap();
```

फ़्लो चलाते हुए एजेंट ज़रूरी लाइनें टेस्ट में कॉपी करता जाता है।
`test_lines` अब तक की सारी लाइनें क्रम से लौटाता है, टेस्ट बॉडी के ड्राफ़्ट की
तरह। लाइन कैसे बनती है, यह [`test_lines`](/reference/mcp#test_lines) में
देखें।

## यह लोकेटर कैसे चेक करता है

कुछ लाइनें किसी एक्शन ने प्रिंट नहीं कीं, जैसे असर्शन। ऐसी लाइन के लिए एजेंट
पहले सेशन में लोकेटर आज़माता है। अंदाज़ा गलत निकला, तो वहीं फ़ेल होता है,
टेस्ट रन में नहीं:

```text wrap
0 nodes match getByLabel("Email").
A test using this locator would fail with LOCATOR_NOT_FOUND. ...

1 node matches getByRole("button", name: "Sign in").
Use: screen.getByRole("button", "Sign in")
```

## यह टेस्ट लाइन कैसे चलाता है

जो लाइनें किसी एक्शन ने प्रिंट नहीं कीं, जैसे असर्शन, उन्हें एजेंट खुले सेशन
में `run_code` से चलाता है। जो पास होती हैं, वे `test_lines` वाले ड्राफ़्ट में
जुड़ जाती हैं। गलत लाइन कुछ ही सेकंड में फ़ेल हो जाती है, टेस्ट रन की ज़रूरत
नहीं पड़ती:

```text wrap
Statement 2 of 2 failed; the one before it passed. Each statement waited at most 5000 ms. ...
1. passed: await screen.getByLabel('Full name').fill('Grace Hopper');
2. failed: await screen.getByRole('button', 'Save').tap();
   LOCATOR_NOT_FOUND: locator matched no nodes within getByRole("button", name: "Save")
```

सर्वर इन लाइनों को पार्स करता है। इन्हें JavaScript की तरह कभी इवैल्युएट नहीं
करता। देखें [`run_code`](/reference/mcp#run_code)।

## फ़ेल हो रहा टेस्ट ठीक करें

`open_session {test: "tests/checkout.e2e.ts:12"}` सेशन में एक टेस्ट चलाता है,
और जिस स्क्रीन पर टेस्ट फ़ेल हुआ, वहीं रुक जाता है। एजेंट फ़ेलियर पढ़ता है,
स्क्रीन देखता है और टेस्ट में बदलाव करता है:

```text wrap
Test "a member checks out" (tests/checkout.e2e.ts:12) failed after 30.25s; 8 steps ran.
LOCATOR_NOT_FOUND: locator matched no nodes within getByLabel("Name")
At tests/checkout.e2e.ts:20:3
On screen, closest to what the locator asked for:
  #n32 textbox "Full name"
```

उस स्क्रीन पर किया हर एक्शन अपनी
[टेस्ट लाइन](#how-it-writes-a-test-line) प्रिंट करता है। सुधारी हुई लाइन
`run_code` से वहीं चलाई जा सकती है। फ़ेल हुई लाइन की जगह एजेंट यही लाइनें
टेस्ट में डाल देता है।

बदला हुआ टेस्ट दोबारा चलाने के लिए एजेंट सेशन बंद करता है, और उसी `test` के
साथ नया सेशन खोलता है। एजेंट स्टेप `e2e run` की तरह कैश से रीप्ले होते हैं।
क्या चलता है और इसकी लिमिट क्या हैं, यह [टेस्ट चलाना](/reference/mcp#running-a-test)
में देखें।

## सेशन के साथ-साथ टेस्ट चलाएँ

सेशन कोई टेस्ट नतीजा नहीं लिखता। सिर्फ़ वही टेस्ट रीप्ले कैश इस्तेमाल करता है
जिसे सेशन `open_session {test}` से चलाए। एजेंट सूट `e2e run` से चलाता है।
अगर रन सेशन के साथ-साथ चल सकता है, तो एजेंट रनों के बीच सेशन खुला रखता है। रन
फ़ेल हो, तो एजेंट नया सेशन नहीं खोलता, उसी सेशन में फ़ेल हुई स्क्रीन पर पहुँच
जाता है।

वेब पर सेशन के साथ-साथ रन कैसे चलेगा, यह टारगेट के `app` पर टिका है:

| टारगेट का `app` | सेशन खुला हो, तब रन |
| --- | --- |
| `command` नहीं है | दोनों वही ऐप इस्तेमाल करते हैं जो आपने चालू किया। |
| पोर्ट [`0`](/web#let-the-runner-pick-the-port) पर `url` | दोनों ऐप की अपनी-अपनी कॉपी चालू करते हैं। कुछ डेव सर्वर एक डायरेक्टरी में एक ही कॉपी चलाते हैं, जैसे `next dev`। उनके साथ रन फ़ेल हो जाता है। |
| [`reuseExisting: true`](/web#starting-your-app) के साथ `command` | रन वही ऐप इस्तेमाल करता है जो सेशन ने चालू किया। सेशन बंद होते ही वह ऐप रुक जाता है, चाहे रन बीच में ही क्यों न हो। |
| फ़िक्स्ड पोर्ट पर `command`, `reuseExisting` के बिना | `APP_ALREADY_RUNNING` के साथ फ़ेल होता है। |

`CI` सेट हो, तो e2e `reuseExisting` को नज़रअंदाज़ करता है, और रन फ़िक्स्ड पोर्ट
वाले केस की तरह फ़ेल होता है। जो रन फ़ेल होने वाला है, उससे पहले सेशन बंद कर
दें। मोबाइल पर ऐसे डिवाइस पर चलाएँ जिसे कोई सेशन इस्तेमाल नहीं कर रहा।

## कई एजेंट चलाएँ

हर एजेंट, सबएजेंट भी, अपने ब्राउज़र या डिवाइस के साथ अपना अलग सेशन खोलता है।
डिफ़ॉल्ट रूप से ऐसे ज़्यादा से ज़्यादा चार सेशन खुल सकते हैं। मोबाइल पर हर सेशन
को उसका अपना टारगेट दें।

## सीक्रेट

`type_secret`, या `run_code` में `fill`, सीक्रेट भर देता है और एजेंट को दिखाता
नहीं। स्क्रीनशॉट सिर्फ़ सिक्योर फ़ील्ड को मास्क करते हैं। इसलिए ऐप अगर कोई
सीक्रेट कहीं और दिखाता है, तो वह स्क्रीनशॉट में आ जाता है।

<Warning>
`start_recording` वाले वीडियो मास्क नहीं होते।
</Warning>
