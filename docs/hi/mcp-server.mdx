`e2e mcp` Claude Code, Codex या Cursor जैसे कोडिंग एजेंट को वेब, iOS या
Android पर आपके ऐप का लाइव सेशन देता है। एजेंट स्क्रीन देखता है, उस पर एक्शन
लेता है, और अपना काम जाँचता है।

## यह क्यों मायने रखता है

| काम | `e2e mcp` के बिना | `e2e mcp` के साथ |
| --- | --- | --- |
| टेस्ट लिखना | लोकेटर का अंदाज़ा लगाता है, चलाता है, फ़ेल होता है, फिर अंदाज़ा लगाता है | फ़्लो से गुज़रते हुए टेस्ट लिखता है, जाँची हुई टेस्ट लाइनों और `run_code` से चलाई गई लाइनों से |
| UI बदलना | कंपाइल हो गया तो काम पूरा | पेज खोलकर नतीजा जाँचता है |
| बग रीप्रोड्यूस करना | कोड देखकर अंदाज़ा लगाता है | ऐप में एक-एक चरण दोहराता है |
| फ़ेल हो रहा टेस्ट ठीक करना | पूरे फ़्लो में फिर से क्लिक करता है | टेस्ट चलाता है और फ़ेलियर पर रुक जाता है |
| PR में बदलाव दिखाना | उसका वर्णन करता है | वीडियो रिकॉर्ड करता है |

सर्वर को किसी मॉडल की ज़रूरत नहीं है। इससे चलाए गए टेस्ट को मॉडल सिर्फ़ तब
चाहिए जब किसी एजेंट चरण की रिकॉर्डिंग न हो।

## इसे सेट अप करें

Codex और Cursor के लिए [e2e प्लगइन](/coding-agents) में सर्वर `npx -y e2e@<version> mcp` के रूप में शामिल है। प्रोजेक्ट में e2e का कोई दूसरा वर्ज़न इंस्टॉल होने पर भी यह प्लगइन की e2e रिलीज़ ही चलाता है।
Claude Code में, या प्लगइन के बिना, सर्वर को प्रोजेक्ट में रजिस्टर करें। `e2e init` सर्वर को `.mcp.json` (Claude Code),
`.cursor/mcp.json` (Cursor) और `.codex/config.toml` (Codex) में रजिस्टर करने
का विकल्प देता है। प्रोजेक्ट की डिपेंडेंसी इंस्टॉल करें और MCP क्लाइंट को
प्रोजेक्ट डायरेक्टरी में शुरू करें, ताकि `npx` (Bun प्रोजेक्ट में `bunx`) e2e
का इंस्टॉल किया गया वर्ज़न इस्तेमाल करे। हाथ से सेट अप करने के लिए:

<Tabs>
  <Tab title="Claude Code">
    <CodeGroup>
    ```bash npm
    claude mcp add --scope project e2e -- npx e2e mcp
    ```

    ```bash pnpm
    claude mcp add --scope project e2e -- pnpm exec e2e mcp
    ```

    ```bash bun
    claude mcp add --scope project e2e -- bunx e2e mcp
    ```
    </CodeGroup>
  </Tab>
  <Tab title="Codex">
    इंस्टॉल किए गए CLI से `e2e init --yes --skills none --mcp .codex/config.toml` चलाएँ,
    या नीचे दी गई एंट्री जोड़ें। प्रोजेक्ट को ट्रस्ट करें और नया Codex सेशन शुरू
    करें। प्रोजेक्ट में `codex mcp list` चलाने पर रजिस्ट्रेशन दिखता है:

    ```toml title=".codex/config.toml"
    [mcp_servers.e2e]
    command = "npx"
    args = ["e2e", "mcp"]
    ```
  </Tab>
  <Tab title="Cursor">
    सर्वर को `.cursor/mcp.json` में जोड़ें। `mcpServers` मैप पढ़ने वाले दूसरे
    क्लाइंट भी यही ब्लॉक लेते हैं।

    ```json title=".cursor/mcp.json"
    {
      "mcpServers": {
        "e2e": { "command": "npx", "args": ["e2e", "mcp"] }
      }
    }
    ```
  </Tab>
  <Tab title="OpenCode">
    सर्वर को प्रोजेक्ट की `opencode.json` फ़ाइल में जोड़ें। प्रोजेक्ट में
    `opencode mcp list` चलाने पर यह कनेक्टेड दिखता है:

    ```json title="opencode.json"
    {
      "$schema": "https://opencode.ai/config.json",
      "mcp": {
        "e2e": { "type": "local", "command": ["npx", "e2e", "mcp"] }
      }
    }
    ```
  </Tab>
</Tabs>

अगर टारगेट में ऐप कमांड है, तो सेशन उसे शुरू करता है और ऐप का URL और पोर्ट
बताता है। कॉन्फ़िग सर्वर का एनवायरनमेंट पढ़ता है, एजेंट का शेल नहीं।

## कॉन्फ़िग के बिना आज़माएँ

जिस डायरेक्टरी में e2e कॉन्फ़िग फ़ाइल नहीं है, वहाँ एजेंट सेशन खोलते समय इंजन
का नाम देता है:

```txt
open_session {engine: "@e2e-dev/web", app: {url: "http://localhost:3000"}}
```

`e2e run` को फिर भी कॉन्फ़िग चाहिए। इंजन के विकल्पों, डिवाइस प्रोवाइडर और
इंजन इंस्टॉल करने के बारे में
[कॉन्फ़िग के बिना](/reference/mcp#without-a-config) देखें।

## एजेंट से कहें

- "लॉगिन फ़ॉर्म में Remember me चेकबॉक्स जोड़ें। e2e से ऐप में इसे जाँचें।"
- "ऐप में चेकआउट से गुज़रते हुए उसका टेस्ट लिखें।"
- "ऐप में issue #123 रीप्रोड्यूस करें और वीडियो रिकॉर्ड करें।"

लोकल ब्राउज़र या सिम्युलेटर में देखने के लिए प्रॉम्प्ट में "headed" जोड़ें।

## यह टेस्ट लाइन कैसे लिखता है

सेशन में हर एक्शन जवाब में वह टेस्ट लाइन देता है जो उसे दोहराती है। उस लाइन
का लोकेटर लाइव स्क्रीन पर सिर्फ़ उसी कंट्रोल से मैच हुआ था:

```text wrap
Tapped #n31.
Test line: await screen.getByRole("button", "Sign in").tap();
```

एजेंट फ़्लो से गुज़रते हुए ज़रूरी लाइनें टेस्ट में कॉपी करता है।
`test_lines` अब तक की सभी लाइनें क्रम से, टेस्ट बॉडी के ड्राफ़्ट के रूप में
लौटाता है। लाइन कैसे बनती है, यह [`test_lines`](/reference/mcp#test_lines) में
देखें।

## यह लोकेटर कैसे जाँचता है

जो लाइन किसी एक्शन ने प्रिंट नहीं की, जैसे कोई असर्शन, उसके लिए एजेंट पहले
सेशन में लोकेटर आज़माता है। गलत अंदाज़ा वहीं फ़ेल होता है, टेस्ट रन में नहीं:

```text wrap
0 nodes match getByLabel("Email").
A test using this locator would fail with LOCATOR_NOT_FOUND. ...

1 node matches getByRole("button", name: "Sign in").
Use: screen.getByRole("button", "Sign in")
```

## यह टेस्ट लाइन कैसे चलाता है

जो लाइनें किसी एक्शन ने प्रिंट नहीं कीं, जैसे असर्शन, उन्हें एजेंट खुले सेशन
में `run_code` से चलाता है। पास होने वाली लाइनें `test_lines` ड्राफ़्ट में जुड़
जाती हैं। गलत लाइन टेस्ट रन के बिना, कुछ ही सेकंड में फ़ेल हो जाती है:

```text wrap
Statement 2 of 2 failed; the one before it passed. Each statement waited at most 5000 ms. ...
1. passed: await screen.getByLabel('Full name').fill('Grace Hopper');
2. failed: await screen.getByRole('button', 'Save').tap();
   LOCATOR_NOT_FOUND: locator matched no nodes within getByRole("button", name: "Save")
```

सर्वर इन लाइनों को पार्स करता है और उन्हें कभी JavaScript के रूप में इवैल्युएट
नहीं करता। देखें [`run_code`](/reference/mcp#run_code)।

## फ़ेल हो रहा टेस्ट ठीक करें

`open_session {test: "tests/checkout.e2e.ts:12"}` सेशन में एक टेस्ट चलाता है
और उस स्क्रीन पर रुकता है जहाँ टेस्ट फ़ेल हुआ। एजेंट फ़ेलियर पढ़ता है, स्क्रीन
जाँचता है और टेस्ट में बदलाव करता है:

```text wrap
Test "a member checks out" (tests/checkout.e2e.ts:12) failed after 30.25s; 8 steps ran.
LOCATOR_NOT_FOUND: locator matched no nodes within getByLabel("Name")
At tests/checkout.e2e.ts:20:3
On screen, closest to what the locator asked for:
  #n32 textbox "Full name"
```

उस स्क्रीन से किया गया हर एक्शन अपनी
[टेस्ट लाइन](#how-it-writes-a-test-line) प्रिंट करता है, और `run_code` वहीं
सुधारी गई लाइन चलाता है। एजेंट फ़ेल हुई लाइन की जगह ये लाइनें टेस्ट में
रखता है।

बदले हुए टेस्ट को दोबारा चलाने के लिए एजेंट सेशन बंद करता है और उसी `test` के
साथ नया सेशन खोलता है। एजेंट चरण `e2e run` की तरह कैश से रीप्ले होते हैं। क्या
चलता है और इसकी सीमाएँ क्या हैं, यह [टेस्ट चलाना](/reference/mcp#running-a-test)
में देखें।

## सेशन के साथ-साथ टेस्ट चलाएँ

सेशन कोई टेस्ट नतीजा नहीं लिखता। सेशन जिस टेस्ट को `open_session {test}` से
चलाता है, सिर्फ़ वही टेस्ट रीप्ले कैश का इस्तेमाल करता है। एजेंट सूट
`e2e run` से चलाता है, और जब रन सेशन के साथ-साथ चल सकता है, तो वह रनों के बीच
सेशन खुला रखता है। रन फ़ेल होने के बाद वह नया सेशन खोलने के
बजाय उसी सेशन में फ़ेल हुई स्क्रीन पर जाता है।

वेब पर, सेशन के साथ-साथ रन कैसे चलेगा, यह टारगेट के `app` पर निर्भर करता है:

| टारगेट का `app` | सेशन खुला होने पर रन |
| --- | --- |
| `command` नहीं | दोनों आपके शुरू किए हुए ऐप का इस्तेमाल करते हैं। |
| पोर्ट [`0`](/web#let-the-runner-pick-the-port) पर `url` | दोनों ऐप की अपनी-अपनी कॉपी शुरू करते हैं। जो डेव सर्वर हर डायरेक्टरी में एक ही कॉपी चलाता है, जैसे `next dev`, उससे रन फ़ेल हो जाता है। |
| [`reuseExisting: true`](/web#starting-your-app) के साथ `command` | रन वही ऐप इस्तेमाल करता है जो सेशन ने शुरू किया। सेशन बंद होने पर, रन के दौरान भी, वह ऐप रुक जाता है। |
| `reuseExisting` के बिना, फ़िक्स्ड पोर्ट पर `command` | `APP_ALREADY_RUNNING` के साथ फ़ेल होता है। |

`CI` सेट होने पर e2e `reuseExisting` को अनदेखा करता है, और रन फ़िक्स्ड पोर्ट की
तरह फ़ेल होता है। जो रन फ़ेल होगा, उससे पहले सेशन बंद करें। मोबाइल पर ऐसे
डिवाइस पर चलाएँ जिसे कोई सेशन इस्तेमाल नहीं कर रहा।

## कई एजेंट चलाएँ

हर एजेंट, सबएजेंट समेत, अपने ब्राउज़र या डिवाइस के साथ अपना सेशन खोलता है,
डिफ़ॉल्ट रूप से अधिकतम चार। मोबाइल पर हर सेशन को उसका अपना टारगेट दें।

## सीक्रेट

`type_secret`, या `run_code` में `fill`, सीक्रेट को एजेंट को दिखाए बिना भरता
है। स्क्रीनशॉट सिर्फ़ सुरक्षित फ़ील्ड को मास्क करते हैं, इसलिए ऐप जो सीक्रेट
कहीं और दिखाता है, वह स्क्रीनशॉट में आ जाता है।

<Warning>
`start_recording` से बने वीडियो मास्क नहीं होते।
</Warning>
