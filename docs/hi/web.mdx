`@e2e-dev/web` आपके ऐप के URL पर, ब्राउज़र में टेस्ट चलाता है। रूट, कुकी,
डायलॉग और डाउनलोड के लिए [ब्राउज़र के साथ काम करना](/browser) देखें।

## अपना ऐप शुरू करना

अपने ऐप का URL टारगेट के `app` में सेट करें। `app.open('/path')` इसी URL के
आधार पर रिज़ॉल्व होता है:

```ts title="Target fragment"
engine: web(),
app: { url: process.env.APP_URL ?? 'http://localhost:3000' },
```

URL में स्कीम न हो, तो HTTPS लगता है, और लूपबैक होस्ट हो तो HTTP। सादा
HTTP सिर्फ़ लूपबैक होस्ट पर चलता है।

### रनर से इसे शुरू करवाएँ

`app.command` जोड़ दें, तो डेव सर्वर रनर खुद शुरू करता है। फिर वह `app.url` के
जवाब देने तक रुकता है। रन ख़त्म हो, फ़ेल हो या बीच में रोका जाए, रनर अपना शुरू
किया सर्वर बंद कर देता है:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{
    engine: web(),
    app: {
      url: process.env.APP_URL ?? 'http://localhost:3000',
      command: {
        executable: 'npm',
        args: ['run', 'dev'],
        reuseExisting: true,
        log: '.e2e/logs/app.log',
      },
    },
  }],
} satisfies E2EConfig;
```

```text
 ✓ target "web" command at http://localhost:3000/ ready 1.20s
```

कमांड शेल के बिना चलती है: `executable` को `PATH` से लिया जाता है और `args`
जैसे लिखे हैं, वैसे ही जाते हैं। चाइल्ड प्रोसेस को सिर्फ़ `PATH`, `HOME`, temp
डायरेक्टरी वाले वेरिएबल, `inheritEnv` और `env` मिलते हैं।

| ऑप्शन | किस लिए |
| --- | --- |
| `reuseExisting: true` | पहले से चल रहा सर्वर इस्तेमाल करें, जैसे किसी [MCP सेशन](/mcp-server#run-tests-next-to-a-session) का शुरू किया सर्वर। CI में e2e इसे नज़रअंदाज़ करता है, और अगर कोई सर्वर पहले से जवाब दे रहा हो, तो `APP_ALREADY_RUNNING` आता है। |
| `log` | ऐप का stdout और stderr एक फ़ाइल में सेव करें, जिसका पाथ प्रोजेक्ट फ़ोल्डर से रिलेटिव हो। स्टार्टअप एरर आए, या `e2e run` के बीच ऐप अचानक बंद हो जाए, तो मैसेज में वे लाइनें दिखती हैं जो कमांड शुरू होने के बाद किसी भी प्रोसेस ने फ़ाइल में जोड़ीं। लॉग 40 लाइनों तक का हो और 8 KiB के अंदर हो, तो पूरा दिखता है। वरना दोनों सिरों से 20-20 लाइनें तक दिखती हैं, और बीच में `[startup output omitted]` आता है। 8 KiB से बड़े लॉग में ये लाइनें उसके पहले और आख़िरी 4 KiB से ली जाती हैं। `command.env` और `inheritEnv` की कम से कम चार कैरेक्टर वाली वैल्यू इन दिखाई गई लाइनों में छिपा दी जाती हैं। फ़ाइल में खुद कुछ नहीं छिपाया जाता। |
| `env` | ऐप के एनवायरनमेंट वेरिएबल। |
| `inheritEnv` | होस्ट के वेरिएबल, जो सेट हों तो आगे भेजे जाते हैं। इन्हें नाम या प्रीफ़िक्स से चुनें: `['DATABASE_URL', 'STRIPE_*']`। एक ही वेरिएबल दोनों में हो, तो `env` वाली वैल्यू चलती है। |
| `startupTimeout` | ऐप के जवाब का कितनी देर इंतज़ार करना है। डिफ़ॉल्ट 60 सेकंड। |
| `readyUrl` | `app.url` की जगह किसी हेल्थ एंडपॉइंट को जाँचने के लिए। इसे `command` के अंदर नहीं, उसके बगल में सेट करें। |

सारे ऑप्शन [command रेफ़रेंस](/reference/config#command) में हैं।

<Note>
रनर सिर्फ़ `app.command` शुरू करता है। डेटाबेस, मॉक और बाकी सर्विसें रन से
पहले खुद शुरू करें। या `app.command` को ऐसी स्क्रिप्ट बना दें जो उन्हें शुरू करे
और ऐप भी सर्व करे। सर्विसों वाला API आगे की किसी रिलीज़ में लौटेगा।
</Note>

### रनर से पोर्ट चुनवाएँ

कई चेकआउट एक साथ बिना पोर्ट टकराए चलाने हैं, तो पोर्ट `0` इस्तेमाल करें। रनर
एक खाली पोर्ट चुनता है और कमांड के `args` और `env` में `{port}` की जगह वही
पोर्ट डाल देता है:

```ts title="Target fragment"
engine: web(),
app: {
  url: 'http://127.0.0.1:0',
  command: { executable: 'pnpm', args: ['dev', '--port', '{port}'], env: { PORT: '{port}' } },
},
```

- `127.0.0.1` या `[::1]` लिखें, यानी वही पता जिस पर कमांड बाइंड होती है।
  `localhost:0` रिजेक्ट हो जाता है।
- टेस्ट असली पोर्ट वाला URL `app.baseUrl` से पढ़ते हैं।
- पोर्ट बदल जाए, तब भी कैश एंट्री वैलिड रहती हैं।
- `reuseExisting` पोर्ट `0` के साथ काम नहीं करता।
- Next.js डेव सर्वर को उस होस्ट के लिए `allowedDevOrigins` में एक एंट्री चाहिए।
  [Next.js](/frameworks/nextjs#fix-next-js-problems) देखें।

[फ़्री पोर्ट](/reference/config#free-ports) देखें।

## प्रोटेक्टेड प्रीव्यू

प्रोटेक्टेड प्रीव्यू खोलना हो या किसी टनल का वॉर्निंग पेज छोड़ना हो, तो
`headers` इस्तेमाल करें। जैसे, Vercel प्रीव्यू एक प्रोटेक्शन बायपास हेडर लेता है:

```ts title="Target fragment"
engine: web({
  headers: {
    'x-vercel-protection-bypass': process.env.VERCEL_AUTOMATION_BYPASS_SECRET ?? '',
  },
}),
app: {
  url: process.env.PREVIEW_URL ?? 'http://localhost:3000',
  identity: 'storefront',
},
```

ब्राउज़र `headers` सिर्फ़ उन रिक्वेस्ट में जोड़ता है जो `app.url` के ऑरिजिन से
शुरू होती हैं। ऑरिजिन मतलब उसकी स्कीम, होस्ट और पोर्ट। रीडायरेक्ट होने पर भी
रिक्वेस्ट ये हेडर साथ रखती है, चाहे रीडायरेक्ट किसी भी ऑरिजिन पर जाए। किसी
दूसरे ऑरिजिन के लिए भी हेडर चाहिए, जैसे उसी गेट के पीछे वाला API होस्ट, तो उसे
`credentialOrigins` में डालें।
[रिक्वेस्ट क्रेडेंशियल](/reference/security#request-credentials) देखें। ngrok
के लिए `'ngrok-skip-browser-warning': '1'` इस्तेमाल करें। प्रीव्यू URL बदल
जाए, तब भी `app.identity` कैश की पहचान एक जैसी रखता है।

<Note>
`headers` सेट करने पर ब्राउज़र का HTTP कैश बंद हो जाता है और सर्विस वर्कर
ब्लॉक हो जाते हैं।
</Note>

HTTP basic ऑथेंटिकेशन के लिए `basicAuth` इस्तेमाल करें। `app.url` के ऑरिजिन से,
और `credentialOrigins` के हर ऑरिजिन से, `401` चैलेंज आए तो ब्राउज़र उसका जवाब
देता है। WebKit में एक फ़र्क़ है: इनमें से कोई ऑरिजिन डिफ़ॉल्ट पोर्ट पर हो, जैसे
बिना पोर्ट वाला `https://` URL, या उसका होस्ट IPv6 हो, तो WebKit किसी भी ऑरिजिन
को जवाब दे देता है। पासवर्ड को `secrets` में डिक्लेयर करें और `secrets.get(name)`
पास करें:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { secrets } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [
    {
      engine: web({
        basicAuth: { username: 'preview', password: secrets.get('previewPassword') },
      }),
      app: { url: 'https://staging.example.com' },
    },
  ],
  secrets: { previewPassword: () => process.env.PREVIEW_PASSWORD ?? '' },
} satisfies E2EConfig;
```

हर अटेम्प्ट की शुरुआत में इंजन सीक्रेट की वैल्यू निकालता है। रनर उसे रिपोर्ट,
लॉग और एजेंट को दिखने वाली चीज़ों से बाहर रखता है। नाम डिक्लेयर न किया हो, तो
कॉन्फ़िग लोड `INVALID_CONFIG` के साथ फ़ेल होता है। सादी स्ट्रिंग वाला पासवर्ड भी
चलता है, लेकिन e2e सिर्फ़ `secrets.get` वाला पासवर्ड छिपाता है।

## व्यूपोर्ट

सूट को किसी एक साइज़ पर चलाना है, तो टारगेट पर व्यूपोर्ट सेट करें। या टेस्ट के
बीच में `browser.setViewport()` कॉल करें। एजेंट अपने
[`resize_viewport`](/reference/agent#action-tools) टूल से साइज़ बदलता है।

### हर टारगेट का एक साइज़

`viewport` हर अटेम्प्ट का शुरुआती साइज़ तय करता है, पिक्सल में। डिफ़ॉल्ट 1280 x
720 है। हर साइज़ के लिए एक टारगेट जोड़ें:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

const app = { url: 'http://localhost:3000' };

export default {
  targets: [
    { name: 'desktop', engine: web(), app },
    { name: 'tablet', engine: web({ viewport: { width: 820, height: 1180 } }), app },
    { name: 'phone', engine: web({ browser: 'webkit', viewport: { width: 390, height: 844 } }), app },
  ],
} satisfies E2EConfig;
```

हर टेस्ट हर टारगेट पर चलता है, और हर टारगेट नाम का नतीजा अलग आता है। हर रीट्राई
टारगेट के साइज़ से शुरू होता है।

- एक साइज़ चलाना हो, तो `npx e2e run --target phone` चलाएँ। टेस्ट और
  टारगेट के जोड़े `npx e2e list` से देखें।
- जिन टारगेट में एक ही `app.command` है, वे एक ही डेव सर्वर शेयर करते हैं।
- इसी लिस्ट में डिवाइस टारगेट भी रख सकते हैं।
  [मोबाइल इंजन रेफ़रेंस](/reference/mobile) देखें।

### विंडो भरें

`viewport: null` कोई साइज़ सेट नहीं करता। तब पेज पूरी ब्राउज़र विंडो भर देता है,
और एजेंट, स्क्रीनशॉट और वीडियो वही साइज़ लेते हैं। इसे हेडेड रन में इस्तेमाल
करें। या ऐसे होस्टेड ब्राउज़र के साथ, जिसके लाइव व्यू में वरना 1280 x 720 का पेज
एक कोने में दिखता:

```ts title="Target fragment"
{ name: 'window', engine: web({ viewport: null }), app }
```

लोकल हेडेड लॉन्च छोटी विंडो खोलता है। होस्टेड ब्राउज़र वही विंडो साइज़ लेता है
जो आपने सर्विस से माँगा था। `browser.setViewport` तब भी काम करता है।

### टेस्ट के अंदर साइज़ बदलें

`browser.setViewport` अटेम्प्ट के बाकी हिस्से के लिए पेज का साइज़ बदल देता है।
`app.restart()` और `app.clearState()` के बाद भी यही साइज़ रहता है। जब एक ही
टेस्ट साइज़ बदलने से पहले और बाद का लेआउट चेक करे, तब इसे इस्तेमाल करें:

```ts
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('the menu collapses on a narrow screen', async ({ app, screen, browser }) => {
  await app.open('/');
  await expect(screen.getByRole('navigation')).toBeVisible();

  await browser.setViewport({ width: 390, height: 844 });
  await expect(screen.getByRole('button', 'Menu')).toBeVisible();
  await expect(screen.getByRole('navigation')).toBeHidden();
});
```

इसे `app.open` से पहले कॉल करें, तो पहला पेज सीधे उसी साइज़ पर लोड होता है।
पहले कोई डेस्कटॉप रेंडर नहीं होता।

### एजेंट क्या देखता है

एजेंट को हर ऑब्ज़र्वेशन के साथ मौजूदा व्यूपोर्ट साइज़ मिलता है। इसलिए साइज़
`agent.act` से पहले बदलें। स्क्रीनशॉट में व्यूपोर्ट जितना हिस्सा आता है। स्क्रीन
से बाहर के एलिमेंट भी ट्री में हो सकते हैं। टैप उन्हें स्क्रोल करके सामने ले आता
है, और एजेंट स्क्रोल करके लेज़ी कंटेंट लोड कर सकता है।

जिस वाक्य में लिंक, ज़ोर वाला टेक्स्ट या कोड हो, वह एजेंट तक पूरा पहुँचता है।
लिंक अलग से एक कंट्रोल के तौर पर भी लिस्ट होता है। एजेंट टेक्स्ट के हर ब्लॉक के
पहले 512 कैरेक्टर पढ़ता है। ब्लॉक इससे लंबा हो, तो e2e उसके लिंक और ज़ोर वाला
टेक्स्ट अलग से भी लिस्ट करता है।

कुछ कंपोनेंट लाइब्रेरी चेकबॉक्स या रेडियो को उसके अपने लेबल के नीचे शून्य
साइज़ का कर देती हैं, जैसे Element Plus। एजेंट फिर भी उसे देखता है, और यह भी
कि वह चेक है या नहीं। उस पर टैप करने से लेबल पर क्लिक होता है। लेकिन अगर वह
लेबल खुद लिंक या कोई दूसरा कंट्रोल हो, या उसके अंदर ऐसा कंट्रोल हो, तो एजेंट
लेबल का टेक्स्ट और वह कंट्रोल देखता है, चेकबॉक्स नहीं। वजह यह है कि लेबल पर
क्लिक लिंक पर जा सकता है। लोकेटर फिर भी ऐसे चेकबॉक्स या रेडियो को छिपा हुआ
(hidden) मानते हैं, जैसे Playwright मानता है। इसलिए उसे `toBeVisible()` से
नहीं, `toBeChecked()` से चेक करें।

### टेस्ट को एक साइज़ तक सीमित करना

`platforms` से व्यूपोर्ट नहीं चुना जा सकता, क्योंकि हर ब्राउज़र
टारगेट का प्लेटफ़ॉर्म `web` होता है। कुछ साइज़ पर टेस्ट स्किप करना हो, तो टेस्ट
के अंदर चौड़ाई पढ़ें:

```ts
test('the sidebar stays open', async ({ app, screen, browser }) => {
  await app.open('/');
  test.skip((await browser.evaluate(() => window.innerWidth)) < 768, 'desktop layout only');
  await expect(screen.getByRole('complementary')).toBeVisible();
});
```

किसी खास साइज़ वाले टेस्ट का ग्रुप अलग रखना है, तो उन्हें उनका अपना कॉन्फ़िग दें
और उसे `--config` से चलाएँ।

### सीमाएँ

पतला व्यूपोर्ट सिर्फ़ रिस्पॉन्सिव लेआउट टेस्ट करता है। ब्राउज़र तब भी डेस्कटॉप
ब्राउज़र ही रहता है: स्केल फ़ैक्टर 1, डेस्कटॉप पॉइंटर और उसका आम यूज़र एजेंट।
टच इम्युलेट नहीं होता। सिम्युलेटर या एम्युलेटर पर टेस्ट करना हो, तो
[मोबाइल इंजन](/mobile) इस्तेमाल करें। डार्क मोड और रिड्यूस्ड मोशन के लिए
[डार्क मोड और रिड्यूस्ड मोशन इम्युलेट करें](/browser#emulate-dark-mode-and-reduced-motion) देखें।

वीडियो उसी साइज़ में रहता है जो रिकॉर्डिंग शुरू होते वक़्त पेज का था। एक तय साइज़
चाहिए, तो `web({ screencast: { size } })` सेट करें। जो ब्राउज़र प्रोवाइडर खुद
रिकॉर्ड करता है, जैसे [Kernel](/integrations/kernel#recordings), वह इसकी जगह
पूरी स्क्रीन रिकॉर्ड करता है।

## ब्राउज़र परमिशन देना

टारगेट जो परमिशन ग्रांट नहीं करता, हेडलेस Chromium उसे मना कर देता है। इसलिए
क्लिक के बाद भी `navigator.clipboard.writeText` फ़ेल होता है। ऐप को क्लिपबोर्ड
इस्तेमाल करने देना है, तो टारगेट पर परमिशन ग्रांट करें:

```ts
{
  engine: web(),
  app: {
    url: 'http://localhost:3000',
    permissions: { 'clipboard-read': 'grant', 'clipboard-write': 'grant' },
  },
}
```

- हर अटेम्प्ट के हर पेज पर, किसी भी ऑरिजिन पर, यह परमिशन मिली रहती है।
- वेब टारगेट सिर्फ़ `'grant'` लेता है। `'deny'` और `'reset'` पर `INVALID_CONFIG`
  आता है: इनकी जगह उस परमिशन को लिखें ही नहीं।
- नाम Playwright वाले हैं, और हर ब्राउज़र परमिशन का अपना अलग सेट ग्रांट करता है।
  [`permissions`](/reference/config#permissions) देखें।
