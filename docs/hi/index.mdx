e2e वेब और मोबाइल ऐप्स के लिए एक ओपन सोर्स टेस्टिंग फ़्रेमवर्क है। टेस्ट में आप
सटीक [लोकेटर](/core-concepts#locators) और
[असर्शन](/reference/expect#locator-matchers) लिख सकते हैं। या आम भाषा में
[लक्ष्य](/core-concepts#goals) लिख सकते हैं, जिन्हें एजेंट पूरा करता है। चाहें
तो एक ही टेस्ट में दोनों लिख सकते हैं।

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('a member upgrades to Pro', async ({ app, agent, screen }) => {
  await app.open('/settings/billing');

  await agent.act('upgrade the workspace to the Pro plan');
  await agent.assert('the invoice preview shows a prorated amount');

  await expect(screen.getByRole('status')).toContainText('Pro');
});
```

## e2e क्यों

- **टेस्ट पर कम समय।** सेलेक्टर और इंतज़ार से भरी स्क्रिप्ट की जगह एक लक्ष्य
  लिखें। UI बदले, तो एजेंट खुद को उसके हिसाब से ढाल लेता है। यानी आपको कम टेस्ट
  ठीक करने पड़ते हैं।
- **सस्ते रन।** बाद की कोई जाँच पास हो जाए, तो e2e `agent.act` स्टेप को रिकॉर्ड
  कर लेता है। अगला रन उसे बिना मॉडल कॉल के [रीप्ले करता है](/cache)। ऐप बदल गया
  हो, तो काम फिर से एजेंट के पास चला जाता है। बिल्ट-इन एजेंट के साथ `assert`,
  `waitFor` और `extract` हर बार मॉडल को कॉल करते हैं।

## यह कैसे काम करता है

- **टारगेट।** हर टेस्ट हर टारगेट पर एक बार चलता है, जैसे Chromium या कोई iPhone
  सिम्युलेटर। [वेब इंजन](/web) Playwright से ब्राउज़र चलाता है।
  [मोबाइल इंजन](/mobile) agent-device से iOS सिम्युलेटर और Android एम्युलेटर
  चलाता है। चाहें तो
  [अपना इंजन भी लिख सकते हैं](/writing-an-engine)।
- **एजेंट स्टेप।** `agent.act` एक लक्ष्य पूरा करता है। `agent.assert`,
  `agent.waitFor` और `agent.extract` स्क्रीन को परखते हैं। अपना
  [सब्सक्रिप्शन](/subscriptions), [API key या लोकल मॉडल](/models) इस्तेमाल करें।
  जिन टेस्ट में कोई एजेंट स्टेप नहीं है, उन्हें मॉडल की ज़रूरत नहीं होती।
- **रिपोर्ट।** रनर मॉडल इनपुट से [रजिस्टर किए गए सीक्रेट छिपा देता है](/security)।
  वह स्टेप, फ़ेलियर और आर्टिफ़ैक्ट एक [रिपोर्ट](/debugging) में दर्ज करता है। इसे
  आप या आपका कोडिंग एजेंट पढ़ सकते हैं।
