रनर के हर एरर में एक क्लास और एक कोड होता है। क्लास एग्ज़िट कोड तय करती है, और
कोड कारण बताता है। मॉडल इनमें से कुछ भी नहीं चुनता। `e2e login`, `e2e logout`,
और `e2e models` इसका अपवाद हैं, जो [एग्ज़िट कोड](#exit-codes) में बताए गए हैं।

```ts title="tests/upgrade.e2e.ts"
import { isAgentError, test } from 'e2e';

test('upgrade to Pro', async ({ agent }) => {
  try {
    await agent.act('upgrade the workspace to Pro');
  } catch (error) {
    if (isAgentError(error) && error.code === 'STEP_TIMEOUT') {
      // the step ran out of time; the message carries the last judgment
      console.error(error.category, error.details);
    }
    throw error;
  }
});
```

## रेफ़रेंस

### एग्ज़िट कोड

| क्लास | एग्ज़िट कोड |
| --- | ---: |
| test | 1 |
| configuration | 2 |
| infrastructure | 3 |
| internal | 4 |
| interrupted | 130 |

- मिले-जुले रन में सबसे ज़्यादा प्राथमिकता वाला कोड जीतता है,
  `130 > 4 > 3 > 2 > 1 > 0`। रिपोर्ट में हर अलग नतीजा बना रहता है।
- जिस टेस्ट का क्लीनअप फ़ेल हो (ज़रूरी वीडियो फ़ाइनलाइज़ न हुआ हो, सेशन बंद न
  हुआ हो), वह उस क्लीनअप एरर के कोड से बाहर निकलता है, आमतौर पर 3।
- सेटअप असर्शन फ़ेलियर एक टेस्ट फ़ेलियर है और उस पर निर्भर टेस्ट स्किप हो जाते
  हैं। गायब सेटअप इन्फ़्रास्ट्रक्चर अपनी configuration या infrastructure क्लास
  बनाए रखता है।
- `internal` क्लास और एग्ज़िट कोड 4 रनर इनवेरिएंट टूटने के लिए रिज़र्व हैं। आज
  कोई फ़र्स्ट-पार्टी कोड इस क्लास का कोड नहीं उठाता।
- `e2e login`, `e2e logout`, और `e2e models` बिना किसी कोड के फ़ेलियर मैसेज
  प्रिंट करके एग्ज़िट 1 देते हैं, या साइन-इन या पिकर कैंसल होने पर 130।

### AgentError

`AgentError` रनर से कैटेगरी वाले एजेंट फ़ेलियर है, जो `e2e` से एक्सपोर्ट होता
है।

```ts
/** Runner-classified agent failure. */
export class AgentError extends Error {
  /** Closed union, assigned by the runner, never taken from model text. */
  readonly code: AgentErrorCode;
  /** The error class in the table above; it sets the exit code. */
  readonly category: 'test' | 'configuration' | 'infrastructure' | 'internal' | 'interrupted';
  readonly retryable: boolean;
  /** Structured facts: locator, expected, observed, match count, wait time. */
  readonly details: ErrorDetails | undefined;
  /** Sanitized, bounded prose; the same value as `message`. */
  readonly explanation: string;
  /** Artifact path, present only when evidence was captured and permitted. */
  readonly screenshot?: string;
  /** True when this failure reports a blocked step, not a product failure. */
  readonly blocked: boolean;
}
```

<Note>
टेस्ट फ़ाइलें अपने अलग मॉड्यूल रेल्म में लोड होती हैं, इसलिए
`instanceof AgentError` false हो सकता है। `e2e` से `isAgentError` इस्तेमाल करें और `code`
के हिसाब से ब्रांच करें, जैसा इस पेज के ऊपर वाले उदाहरण में है।
</Note>

#### एजेंट कोड

क्लोज़्ड `AgentErrorCode` यूनियन के मेंबर। `blocked:` बताता है कि ब्लॉक्ड फ़ैसला
किस रुकावट की श्रेणी रिपोर्ट करता है।
