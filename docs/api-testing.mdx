An API test calls your API with the [`request`](/reference/request) fixture
and checks the response with the value matchers. It sits in the
same files and the same run as UI tests, and calls no model.

```ts title="tests/users-api.e2e.ts"
import { test, expect } from 'e2e';
import { z } from 'zod';

const User = z.object({ id: z.number(), name: z.string() });

test('GET /api/users returns the seeded users', async ({ request }) => {
  const response = await request.get('/api/users');
  expect(response.status).toBe(200);
  expect(response.headers['content-type']).toContain('application/json');
  const users = expect(await response.json()).toMatchSchema(z.array(User));
  expect(users).toHaveLength(3);
  expect(users.map((user) => user.name)).toEqual(['Ada', 'Grace', expect.any(String)]);
});
```

Each call is a step in the report, such as `GET /api/users`, and fails the
test when it runs past `actionTimeout`.

`toMatchSchema` takes any [Standard Schema](/reference/expect#matching-a-schema),
such as Zod, Valibot, or ArkType, and returns the value, typed. Use the
schema your app parses the API with, and the test fails when the API stops
matching it.

## Where the API runs

A path such as `/api/users` resolves against the target's `app.url`, with
the port the run picked when the URL declares port `0`. So one file runs
against the `app.command` the config starts and against a deployed preview.
A leading `/` starts at the origin: when `app.url` has a path, such as
`/shop`, write ``request.get(`${app.baseUrl}/api/users`)``.

When the API writes state after it answers, use
[`expect.poll`](/reference/expect#polling-a-value) to read again until a
matcher passes.

## Signed-in requests

`request` does not send the browser's cookies. To call the API as the user
the test signed in, send your app's session cookie in a header. `browser`
needs a web target:

```ts title="tests/orders-api.e2e.ts"
import { expect } from 'e2e';
import { test } from '@e2e-dev/web';

test('lists my orders', async ({ app, browser, request }) => {
  await app.open('/sign-in');
  // ...sign in through the UI...
  // The domain your app sets the cookie on: its host, or `.example.com` for `Domain=example.com`.
  const domain = new URL(app.baseUrl).hostname;
  const session = (await browser.cookies()).find((c) => c.name === 'session' && c.domain === domain);
  if (session === undefined) throw new Error('not signed in');
  const headers = { cookie: `${session.name}=${session.value}` };
  expect((await request.get('/api/orders', { headers })).status).toBe(200);
});
```

`browser.cookies()` returns every cookie of the browser context, those of
other sites included, such as a sign-in provider's. Pick your app's session
cookie by its name and the exact domain your app sets it on, and send it
only with paths on your app.

## Without a browser

On a web target, an API test still opens a browser context. A target
without an engine opens nothing, and has no `app.url`, so pass an absolute
URL. Read it from an environment variable:

```ts
const response = await request.get(`${process.env.API_URL}/api/users`);
```

`e2e init` sets up such a target when you select no engine.
