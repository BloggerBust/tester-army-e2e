---
title: Desktop
description: Test a native desktop app on macOS through its accessibility tree.
---

`@e2e-dev/desktop` runs tests on native desktop apps. It reads and drives
the app through the OS accessibility tree with
[agent-desktop](https://github.com/vercel-labs/agent-desktop). Tests use the
same `agent`, `screen`, and `expect` APIs as browser tests.

<Note>
  The desktop engine is a prototype, and it runs on macOS only. A config with
  a desktop target still loads on Windows and Linux, and its other targets run
  there when you pick them with `--target`. A run that includes the desktop
  target stops before any test starts.
</Note>

## Set up

Install the runner and the engine:

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/desktop
```

```bash pnpm
pnpm add --save-dev e2e @e2e-dev/desktop
```

```bash bun
bun add --dev e2e @e2e-dev/desktop
```
</CodeGroup>

On macOS, the app that starts e2e needs two permissions in **System Settings
> Privacy & Security**. That app is your terminal, your IDE, or your CI agent.

- **Accessibility**, to read and drive the app.
- **Screen Recording**, for screenshots.

The first run downloads agent-desktop and checks its SHA-256 digest. To use
your own install, such as a Homebrew one, set
`desktop({ binary: '/path/to/agent-desktop' })`.

Check your setup:

<CodeGroup>
```bash npm
npx e2e doctor
```

```bash pnpm
pnpm exec e2e doctor
```

```bash bun
bunx e2e doctor
```
</CodeGroup>

It checks agent-desktop, both permissions, and the `appPath` build.

## Point at your app

Set the target's `app.appPath` to a built `.app` bundle. Or set
`app.bundleId` to an installed app's bundle id or name, such as
`com.apple.calculator`. With both, the `appPath` build is launched, and its
bundle id must be `bundleId`. `app.launchArguments` go to every launch. An
object entry becomes `-name value`, as on iOS, so
`{ AppleLanguages: ['fr'] }` opens the app in French.

The launched app gets only a minimal environment (`HOME`, `USER`, `LOGNAME`,
`SHELL`, `PATH`, `TMPDIR`, `LANG`, `LC_*`, `__CF_USER_TEXT_ENCODING`, plus
`E2E_DESKTOP_LAUNCH` for process tracking, or `AGENT_DESKTOP_HOME` when
launched by `bundleId`), so your secrets, model keys, and CI tokens never
leak into it. Built-in macOS apps and builds signed with the `restrict` flag
must be launched by `bundleId` rather than `appPath`.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { desktop } from '@e2e-dev/desktop';

export default {
  targets: [
    {
      name: 'mac',
      engine: desktop(),
      app: { appPath: 'build/MyApp.app' },
    },
  ],
  credentials: {
    ada: { username: 'ada', password: process.env.ADA_PASSWORD ?? '' },
  },
} satisfies E2EConfig;
```

## Write a test

Import `test` from `@e2e-dev/desktop`. By default, `app.open()` leaves the
app in the background. Use `desktop({ headed: true })` for apps that need to
come forward before they show a window. `e2e run --headed` also launches
the app in the foreground, but only `desktop({ headed: true })` turns on the
physical input described below. When the engine launched it
before, it quits that copy first. A copy you opened yourself is left alone,
and the engine never reads or drives it. Every test ends with the app quit,
and no window the app saved at its last quit comes back.

```ts title="tests/sign-in.e2e.ts"
import { test } from '@e2e-dev/desktop';
import { credentials, expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  const ada = credentials.user('ada');
  await app.open();
  await screen.getByRole('textbox', 'Username').fill(ada.username);
  await screen.getByRole('textbox', 'Password').fill(ada.password);
  await screen.getByRole('combobox', 'Plan').selectOption('Team');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByTestId('status')).toContainText('Signed in as ada');
});
```

Roles use the names the web uses: `textbox`, `checkbox`, `combobox`,
`button`. Static text has the role `text`, so find it with `getByText`. A
control's name is the one macOS accessibility gives it: its title, or its
accessibility label. A button's title is its name and its text, so
`getByText('Sign in')` finds the button as well as any static text that
reads the same; `getByRole('button', 'Sign in')` finds only the button.
`getByPlaceholder` is not supported: macOS reports no placeholder, and
names a field with no label by its placeholder, so find that field with
`getByRole('textbox', 'Username')`. `getByTestId` finds the control's
`AXIdentifier` (`accessibilityIdentifier` in AppKit, SwiftUI's
`.accessibilityIdentifier`).

The `desktop` fixture lists the app's windows (`desktop.windows()`), picks
the one `screen` reads (`desktop.useWindow(window)`), and quits the app
(`desktop.closeApp()`).

## What differs from the web

| Area | On a desktop target |
| --- | --- |
| Input | The app runs in the background using the macOS Accessibility API, so your mouse and keyboard stay free. Apps that don't open a window in the background (like document-based apps) need `headed: true` or `--headed`. |
| Physical input | `doubleTap`, `hover`, `press`, coordinate taps, and focused typing require `desktop({ headed: true })`, which brings the app forward and uses real pointer/keyboard input. Watch out for floating windows overlapping the target area. |
| Keys | `press` sends keys only to the focused control in an active window (`headed: true`). It supports named keys, letters, digits, and ``, . / ; ' [ ] \ - = ` `` (other characters like `!` or `é` are rejected), and blocks system shortcuts like `ControlOrMeta+q` (use `desktop.closeApp()` instead). |
| Select | `selectOption` matches by option label, not index. For editable combo boxes, use `fill()` instead. |
| Windows | `screen` reads the window picked with `desktop.useWindow()`, otherwise the focused window, otherwise the first visible window. Sheets are included; window chrome (Close/Minimize/Zoom) is excluded. Minimized windows read as hidden, while windows on another macOS Space stay readable. |
| Reading | Only an app with no open windows reads as empty. If the screen is locked or the window tree is deeper than `maxDepth`, locators keep retrying until timeout instead of returning false negatives, and `app.open()` fails on a locked screen. |
| Menu bar | The app's menu bar isn't readable yet; trigger menu items with a key shortcut (`press` + `headed: true`). |
| Web content | Browser windows, Electron apps, and web views aren't supported. Use `@e2e-dev/web` for those. |
| Workers | Limited to one worker per desktop target. If you run two desktop targets with `headed: true`, set `workers: 1` so they don't fight over the cursor and keyboard. |
| State | `app.clearState()` isn't supported yet. |
| Secrets | Password fields never expose their value and are painted black in screenshots (a field whose states can't be read isn't painted and shows dots instead). If a screenshot can't cover a readable password field, or the window exceeds `maxDepth`, it fails instead of saving. |

Temporary accessibility state is cleaned up when the run exits, and if an
app or worker gets killed mid-run, the next desktop run cleans up the
leftover app process automatically.

<Accordion title="Additional desktop edge cases">
- **Unreadable windows:** a window that can't be read never reads as empty,
  so `not.toBeVisible()` can't pass on it.
- **Large field values:** a field value over 64 KiB, or one agent-desktop
  couldn't read, reads as empty.
- **Pop-up menus:** choosing a missing option in a pop-up button can leave
  its menu open; e2e tries Escape to close it, which only reaches the app in
  `headed: true` mode.
</Accordion>

## Options

| Option | Type | Default |
| --- | --- | --- |
| `binary` | `string` | the downloaded release |
| `snapshot` | `'full' \| 'interactive'` | `'full'` |
| `headed` | `boolean` | `false` |
| `settle` | `number \| false` | `150` |
| `maxDepth` | `number` | `24` |

`snapshot: 'interactive'` makes the agent's observations read only controls,
without static text; locators and `expect` read the whole window either way.
`settle` is how long the engine waits after an agent action before the agent
reads the screen, in milliseconds. `maxDepth` is how many levels of a window a
read goes down, from 1 to 50; raise it when locators on a deeply nested app
time out on a read only in part.
