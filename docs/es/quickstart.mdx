## Configura con tu agente de programación

Pega este prompt en Claude Code, Codex, Cursor u otro agente de programación,
en el directorio de tu app:

<SetupPrompt>

<Prompt description={setupPrompt} children={setupPrompt} actions={["copy", "cursor"]} />

</SetupPrompt>

El agente instala el [skill de e2e](/coding-agents), así que los prompts
posteriores, como «añade un test para el pago», no requieren más configuración.

<Note>
Usa Node.js 24.8 o superior (22.22.3 o superior en Node.js 22), o [Bun](/reference/cli#bun) 1.4.3 o superior para los tests web. En Windows, ejecuta dentro de WSL. Los tests móviles
también necesitan Xcode con un runtime de simulador de iOS, o el SDK de Android con un emulador.
</Note>

## Configuración manual

### Ejecuta tu primer test

<Steps>
  <Step title="Crea el proyecto de tests">
  En el directorio de tu app:

  <CodeGroup>
  ```bash npm
  npx e2e init
  ```

  ```bash pnpm
  pnpm dlx e2e init
  ```

  ```bash bun
  bunx e2e init
  ```
  </CodeGroup>

  Elige **Web (Playwright)** o **Mobile (iOS/Android)** y, después, una
  suscripción, un proveedor de modelos o **None** para tests sin IA. El
  asistente escribe una configuración y un test de ejemplo, añade
  dependencias y ofrece configurar tu agente de programación. Conserva los
  archivos existentes.

  <Tabs>
    <Tab title="Web">
    Inicia el servidor de desarrollo de tu app en `http://localhost:3000`, o indica su dirección
    en `e2e.config.ts`. También puedes [dejar que e2e lo inicie](/web#starting-your-app).

    <Accordion title="Configuración y test de ejemplo para web">
    Esta configuración usa Vercel AI Gateway. El asistente configura el proveedor que elegiste.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
} satisfies E2EConfig;
```

```ts title="tests/example.e2e.ts"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('app opens', async ({ app, browser }) => {
  await app.open('/');
  await expect(browser.locator('body')).toBeVisible();
});
```
    </Accordion>
    </Tab>
    <Tab title="Móvil">
    Ejecuta `npx e2e doctor` para comprobar tu entorno. El asistente elige iOS en macOS
    y Android en los demás sistemas. El ejemplo abre la app Ajustes.

    <Accordion title="Configuración y test de ejemplo para iOS">
    Esta configuración usa Vercel AI Gateway. Para Android, el asistente establece
    `platform: 'android'` y `app: { bundleId: 'com.android.settings' }`.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { gateway } from 'ai';

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [{ name: 'ios', engine: mobile({ platform: 'ios' }), app: { bundleId: 'Settings' } }],
  workers: 1,
} satisfies E2EConfig;
```

```ts title="tests/example.e2e.ts"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('Settings opens', async ({ app, screen }) => {
  await app.open();
  await expect(screen.getByRole('button', 'General')).toBeVisible();
});
```
    </Accordion>

    Consulta [Móvil](/mobile) para usar tu propia app.
    </Tab>
  </Tabs>
  </Step>
  <Step title="Ejecuta el ejemplo">
  <CodeGroup>
  ```bash npm
  npx e2e run
  ```

  ```bash pnpm
  pnpm exec e2e run
  ```

  ```bash bun
  bunx e2e run
  ```
  </CodeGroup>

  e2e descarga un navegador o inicia el simulador o emulador, comprueba que
  la app se abre e imprime el resultado. El ejemplo no hace llamadas al modelo,
  así que no necesita iniciar sesión ni una clave de API.
  </Step>
</Steps>

### Añade un paso del agente

Da a `agent.act` un [objetivo atómico](/core-concepts#goals) por llamada y
comprueba después el resultado. Adapta el ejemplo a un flujo de tu app:

<Tabs>
  <Tab title="Web">
```ts title="tests/agent.e2e.ts"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('a visitor signs up for a trial', async ({ app, agent, screen }) => {
  await app.open('/');

  await agent.act('sign up for a free trial as {name} with email {email}', {
    params: { name: 'Ada Lovelace', email: 'ada@example.test' },
  });

  await agent.assert('the welcome screen greets Ada by name');
  await expect(screen.getByRole('status')).toContainText('trial');
});
```
  </Tab>
  <Tab title="Móvil (iOS)">
```ts title="tests/agent.e2e.ts"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('the agent opens General', async ({ agent, app, device }) => {
  await app.open();
  await agent.act('open {section} settings', { params: { section: 'General' } });

  await agent.assert('the General settings screen is showing');
  await expect(device.locator('role=navigation-bar id=General')).toBeVisible();
});
```

  `app.open()` inicia la app desde cero. Sin esa llamada, un test empieza
  donde la anterior dejó el dispositivo. `device.locator` acepta
  [selectores de agent-device](/mobile#the-device-fixture).
  </Tab>
</Tabs>

`params` rellenan los marcadores de posición del objetivo. `agent.assert` juzga la pantalla.
`expect` comprueba un valor exacto.

<CodeGroup>
```bash npm
npx e2e run tests/agent.e2e.ts
```

```bash pnpm
pnpm exec e2e run tests/agent.e2e.ts
```

```bash bun
bunx e2e run tests/agent.e2e.ts
```
</CodeGroup>

Si elegiste **None** en el asistente, [añade un modelo](/models) primero. Añade
`--headed` para ver un test web. Añade `--no-cache` para llamar al modelo en lugar de
reproducir las acciones en caché.

### Configura el proyecto

`e2e.config.ts` contiene las opciones. Estas son las que la mayoría de los
proyectos cambia después de `init`:

| Para | Establece | Consulta |
| --- | --- | --- |
| apuntar a tu app | `app.url`, o `app.bundleId` en móvil | [La app bajo prueba](/reference/config#the-app-under-test) |
| iniciar la app con la ejecución | `app.command` | [Iniciar tu app](/web#starting-your-app) |
| usar un modelo | `agents.default.model` | [Modelos](/models) |
| probar varios navegadores o dispositivos | una entrada de `targets` para cada uno, con un `name` | [targets](/reference/config#targets) |
| dar más tiempo a los tests | `timeout`, `actionTimeout`, `assertionTimeout` | [timeout](/reference/config#timeout) |
| reintentar los tests fallidos | `retries`, `1` en CI | [retries](/reference/config#retries) |
| ejecutar tests en paralelo | `workers`, `1` en CI | [workers](/reference/config#workers) |
| elegir los archivos de test | `tests` | [tests](/reference/config#tests) |
| conservar trazas y videos | `trace`, `video` | [Grabación](/reference/config#recording) |
| escribir un informe JUnit | `reporters: ['list', 'junit']` | [reporters](/reference/config#reporters) |
| iniciar sesión y pasar claves de API | `credentials`, `secrets` | [Autenticación](/authentication) |
| escribir la caché de reproducción en CI | `cache: 'read-write'` | [Caché](/cache) |

<Accordion title="Configuración de ejemplo con opciones habituales">
```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

const app = {
  url: process.env.APP_URL ?? 'http://localhost:3000',
  command: { executable: 'npm', args: ['run', 'dev'], reuseExisting: true },
};

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [
    { name: 'chromium', engine: web({ viewport: { width: 1440, height: 900 } }), app },
    { name: 'firefox', engine: web({ browser: 'firefox' }), app },
  ],
  timeout: 180_000,
  workers: 4,
  reporters: ['list', 'junit'],
  video: 'retain-on-failure',
} satisfies E2EConfig;
```

`--target firefox` ejecuta un solo destino. Los destinos que comparten un mismo `command` comparten
un único proceso de servidor.
</Accordion>
