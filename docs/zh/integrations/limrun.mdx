`@e2e-dev/limrun` 是移动端引擎的托管设备提供方。它为每个工作进程创建设备、安装应用，并在运行结束时释放设备。使用标准的 `app`、`screen` 和 `expect` API 测试应用的用户流程。

## 安装和身份验证

将集成包与移动端引擎及其对等依赖项一起安装：

<CodeGroup>
```bash npm
npm install --save-dev e2e @e2e-dev/mobile @e2e-dev/limrun @limrun/api
```

```bash pnpm
pnpm add -D e2e @e2e-dev/mobile @e2e-dev/limrun @limrun/api
```

```bash bun
bun add -d e2e @e2e-dev/mobile @e2e-dev/limrun @limrun/api
```
</CodeGroup>

在启动 e2e 的环境中设置 `LIMRUN_API_KEY`。在 CI 中，将其存储为机密值。使用具有创建和控制实例权限的密钥。提供方读取本次运行的环境，不会读取 `lim login` 会话或 `LIM_API_KEY`。

测试运行器需要 Node.js 和包依赖项。对于 Android，将 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) 中的 `adb` 加入 `PATH`，无需本地模拟器。iOS 运行器无需本地 Xcode 或模拟器。请单独构建适用于 iOS 模拟器的应用或 Android APK。

## 配置测试目标

在移动端引擎上设置 `device: limrun()`，并将 `appPath` 指向构建产物。此配置运行 Limrun 的[应用流程示例](https://github.com/limrun-inc/testerarmy-e2e-limrun)中的 SwiftUI 应用。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { limrun } from '@e2e-dev/limrun';

export default {
  targets: [{
    name: 'ios',
    engine: mobile({ platform: 'ios', device: limrun() }),
    app: {
      bundleId: 'dev.e2e.examples.swiftui',
      appPath: 'build/HelloApp.app',
    },
  }],
  workers: 2,
} satisfies E2EConfig;
```

对于 Android，使用 `platform: 'android'`，将应用包名设为 `bundleId`，将 APK 设为 `appPath`。路径相对于项目根目录解析。提供方会在测试开始前安装构建产物。

## 测试应用流程

使用稳定的测试 ID 和可见文本填写表单并检查结果。此测试纠正一次空表单提交，并保存问候语的截图。

```ts title="tests/greeting.e2e.ts"
import { expect } from 'e2e';
import { test } from '@e2e-dev/mobile';

test('corrects an empty submission', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('greet').click();
  await expect(screen.getByText('Enter a name first.', { exact: true })).toBeVisible();

  await screen.getByTestId('name').fill('Ada');
  await screen.getByTestId('greet').click();
  await expect(screen.getByText('Hello, Ada!', { exact: true })).toBeVisible();
  await expect(screen.getByText('Enter a name first.', { exact: true })).not.toBeVisible();
  await app.screenshot('greeting');
});
```

Limrun 维护了一个[可运行的示例](https://github.com/limrun-inc/testerarmy-e2e-limrun)，在 SwiftUI 和 Compose 应用上使用相同的五个测试。它涵盖初始表单、验证失败后的恢复、去除首尾空白的输入、重复提交和应用重启。Limrun 远程构建这两个应用，配置中包含两个测试目标。无需 AI 密钥。

## 录制运行

添加 `--video`，录制每次尝试：

<CodeGroup>
```bash npm
npx e2e run --video
```
```bash pnpm
pnpm exec e2e run --video
```
```bash bun
bunx e2e run --video
```
</CodeGroup>

视频和截图与运行报告一起保存在 `.e2e/` 下。

## 选择设备选项

| 选项 | 默认值 | 用途 |
| --- | --- | --- |
| `region` | 由 Limrun 选择 | 区域偏好，例如 `eu` 或 `us-east1`。容量限制可能导致调度到其他区域。 |
| `hardTimeout` | `1h` | 设备最长存活时间，包括被遗弃的运行。使用 Go 时长格式，例如 `30m` 或 `2h`。 |
| `ios.model` | 由 Limrun 选择 | `iphone` 或 `ipad`。 |
| `android.model` | 由 Limrun 选择 | `phone` 或 `tablet`。 |
| `android.osVersion` | `15` | 请求的 Android 主版本号，作为调度参考。 |

每个工作进程都会在测试运行器上获得一个隔离的 agent-device 守护进程和一个 Limrun 实例。守护进程使用 agent-device 的 Limrun 驱动来控制应用和录制。集成包固定使用与移动端引擎相同的 agent-device 版本，并在分配设备前检查版本。

设备必须在五分钟内就绪并完成安装。准备失败后，提供方会执行清理；运行结束或中断时，引擎会释放所有已获取的设备。其他测试目标运行期间，提供方会续租空闲驱动的租约。守护进程会在命令间隙保持活跃设备运行；如果运行器消失，硬超时仍是最长存活时间上限。请将超时时间设得比运行时长更长。

实例 ID 会显示在进度输出中。在 Limrun 中通过 `source=e2e` 和 `run=<run id>` 标签查找某次运行的实例。录制使用常规移动端产物路径，即每次尝试目录内的 `video/video.mp4`。

## 检查应用兼容性

Limrun 的 iOS 传输层会以 `UNSUPPORTED_CAPABILITY` 拒绝 `locator.press('Enter')` 等键盘操作。如果流程提供提交按钮，请点击该按钮。

在应用的目标运行时上测试所使用的定位器和库。问候语示例展示的是原生表单流程，并不代表兼容所有移动端框架或控件。
