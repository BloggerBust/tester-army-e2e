`e2e` CLI 会发送匿名使用数据：用户使用哪些命令、引擎和功能，以及运行在哪些环节失败。遥测默认开启，只发送计数和版本，绝不发送测试内容、应用内容或凭据。

## 退出遥测

以下任一种方式都可关闭遥测：

<CodeGroup>
```bash npm
npx e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```

```bash pnpm
pnpm exec e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```

```bash bun
bunx e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```
</CodeGroup>

环境变量优先于已保存的设置。`e2e telemetry enable` 会撤销已保存的 `disable`。`e2e telemetry` 输出状态，并在关闭时说明原因。如果设置了 XDG_CONFIG_HOME，偏好设置文件就位于 `$XDG_CONFIG_HOME/e2e/`；Windows 上则位于 `%APPDATA%\e2e\`。

`disable` 也会停止其他终端中已在运行的命令发送遥测。偏好设置目录不可写时，或从 e2e 仓库的源码检出目录运行时，不会发送任何内容。

## 查看将发送的内容

<CodeGroup>
```bash npm
E2E_TELEMETRY_DEBUG=1 npx e2e run
```

```bash pnpm
E2E_TELEMETRY_DEBUG=1 pnpm exec e2e run
```

```bash bun
E2E_TELEMETRY_DEBUG=1 bunx e2e run
```
</CodeGroup>

CLI 会以 `[telemetry] {...}` 格式将确切的载荷输出到标准错误，不发送任何内容。

## 发送的内容

每个命令都会发送一个 `e2e_cli_session` 事件。`run` 和 `explore` 还会发送 `e2e_run_completed`；`init` 发送 `e2e_init_completed`（`explore` 先运行初始化向导时也会发送）；`upgrade` 发送 `e2e_upgrade_completed`；`mcp` 为每个 MCP 会话发送一个 `e2e_mcp_session`。任何命令使用 `--help` 和 `--version` 时都不发送任何内容。`e2e/runner` 中的 `run()` 和 `explore()` 不发送会话事件，只在每次调用返回报告时发送一个 `e2e_run_completed`。

命令、`run()` 或 `explore()` 结束时，事件会在同一个请求中发送，截止时限为两秒。`e2e mcp` 为每个会话事件单独发送请求，`e2e run --watch` 则在每次运行结束时发送该次运行的事件。

事件只包含以下属性。不是大写标记的错误代码会作为 `OTHER` 发送。引擎、平台、模型、机群或 MCP 客户端名称，以及 MCP 客户端版本，如果不是仅由字母、数字、点、连字符和下划线组成的简单标记，都会作为 `other` 发送。不符合 semver 的引擎版本会作为 `unversioned` 发送。在操作和工具调用计数中，项目自有工具统一计为 `tool`，其他任何名称计为 `other`。

## 绝不发送的内容

遥测绝不发送测试标题、文件路径、URL、源、指令、观测、页面内容、截图、错误消息、堆栈追踪、环境变量值、凭据或文件内容。它也绝不发送测试目标、智能体、凭据、机密值或项目工具的名称，MCP 工具参数或结果，探索目标或探索任务，以及发现内容的文字。

## 在 CI 中

CI 运行按 CI 厂商计数，而不是按机器计数，不使用偏好设置文件，也不显示通知。如果编码智能体在 Shell 中设置了 `CI`，但周围没有 CI 厂商环境，则按它所在的机器计数。

在 CI 中，只有环境变量能关闭遥测。在作业的 `env` 中设置 `E2E_TELEMETRY_DISABLED: '1'`。

## 在机群中

如果平台在新机器上为用户运行 e2e，每台机器都会被计为新用户。在这些机器上设置 `E2E_TELEMETRY_FLEET=<name>`。其事件将计为 `fleet:<name>`，与 CI 一样，不使用偏好设置文件，也不显示通知。也可以设置 `E2E_TELEMETRY_DISABLED=1`，不发送任何内容。

## 发送到哪里

事件发送到 `eu.i.posthog.com`，这是 e2e 维护者运营的 PostHog 项目。PostHog 不保留个人档案，不存储请求地址，并为每个事件跳过 GeoIP。数据以汇总形式查看。

遥测受[安全策略](https://github.com/e2e-inc/e2e/blob/main/SECURITY.md)约束。[出站连接](/reference/security#outbound-connections)列出了运行可能建立的所有其他连接。

## 反馈

[`e2e feedback`](/reference/cli#e2e-feedback) 不属于遥测。它会将参数中的文字作为一个 `e2e_feedback` 事件发送到同一 PostHog 项目，并附带上述机器信息。遥测开启时，它与遥测事件使用相同的匿名 ID。

已保存的 `e2e telemetry disable` 不会阻止它。`E2E_TELEMETRY_DISABLED=1` 和 `DO_NOT_TRACK=1` 则会阻止。[CLI 参考](/reference/cli#e2e-feedback)介绍了脱敏、`--dry-run`，以及没有 `--repro` 的 Bug 报告。

## 通知

首个命令，或 `e2e/runner` 中首次调用的 `run()` 或 `explore()`，会在标准错误中打印一条说明如何退出遥测的通知，不影响 `--reporter json` 的输出。`e2e init` 和 `e2e telemetry` 不打印通知，因此通知会等到下一个命令再显示。收集的数据发生重大变化后，通知会再次显示。
