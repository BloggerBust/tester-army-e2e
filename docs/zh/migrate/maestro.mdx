## 迁移配置

<Note>按[移动端指南](/mobile)配置测试目标，按[快速开始](/quickstart)配置模型。</Note>

| Maestro | e2e |
| --- | --- |
| 每个流程顶部的 `appId` | 测试目标上的 `app: { bundleId: 'com.example.app' }`，即 `app.open()` 启动的应用 |
| 每个流程使用不同的 `appId`，或流程中途使用第二个应用 ID | 在测试中调用 `device.openApp(id)`，或每个应用使用一个配置 |
| `--platform`、`--device` | `mobile({ platform: 'ios', device: 'iPhone 17' })`，每个平台一个测试目标；`device` 列表是设备池。仅本次运行使用时，`e2e run --target ios --device 'iPhone 17'` |
| `.maestro/config.yaml` `flows`、`'!helper.yaml'` | `tests: ['tests/**/*.e2e.ts', '!tests/helpers/**']` |
| `tags`、`--include-tags`、`--exclude-tags` | 测试或分组上的 `{ tags: [...] }`；CLI 的 `--tag`、`--exclude-tag` |
| `env` 和 `${VAR}` | 模块常量，以及目标中的 `params`：`agent.act('sign in as {email}', { params: { email } })` |
| `MAESTRO_*` 变量 | 配置中的 `process.env`；密码和令牌放在 `credentials` 或 `secrets` 下，参阅[身份验证](/authentication) |
| `--format junit` | `--reporter list,junit` 写入 `.e2e/junit.xml` |
| `--format html` | `@e2e-dev/html-reporter` 中的 `htmlReporter()` 写入 `.e2e/report.html` |
| `--shards`、`--shard-split` | 单机使用 `device: [...]` 加 `workers`；跨机器使用 `--shard <index/total>`，参阅[分片](/ci#sharding) |
| `maestro record` | `npx e2e run --video`，每次尝试生成一段设备 MP4 视频，或使用托管提供方自己的录像 |
| `maestro test -c` | `npx e2e run --watch` |
| `maestro hierarchy` | 测试中用 `await screen.debug()` 输出屏幕树；`screen.tree()` 返回屏幕树 |

## 改写一个流程

从 `optional` 步骤和 `runFlow: { when }` 分支经常需要更新的流程开始。

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

## 改写选择器

- Maestro 将文本和 ID 视为不区分大小写的正则表达式。`getByText` 和 `getByTestId` 匹配整个字符串，且区分大小写。使用 `getByText(/^mute account$/i)`，或用 `{ exact: false }` 匹配文本子串。
- Maestro 会点击多个匹配项中的第一项。e2e 会以 `LOCATOR_AMBIGUOUS` 失败，因此如果你想要第一项，就添加 `.first()`。
- `isVisible()` 替代 `optional` 和 `runFlow: { when }`。它只读取一次屏幕，不等待。匹配多项时会失败，因此可能存在隐藏的重复节点时，添加 `{ visible: true }` 或 `.first()`。
- `below`、`above`、`leftOf` 和 `rightOf` 没有对应方法，参阅[尚未支持](#not-yet)。在 iOS 的普通 React Native `View` 上，`filter({ has })` 和链式查询匹配不到任何内容，参阅[已知设备限制](/mobile#known-device-limitations)。

## e2e 尚未支持的功能

“已计划”表示已列入路线图，“尚未支持”表示暂无日期。“不计划支持”表示有意不提供。

### 已计划

| Maestro | 当前替代方案 |
| --- | --- |
| `permissions: { all }`、默认授予全部权限、`bluetooth` 和 `storage` 等名称 | 在 `app.permissions` 中逐项列出权限，或用 `device.alert('accept')` 接受提示 |
| `point: "50%,50%"`、`swipe` 中以百分比表示的 `start` 和 `end` | 根据全屏节点的 `boundingBox()` 计算像素 |
| 不指定字段的 `inputText` 和 `pressKey: Enter`、`eraseText: N`、`pressKey: backspace`、`tab` | 在字段定位器上调用 `fill` 或 `press`；用 `fill` 填入缩短后的 `inputValue()` 来删除文本；点击下一个字段来替代 Tab |
| `addMedia` | 在 iOS 模拟器上，在 `app.open()` 前运行 `xcrun simctl addmedia`；Android 未验证。参阅[设备测试夹具](/mobile#the-device-fixture)中的“用于选择器测试的照片” |
| 命令上的 `label` | `-`。每个步骤以调用命名 |
| `scrollUntilVisible: { centerElement, visibilityPercentage }` | 没有完全对应的方法。完成后读取 `boundingBox()`，如果节点不在中央，再调用 `screen.swipe({ direction, momentum: 'slow' })` |
| 失败时附带设备日志和崩溃报告 | 在测试夹具中收集 `adb logcat` 或 `xcrun simctl spawn <udid> log stream` |
| 作为终端命令的 `maestro hierarchy` | 一个调用 `screen.debug()` 的单行测试 |
| `--device-locale` | iOS 使用 `app.launchArguments: ['-AppleLanguages', '(de)', '-AppleLocale', 'de_DE']`，参阅[以其他语言运行应用](/mobile#run-the-app-in-another-language)；Android 在运行前设置设备语言 |
| Maestro Cloud | 你的 [CI](/ci) 配合[托管设备提供方](/mobile#hosted-devices) |
| `pressKey: lock`、`power`、`volume up`、`volume down` | [`unstable_raw`](/reference/mobile#unstable_raw) 上的 `client.command.hardwareButton`：Android 支持电源和音量键，iPhone 真机支持音量键 |
| JUnit `properties`、通过 `--output` 设置 JUnit 路径 | 将 ID 放入标签或标题；运行后复制 `.e2e/junit.xml` |

### 尚未支持

| Maestro | 当前替代方案 |
| --- | --- |
| `optional: true` | `if (await locator.isVisible())` 或 try/catch；报告不会显示警告 |
| `executionOrder` | 一个 `describe(..., { serial: true })`，将每个流程作为函数调用 |
| `retry: { maxRetries, commands }` | 带 try/catch 的 `for` 循环；值使用 `expect.poll`，整个测试使用 `{ retries }` |
| 用 `killApp` 模拟 Android 进程死亡 | `device.home()`，然后 `adb shell am kill <package>`，再调用 `device.openApp(id)` |
| `assertDarkMode`、`assertLightMode` | 对采用主题样式的控件进行断言，或使用 `toHaveScreenshot` |
| 电视遥控器按键 | `-` |

### 不计划支持

| Maestro | 替代方案 |
| --- | --- |
| 将文本和 ID 视为正则表达式，并采用第一个匹配项 | `RegExp` 和 `.first()`，参阅[改写选择器](#rewrite-selectors) |
| `retryTapIfNoChange` | 断言结果，然后在测试中再次点击。盲目执行第二次点击可能触发控件两次 |
| `waitToSettleTimeoutMs` | 操作后使用带独立 `timeout` 的断言；该断言就是等待 |
| `toggleAirplaneMode`、`toggleDarkMode` | 设置所需状态：`device.setAirplaneMode(true)`、`device.setAppearance('dark')` |
| Maestro Studio | 通过 [`npx e2e mcp`](/mcp-server) 使用编码智能体，或将 `screen.debug()` 与 `npx e2e run --watch` 或 `--step` 配合使用 |
| `waitForAnimationToEnd` | 对动画结束后出现的内容调用 `await expect(locator).toBeVisible()` |
| `below`、`above`、`leftOf`、`rightOf` | `getByLabel`、测试 ID、共享容器上的 `filter({ has })`，或 `agent.act` 目标 |

## 有意保留的差异

- Maestro 启动应用时会授予全部权限。e2e 只授予你明确指定的权限，因此迁移后的流程会遇到 Maestro 从未显示过的系统提示。在 [`app.permissions`](/mobile#launch-arguments-and-permissions) 中逐项列出，使用 `grant`、`deny`、`reset` 对应 Maestro 的 `allow`、`deny`、`unset`。
- 通过 [`device.unstable_raw`](/reference/mobile#unstable_raw) 执行的调用不算步骤。报告、追踪记录、智能体缓存和脱敏都不会处理这些调用。
- 设备不支持 `test.setup` 或 `{ session }`，参阅[与网页端的差异](/mobile#what-differs-from-the-web)。
