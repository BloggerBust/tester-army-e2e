TesterArmy 中保存的测试是一组自然语言步骤，由 QA 智能体在 TesterArmy 云端运行。在 e2e 中，每个步骤都会变为 TypeScript 测试中的一行，在你的机器或 CI 中运行：它可以是 `agent.act` 或 `agent.assert` 调用；如果步骤无需判定，也可以是定位器调用。编码智能体通过 TesterArmy MCP 服务器读取你的项目和测试，并编写 e2e 测试。

## 连接 TesterArmy MCP 服务器

编码智能体从 `https://tester.army/mcp` 上的托管服务器读取你的测试。将它添加到你机器上的编码智能体中：

<CodeGroup>
```bash npm
npx add-mcp --global --name testerarmy https://tester.army/mcp
```

```bash pnpm
pnpm dlx add-mcp --global --name testerarmy https://tester.army/mcp
```

```bash bun
bunx add-mcp --global --name testerarmy https://tester.army/mcp
```
</CodeGroup>

`add-mcp` 会将 Claude Code 的条目写入 `~/.claude.json`。如果设置了 `CLAUDE_CONFIG_DIR`，请改为运行 `claude mcp add --transport http testerarmy https://tester.army/mcp`。客户端提示时进行登录。其他添加服务器的方式见 [TesterArmy 的 MCP 配置](https://tester.army/docs/cli/mcp)。

迁移只会读取 TesterArmy 中的内容，绝不会编辑、删除或运行其中的测试。

## 迁移项目

<Note>按照[快速开始](/quickstart)安装 e2e 并配置模型。智能体调用需要模型。</Note>

| TesterArmy | e2e |
| --- | --- |
| 网页端项目的 `url` | `web()` 测试目标上的 `app: { url }` |
| 移动端项目及其上传的构建产物 | 设置了 `app: { bundleId, appPath }` 的 `mobile({ platform })` 测试目标。你负责构建应用，`device.installApp()` 负责安装，参阅[移动端](/mobile) |
| 静态环境（Staging、QA） | 每个环境对应一个测试目标，各自设置 `app.url`。`--target staging` 只运行一个测试目标 |
| PR 预览环境 | 在 CI 作业中将 `app.url` 设为预览 URL，参阅[受保护的预览](/web#protected-previews) |
| `login` 凭据 | 一个 `credentials` 条目。TesterArmy 从不返回密码或 TOTP 机密值，因此应从环境变量读取，参阅[身份验证](/authentication#credentials) |
| 凭据的 `totpSecret` | 一个 `secrets` 条目，其值为计算验证码的函数。e2e 不附带 TOTP 生成器，因此需要添加一个 TOTP 库 |
| 凭据的环境覆盖值 | 一个 `credentials` 条目，在每个环境中设置 `E2E_USER_<NAME>_PASSWORD`，参阅[按运行覆盖值](/authentication#override-a-value-per-run) |
| `agentInstructions` | 智能体上的 `system`，参阅[指令与工具词汇](/agents#instructions-and-vocabulary) |
| 记忆 | 智能体上的 `context` |
| 项目文件 | 代码仓库中的文件，例如 `tests/fixtures/receipt.jpg` |
| 测试的 `viewport` 设置 | `web({ viewport: { width, height } })`，每种尺寸对应一个测试目标 |
| PR 测试 | 在每个拉取请求（PR）上运行 e2e 作业，并使用 [GitHub 报告器](/github)发表评论 |
| 分组计划 | 定时运行的 CI 工作流 |

## 改写一个测试

每个步骤对应一次带 await 的调用。`login` 步骤变为初始化测试，只登录一次并保存会话：

```json title="TesterArmy (get_test)"
{
  "title": "Creates a project",
  "steps": [
    { "type": "login", "title": "Log in as the admin" },
    { "type": "act", "title": "Open Projects from the sidebar and click New Project" },
    { "type": "act", "title": "Name the project Apollo and save" },
    { "type": "assert", "title": "Apollo appears in the project list" }
  ]
}
```

<Tabs>
  <Tab title="tests/projects.e2e.ts">

```ts
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('creates a project', { session: 'admin' }, async ({ app, agent, screen }) => {
  await app.open('/');
  await agent.act('open Projects from the sidebar and click New Project');
  await agent.act('name the project {name} and save', { params: { name: 'Apollo' } });
  await agent.assert('Apollo appears in the project list');
  await expect(screen.getByText('Apollo')).toBeVisible();
});
```

  </Tab>
  <Tab title="tests/auth.setup.e2e.ts">

```ts
import { test } from '@e2e-dev/web';
import { credentials } from 'e2e';

test.setup('log in as the admin', { sessions: ['admin'] }, async ({ app, agent, session }) => {
  const admin = credentials.user('admin');

  await app.open('/login');
  await agent.act('log in', { params: { username: admin.username, password: admin.password } });
  await agent.assert('the dashboard is shown');
  await session.save('admin');
});
```

  </Tab>
</Tabs>

TesterArmy 会在第一个步骤之前打开项目 URL。在 e2e 中，页面不会自动打开，因此每个测试都以 `app.open()` 开始。

## 映射每个步骤

| TesterArmy | e2e |
| --- | --- |
| `act` 步骤 | `agent.act('...')`；如果步骤只是打开已知路由或操作一个有名称的控件，也可以使用定位器调用 |
| `assert` 步骤 | `agent.assert('...')`；如果标签或测试 ID 能标识结束状态，再添加一个定位器断言 |
| `login` 步骤 | 在 `test.setup` 中登录并调用 `session.save()`，然后在每个测试上设置 `{ session }`，参阅[身份验证](/authentication) |
| 网页端的 `files` 步骤、步骤中的 `@receipt.jpg` | 在目标中使用文件在代码仓库中的路径：`agent.act('attach tests/fixtures/receipt.jpg')`，或使用 `locator.setInputFiles()` |
| `screenshot` 步骤 | `app.screenshot('label')` |
| `javascript` 步骤 | `browser.evaluate()`。只有代码抛出错误时它才会失败，因此需要用 `expect` 检查 `{ success: false }` 返回值 |
| 设置了 `disabled: true` 的步骤 | 省略该步骤 |
| 已禁用的测试 | `test.skip` |
| 分组 | 带有 `tags` 的 `describe`，通过 `npx e2e run --tag <tag>` 运行 |
| 分组的 `runMode: sequential` | 在分组上设置 `{ serial: true }` |
| 分组的 `maxConcurrentRuns` | 配置中的 `workers`。它限制整次运行，而非单个分组 |
| 分组的 `prepTestId` | 保存会话的 `test.setup`，以及分组上的 `{ session }` |
| `run_test`, `run_group` | `npx e2e run <file>`、`npx e2e run --tag <tag>` |

如果步骤需要读取屏幕后再决策、跨越多个屏幕，或没有稳定的控件名称，就保留智能体。在将步骤替换为定位器之前，先找到控件的准确名称，并检查相同的结束状态。

## e2e 尚不支持的功能

“已规划”表示已列入路线图。“尚未支持”表示没有确定日期。“不计划支持”表示有意不提供。请使用替代方案，或将测试保留在 TesterArmy 中。

### 已规划

| TesterArmy | 当前可用方案 |
| --- | --- |
| `inbox` 凭据、使用 `temporaryEmail` 的 `login` | 从[测试夹具](/fixtures)调用你自己的测试收件箱 |
| 移动端的 `files` 步骤（照片图库） | 在 iOS 模拟器上，在 `app.open()` 前运行 `xcrun simctl addmedia`，然后在系统选择器中选取照片；Android 尚未验证。参阅[设备测试夹具](/mobile#the-device-fixture)下的“为选择器测试准备照片” |
| `accessibilityAuditEnabled` | - |

### 尚未支持

| TesterArmy | 当前可用方案 |
| --- | --- |
| `microphone` 步骤 | - |

### 不计划支持

| TesterArmy | 替代方案 |
| --- | --- |
| `browserRegion`, `simulatorRegion` | 浏览器运行在执行 `e2e run` 的机器上，或运行在[托管提供方](/integrations)上 |
| `webSearchEnabled` | 将智能体需要了解的内容放在其 `context` 中 |

## 有意保留的差异

- 测试在你的机器或 CI 中运行，而非 TesterArmy 云端。由你选择应用 URL 和设备。
- 模型永远看不到密码。运行器通过句柄输入密码，参阅[身份验证](/authentication#the-password-is-a-handle)。
- `agent.act` 步骤会回放其录制的操作，无需调用模型。屏幕不再匹配时，由智能体接手，参阅[回放缓存](/cache)。
