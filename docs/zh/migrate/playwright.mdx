e2e 可以在同一个项目中与 Playwright 并行运行，让你逐个文件迁移测试。`@e2e-dev/web` 自带固定版本的 `playwright-core`，因此你的 `@playwright/test` 版本不受影响。e2e 默认读取 `e2e.config.ts` 并查找 `tests/**/*.e2e.ts`，因此请确保两套文件匹配模式互不重叠。

## 迁移配置

<Note>按照[快速开始](/quickstart)安装 e2e 并配置模型。</Note>

使用 `testDir`、`baseURL`、`use`、`webServer` 或 `projects` 等 Playwright 配置键会失败，错误消息会指出应该使用的 e2e 配置键。[配置参考](/reference/config)列出了所有键。

| Playwright | e2e |
| --- | --- |
| `use.baseURL`, `webServer` | 测试目标上的 `app: { url, command }`，参阅[启动应用](/web#starting-your-app) |
| `webServer.reuseExistingServer` | `app.command: { reuseExisting: true }`；CI 会忽略它 |
| `projects` | `targets`，每项一个引擎实例 |
| `testDir`, `testMatch`, `testIgnore` | `tests`，相对于项目根目录的 glob 模式；前缀 `!` 表示排除 |
| `retries`, `workers`, `timeout` | 名称相同，但[默认值不同](#defaults-that-differ)；`workers` 为整数 |
| `expect.timeout`, `use.actionTimeout`, `globalTimeout` | `assertionTimeout`、`actionTimeout`、`maxDuration`；`maxDuration` 从测试开始时计时，不包含应用启动 |
| `maxFailures`, `use.headless: false` | CLI 上的 `--max-failures <n>` 和 `--headed` |
| `reporter`, `outputDir` | `reporters: ['list', 'junit', htmlReporter()]`，其中 `htmlReporter` 来自 `@e2e-dev/html-reporter`；也支持 `dot`、`json` 和 `markdown`；`output` 默认为 `.e2e` |
| `use.viewport`, `locale`, `timezoneId`, `colorScheme`, `reducedMotion`, `userAgent`, `testIdAttribute` | `web({ ... })` 中的同名键 |
| `use.browserName`, `httpCredentials`, `extraHTTPHeaders` | `web({ browser, basicAuth, headers })`；`basicAuth` 和 `headers` 仅作用于应用的源，可通过 [`credentialOrigins`](/reference/web#credentialorigins) 添加更多源 |
| `chromium.connectOverCDP(url)` | `web({ connect: { cdpEndpoint: () => url } })`，仅限 chromium |
| `use.trace`, `use.video` | `trace`、`video`：在配置、测试目标或测试上设置模式。`web({ screencast: { size } })` 设置视频尺寸 |
| `use.permissions` | 测试目标上的 `app.permissions`，参阅[授予浏览器权限](/web#granting-browser-permissions) |
| 来自 `setup` 项目的 `use.storageState` | 使用带有 `session.save(name)` 的 `test.setup`，然后在测试上设置 `{ session }`，参阅[身份验证](/authentication) |
| 带有固定值的 `use.storageState: { cookies }` | 测试夹具中的 `browser.setCookies(cookies)` |

## 改写一个测试文件

从步骤经常变化的流程开始，例如向导或结账。稳定的 Playwright 测试可以保持原样。

```ts title="Playwright"
import { test, expect } from '@playwright/test';

test('checkout', async ({ page }) => {
  await page.goto('/cart');
  await page.getByRole('button', { name: 'Checkout' }).click();
  await page.getByLabel('Card number').fill('4242424242424242');
  await page.getByLabel('Expiry').fill('12/30');
  await page.getByLabel('CVC').fill('123');
  await page.getByRole('button', { name: 'Pay' }).click();
  await expect(page.getByRole('heading')).toHaveText('Order confirmed');
});
```

```ts title="e2e"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('checkout', async ({ app, agent, screen }) => {
  await app.open('/cart');
  await agent.act('pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123');
  await expect(screen.getByRole('heading')).toHaveText('Order confirmed');
});
```

智能体执行结账步骤，并在表单变化时进行适应。测试也可以保持完全确定性，为每一行 `page.getBy*` 对应一行 `screen.getBy*`。

## 迁移页面对象

页面对象接收 `screen` 以执行查询和操作，接收 `browser` 以使用键盘、鼠标、CSS 选择器和 `evaluate`。将它作为测试夹具提供：

```ts title="tests/page-models/account-page.ts"
import type { Locator, Screen } from 'e2e';
import type { Browser } from '@e2e-dev/web';

export class AccountPage {
  readonly accountName: Locator;

  constructor(
    readonly screen: Screen,
    readonly browser: Browser,
  ) {
    this.accountName = screen.getByTestId('account-name');
  }

  async filterByNote(note: string) {
    await this.screen.getByRole('button', 'Filter').click();
    await this.screen.getByRole('button', 'Note').click();
    await this.browser.keyboard.type(note);
  }
}
```

```ts title="tests/fixtures.ts"
import { test as base } from '@e2e-dev/web';
import { AccountPage } from './page-models/account-page.ts';

export const test = base.extend<{ accountPage: AccountPage }>({
  accountPage: async ({ screen, browser }, use) => {
    await use(new AccountPage(screen, browser));
  },
});
```

列出 `browser` 的测试夹具会让使用它的每个测试仅限网页端，参阅[保持可移植性](/page-object-model#keep-it-portable)。从钩子中移除 `newPage()` 和 `page.close()`：每次尝试都在全新的上下文中开始。

## e2e 尚未提供的功能

“已计划”表示已纳入路线图。“尚未实现”表示没有确定日期。“不计划支持”表示有意不提供。请使用替代方案，或将测试保留在 Playwright 中。

### 已计划

<Accordion title="定位器和操作">

| Playwright | 目前可用的方式 |
| --- | --- |
| `locator.locator(selector)`, `locator.and()`, `filter({ visible })` | 一个 `browser.locator` 选择器，例如 `'.card >> .close'`，或作用域内的 `screen` 查询 |

</Accordion>

## 有意保留的差异

- 字符串匹配完整文本，且区分大小写。Playwright 的 `getByRole` 名称、`getByLabel`、`getByPlaceholder` 和 `getByText` 匹配不区分大小写的子字符串。匹配片段时传入 `{ exact: false }` 或 `RegExp`。参阅[查询](/reference/screen#queries)。

  ```ts
  // <button>Save changes</button>, <label>Email address <input></label>
  screen.getByRole('button', 'Save');                  // no match
  screen.getByRole('button', { name: 'Save', exact: false });    // matches
  screen.getByRole('button', 'save changes');          // no match, case differs
  screen.getByLabel('Email');                                    // no match
  ```
- 文本读取的是渲染后的文本。`textContent()`、`toHaveText` 和 `toContainText` 读取 `innerText` 返回的内容，因此会忽略隐藏文本，并应用 `text-transform`。参阅[定位器读取](/reference/screen#locator-reads)。
- `toHaveRole` 接受 `getByRole` 使用的角色集合，因此 `paragraph`、`generic` 及其他未包含的角色会导致类型错误，`img` 则读取为 `image`。它比较的是语义树读取的角色，其中 `contenteditable` 编辑器是 `textbox`。
- 定位器采用严格匹配。对多个匹配项执行操作、读取或正向匹配器会触发 `LOCATOR_AMBIGUOUS`，而 Playwright 的 `page.click(selector)` 和 `isVisible()` 会取第一个。使用 `filter` 或 `first()` 缩小范围。
- `.not.toBeChecked()` 在按钮或标题上会通过。按角色查询控件，让断言在控件类型改变时失败。
- 会话仅持续一次运行。`test.setup` 以指定名称保存状态，`{ session }` 恢复状态。文件会加密，并在清理时删除，因此没有可复用的 `.auth/user.json`。
- 测试无法获取原始 `Page`，因为其上的任何操作都不会被记录、脱敏或遮蔽。`surfaceOf(engine)` 用于[自定义执行器](/executors#driving-the-page-yourself)，不用于测试代码。
