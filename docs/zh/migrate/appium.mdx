## 迁移能力配置

<Note>按照[移动端指南](/mobile)配置测试目标，按照[快速开始](/quickstart)配置模型。只有智能体步骤需要模型。</Note>

| Appium | e2e |
| --- | --- |
| `platformName`, `appium:automationName` | `mobile({ platform: 'ios' })` 或 `'android'` |
| `appium:deviceName`, `appium:udid` | `mobile({ device: 'iPhone 17' })`：名称、模拟器 UDID 或 `emulator-5554` 序列号。手机通过名称指定 |
| `appium:app` | `app: { appPath }`。自行安装构建产物，参阅[指定你的应用](/mobile#point-at-your-app) |
| `appium:bundleId`, `appium:appPackage` | `app: { bundleId }`，即 `app.open()` 启动的应用 |
| `appium:processArguments`, `appium:optionalIntentArguments` | `app.launchArguments`，字符串列表 |
| `appium:permissions` | `app.permissions: { camera: 'grant' }`。每个 [`DevicePermission`](/reference/mobile#device-fixture) 名称接受 `grant`、`deny` 或 `reset` |
| `appium:noReset` | 默认为 `true`，因此不会清除应用数据。若需 `false` 的行为，在测试开始时调用 `app.clearState()` |
| `appium:fullReset` | `device.installApp(path, { reinstall: true })` |
| `appium:newCommandTimeout`, WebDriverAgent 超时 | 无需设置。操作使用 `actionTimeout`，断言使用 `assertionTimeout`，测试使用 `timeout` |
| `bstack:options`, `lt:options` | 设备提供方：[`browserstack()`](/integrations/browserstack) 或 [`testmu()`](/integrations/testmu) |
| 托管设备上的 `appium:platformVersion`、`appium:language`、`appium:locale` | `browserstack()` 和 `testmu()` 上的 `osVersion`、`language` 和 `locale`；[`limrun()`](/integrations/limrun) 上的 `android.osVersion` |
| 多组能力配置、`maxInstances` | 每个平台一个测试目标、`workers`，以及每台设备对应一个工作进程的 `device` 列表 |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    {
      name: 'ios',
      engine: mobile({ platform: 'ios', device: 'iPhone 17' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'ios/build/MyApp.app',
        launchArguments: ['-e2e', 'YES'],
        permissions: { notifications: 'grant' },
      },
    },
    {
      name: 'android',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'android/app/build/outputs/apk/release/app-release.apk',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { notifications: 'grant' },
      },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

## 改写一个测试

先选择一个 XPath 选择器或显式等待经常出问题的测试。

```js title="Appium (WebdriverIO)"
describe('login', () => {
  it('signs in', async () => {
    await $('~email').setValue('ada@example.test');
    await $('~password').setValue('hunter2');
    await $('//XCUIElementTypeButton[@name="Sign in"]').click();
    await $('~welcome').waitForDisplayed({ timeout: 10000 });
    await expect($('~welcome')).toHaveText('Welcome, Ada');
  });
});
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('email').fill('ada@example.test');
  await screen.getByTestId('password').fill('hunter2');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByText('Welcome, Ada')).toBeVisible({ timeout: 10_000 });
});
```

- 应用不会自动启动，因此测试以 `app.open()` 开始。
- 操作会等待对应元素，断言会重试，因此无需显式等待。

对于经常出问题的一连串脚本点击操作，可以用一个 `agent.act` 目标替代。后续检查通过后，[回放缓存](/cache)会记录其操作，下次运行时直接回放，无需调用模型。密码应放在[配置的凭据](/authentication)中，模型永远看不到它：

```ts
import { credentials } from 'e2e';

const ada = credentials.user('ada');
await agent.act('sign in as {username}', { params: { username: ada.username, password: ada.password } });
```

## 改写选择器

| Appium | e2e |
| --- | --- |
| iOS 上的 `$('~login')`，无障碍标识符或 React Native 的 `testID` | `screen.getByTestId('login')` |
| Android 上的 `$('~Log in')`，内容描述或 React Native 的 `accessibilityLabel` | `screen.getByLabel('Log in')` |
| `$('id=com.example:id/email')`, `resourceId` | `screen.getByTestId('email')`；`com.example:id/` 前缀可省略 |
| `-ios predicate string:label == "Sign in"`, `android=new UiSelector().text("Sign in")` | `screen.getByText('Sign in')` 或 `getByLabel('Sign in')` |
| `-ios class chain`，类名（`XCUIElementTypeButton`、`android.widget.Button`） | `screen.getByRole('button', 'Sign in')` |
| `$$(selector)[2]` | `.nth(2)`；`.all()` 返回所有匹配项 |
| 查询无法表达的选择器 | `device.locator('role=text label="Total"')`，使用 agent-device 的选择器语法 |

- `getByText`、`getByLabel` 和 `getByTestId` 匹配完整字符串，区分大小写。传入 `RegExp`，或使用 `{ exact: false }` 对文本或标签进行不区分大小写的子串匹配。
- Appium 的 `$()` 返回第一个匹配项。e2e 操作要求恰好匹配一个元素，匹配到多个时会以 `LOCATOR_AMBIGUOUS` 失败。使用 `.filter()`、`.first()` 或 `.nth()` 缩小范围。
- `button`、`textbox` 和 `switch` 等角色在 iOS 和 Android 上相同，因此同一个测试可以在两个平台上运行。参阅[角色](/reference/mobile#roles)。

## 权限和深层链接

在 `app.open()` 前设置权限，因为在 iOS 上更改权限会停止正在运行的应用。每个测试都需要的权限放在 `app.permissions` 中。

```js title="Appium (WebdriverIO)"
await driver.execute('mobile: setPermission', {
  bundleId: 'com.example.app',
  access: { location: 'yes' },
});
await driver.activateApp('com.example.app');
await driver.url('myapp://orders/42');
await expect($('~order-title')).toHaveText('Order #42');
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('opens an order from a link', async ({ app, device, screen }) => {
  await device.setPermission('location', 'grant');
  await app.open();
  await device.openLink('myapp://orders/42');
  await expect(screen.getByText('Order #42')).toBeVisible();
});
```

| `driver.getLogs('logcat')`, `'syslog'`, `'crashlog'` | 在钩子中运行 `adb logcat` 或 `xcrun simctl spawn <udid> log stream` |
| `driver.queryAppState(id)` | 部分对应：`device.isAppInstalled(id)` 判断是否安装，`device.foregroundApp()` 获取前台应用。后台运行状态没有对应方法 |
| `driver.lock()`、`unlock()`、电源和音量按钮 | 通过 [`unstable_raw`](/reference/mobile#unstable_raw) 调用 `client.command.hardwareButton` |
| `driver.openNotifications()`, `mobile: pushNotification` | 从顶部边缘执行 `screen.swipe({ from, to })`；在 Node 中运行 `xcrun simctl push` |
| `driver.pushFile()`, `pullFile()`, `pullFolder()` | 在 Node 中运行 `adb push`、`adb pull` 或 `xcrun simctl addmedia`；仅限本地设备 |
| `driver.getAlertText()` | iOS 上使用 `screen.getByRole('alert').textContent()`，Android 上使用 `getByText` |
| `wdio.conf.ts` 中的钩子，例如 `onPrepare` 和 `afterTest` | `afterEach`、测试夹具或[自定义报告器](/reference/reporters#custom-reporters) |

</Accordion>
</AccordionGroup>

### 尚未支持

| Appium | 当前可用方案 |
| --- | --- |
| `appium:autoAcceptAlerts`, `appium:autoDismissAlerts` | 设置 `app.permissions`，或调用 `device.alert('accept')` |
| Webview 上下文：`getContexts()`、`switchContext()`、CSS 选择器、`execute(js)` | 使用 `getByText` 和 `getByRole` 查询 webview 的无障碍节点 |
| 移动网页：`browserName: 'Safari'` 或 `'Chrome'` | 使用[手机视口](/web#viewports)的 `web()` 测试目标，仅测试布局 |
| `appium:unlockType`, `unlockKey` | 保持设备解锁 |
| 以 XML 返回的 `driver.getPageSource()` | 不支持 XML 导出。`screen.tree()` 以文本形式返回树，通过 [`unstable_raw`](/reference/mobile#unstable_raw) 调用 `client.capture.snapshot()` 则返回节点。依赖 XML 的测试保留在 Appium 中 |
| 使用多指或多个路径点的 `performActions()` | 使用单个手势，或通过 [`unstable_raw`](/reference/mobile#unstable_raw) 调用 `client.interactions.gesture` |
| `mobile: shell`, `getPerformanceData()` | 在 Node 中使用 `device.unstable_raw.deviceId` 运行 `adb` 或 `simctl`；仅限本地设备 |
| iPhone 上的 `mobile: setSimulatedLocation`、`mobile: setAppearance`、`mobile: setPasteboard` | 在模拟器上运行这些测试，参阅[真机](/mobile#physical-devices) |
| 其他 `bstack:options` 键，例如 `gpsLocation` 和 `uploadMedia` | - |
| 本地设备上的 `appium:platformVersion`、手机的 `appium:udid` | 指定运行该版本的模拟器。在 `device` 中填写手机名称 |
| `appium:avd`, `avdArgs`, `isHeadless` | 在运行前启动模拟器，并指定其序列号 |
| 使用 Java、Python、Ruby 或 C# 编写的测试 | e2e 测试在 Node 中运行。在应用旁的 `e2e/` 文件夹中用 TypeScript 改写 |

### 不计划支持

| Appium | 替代方案 |
| --- | --- |
| XPath | 链式查询（`screen.getByTestId('row').getByText('Delete')`）或使用 `filter({ has, hasText })`。XPath 会让测试绑定到某个平台的树 |
| `-image` 选择器、`findImage` | `screen.tapAt({ x, y })`，或 `agent.act` 目标 |
| `$(selector)` 对多个匹配项中的第一个执行操作 | `.first()`，参阅[改写选择器](#rewrite-selectors) |
| WebDriverAgent 能力配置，例如 `usePrebuiltWDA` | 无需设置。agent-device 构建并签名自己的运行器 |
| 复合的 `-ios predicate string` 逻辑、`UiSelector` 标志和 `fromParent()` | 带 `filter({ has })` 或 `RegExp` 的 `getBy*` 查询 |
| Gherkin 特性文件 | 每个场景对应一个测试。步骤可以是 `agent.act` 目标 |
| 保存的会话、`test.setup` 和 `{ session }` | 每个测试单独登录，或为应用预置数据。设备没有可保存的会话，参阅[与网页端的差异](/mobile#what-differs-from-the-web) |
| 设备网格或中枢、其他设备云 | 托管提供方，或你编写的 `DeviceProvider` |
| `sauce:options` | 编写 [`DeviceProvider`](/mobile#hosted-devices) |
| Appium Inspector | `screen.debug()`，或用于编码智能体实时会话的 [`npx e2e mcp`](/mcp-server) |
| `driver.updateSettings()`, `appium:settings[...]` | [`mobile()`](/reference/mobile#engine) 上的 `snapshot`、`settle` 和 `transition` |
| `.getAttribute('clickable')`, `.isClickable()` | 对元素执行操作。操作会等待元素达到可操作状态 |
| 远程 Appium 服务器（`hostname`、`port`） | 在拥有设备的机器上运行 e2e |
| Allure | 向它提供 `.e2e/junit.xml`，或使用 `htmlReporter()` |
