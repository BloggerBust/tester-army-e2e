O e2e pode rodar ao lado do Playwright em um mesmo projeto enquanto você move
os testes um arquivo por vez. O `@e2e-dev/web` traz o próprio
`playwright-core`, em versão fixa, então a versão do seu `@playwright/test`
continua sendo escolha sua. O e2e lê `e2e.config.ts` e encontra
`tests/**/*.e2e.ts` por padrão, então mantenha os dois padrões de arquivo
separados.

## Porte a configuração

<Note>Instale o e2e e configure um modelo com o [Início rápido](/quickstart).</Note>

Uma chave do Playwright como `testDir`, `baseURL`, `use`, `webServer` ou
`projects` falha com uma mensagem que indica a chave do e2e a usar. A
[referência da configuração](/reference/config) lista todas as chaves.

| Playwright | e2e |
| --- | --- |
| `use.baseURL`, `webServer` | `app: { url, command }` no alvo, veja [Iniciar seu app](/web#starting-your-app) |
| `webServer.reuseExistingServer` | `app.command: { reuseExisting: true }`; a CI ignora essa opção |
| `projects` | `targets`, uma instância de engine em cada |
| `testDir`, `testMatch`, `testIgnore` | `tests`, globs a partir da raiz do projeto; um `!` no início exclui |
| `retries`, `workers`, `timeout` | os mesmos nomes, com [outros padrões](#defaults-that-differ); `workers` é um inteiro |
| `expect.timeout`, `use.actionTimeout`, `globalTimeout` | `assertionTimeout`, `actionTimeout`, `maxDuration`; o relógio de `maxDuration` começa com os testes, não com a inicialização do app |
| `expect.toPass` | [`toPass`](/reference/config#topass) no nível superior |
| `maxFailures`, `use.headless: false` | `--max-failures <n>` e `--headed` na CLI |
| `reporter`, `outputDir` | `reporters: ['list', 'junit', htmlReporter()]`, com `htmlReporter` de `@e2e-dev/html-reporter`; também `dot`, `line`, `json`, `markdown` e `ctrf`; `output`, padrão `.e2e` |
| `use.viewport`, `deviceScaleFactor`, `locale`, `timezoneId`, `colorScheme`, `reducedMotion`, `userAgent`, `testIdAttribute` | as mesmas chaves em `web({ ... })` |
| `use.browserName`, `httpCredentials`, `extraHTTPHeaders` | `web({ browser, basicAuth, headers })`; `basicAuth` e `headers` valem só para a origem do app, [`credentialOrigins`](/reference/web#credentialorigins) adiciona outras |
| `chromium.connectOverCDP(url)` | `web({ connect: { cdpEndpoint: () => url } })`, só chromium |
| `use.trace`, `use.video` | `trace`, `video`: um modo na configuração, em um alvo ou em um teste. `web({ screencast: { size } })` define o tamanho do vídeo |
| `use.permissions` | `app.permissions` no alvo, veja [Conceder permissões do navegador](/web#granting-browser-permissions) |
| `use.storageState` de um projeto `setup` | `test.setup` com `session.save(name)`, depois `{ session }` em um teste, veja [Autenticação](/authentication) |
| `use.storageState: { cookies }` com valores fixos | `browser.setCookies(cookies)` em uma fixture |

## Reescreva uma spec

Comece por um fluxo cujos passos mudam com frequência, como um assistente
passo a passo ou uma finalização de compra. Testes estáveis do Playwright podem
ficar onde estão.

```ts title="Playwright"
import { test, expect } from '@playwright/test';

test('checkout', async ({ page }) => {
  await page.goto('/cart');
  await page.getByRole('button', { name: 'Checkout' }).click();
  await page.getByLabel('Card number').fill('4242424242424242');
  await page.getByLabel('Expiry').fill('12/30');
  await page.getByLabel('CVC').fill('123');
  await page.getByRole('button', { name: 'Pay' }).click();
  await expect(page.getByRole('heading')).toHaveText('Order confirmed');
});
```

```ts title="e2e"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('checkout', async ({ app, agent, screen }) => {
  await app.open('/cart');
  await agent.act('pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123');
  await expect(screen.getByRole('heading')).toHaveText('Order confirmed');
});
```

O agente faz os passos da finalização de compra e se adapta quando o formulário
muda. Um teste também pode continuar totalmente determinístico, com uma linha
`screen.getBy*` para cada linha `page.getBy*`.

## Mapeie cada API

Toda linha funciona hoje. Para uma API que não está aqui, confira
[O que o e2e ainda não tem](#what-e2e-doesnt-have-yet). Chamadas em `browser`
só rodam em um navegador, então um teste que faz essas chamadas declara
`platforms: ['web']` e os outros alvos pulam esse teste.

## Porte os page objects

Um page object recebe `screen` para consultas e ações, e `browser` para
teclado, mouse, seletores CSS e `evaluate`. Forneça-o como uma fixture:

```ts title="tests/page-models/account-page.ts"
import type { Locator, Screen } from 'e2e';
import type { Browser } from '@e2e-dev/web';

export class AccountPage {
  readonly accountName: Locator;

  constructor(
    readonly screen: Screen,
    readonly browser: Browser,
  ) {
    this.accountName = screen.getByTestId('account-name');
  }

  async filterByNote(note: string) {
    await this.screen.getByRole('button', 'Filter').click();
    await this.screen.getByRole('button', 'Note').click();
    await this.browser.keyboard.type(note);
  }
}
```

```ts title="tests/fixtures.ts"
import { test as base } from '@e2e-dev/web';
import { AccountPage } from './page-models/account-page.ts';

export const test = base.extend<{ accountPage: AccountPage }>({
  accountPage: async ({ screen, browser }, use) => {
    await use(new AccountPage(screen, browser));
  },
});
```

Uma fixture que nomeia `browser` faz todo teste que a usa rodar só na web, veja
[Mantenha-o portável](/page-object-model#keep-it-portable). Tire `newPage()` e
`page.close()` dos hooks: toda tentativa começa em um contexto novo.

## O que o e2e ainda não tem

“Planejado” está no roadmap. “Ainda não” fica sem data. “Não planejado” foi
deixado de fora de propósito. Use a alternativa ou mantenha o teste no
Playwright.

### Planejado

<Accordion title="Localizadores e ações">

| Playwright | Use hoje |
| --- | --- |

<Accordion title="Asserções">

| Playwright | Use hoje |
| --- | --- |
| `{ fullPage, clip }`, `snapshotPathTemplate`, `ignoreSnapshots` | O viewport ou um localizador em `toHaveScreenshot`; uma tag e `--exclude-tag` para pular testes visuais |

| `expect.extend()` | Uma função auxiliar assíncrona que chama `expect` |

<Accordion title="Navegação, rede e navegador">

| Playwright | Use hoje |

| `devices['iPhone 15']`, `isMobile`, `hasTouch` | `web({ viewport, userAgent, deviceScaleFactor })`; um alvo mobile para toque real |

| `waitForResponse(predicate)`, `waitForRequest()`, `page.on('request')`, `response.ok()` | `browser.waitForResponse(pattern)`, ou `{ method, url }` para filtrar pelo método da requisição, depois verifique a resposta no teste, `status` para `ok()`. ## O que é diferente de propósito

- Uma string corresponde ao texto inteiro, diferenciando maiúsculas de
  minúsculas. O nome do `getByRole`, o `getByLabel`, o `getByPlaceholder` e o
  `getByText` do Playwright correspondem a uma substring, sem diferenciar
  maiúsculas de minúsculas. Passe `{ exact: false }` ou uma `RegExp` para um
  trecho. Veja [consultas](/reference/screen#queries).

  ```ts
  // <button>Save changes</button>, <label>Email address <input></label>
  screen.getByRole('button', 'Save');                  // no match
  screen.getByRole('button', { name: 'Save', exact: false });    // matches
  screen.getByRole('button', 'save changes');          // no match, case differs
  screen.getByLabel('Email');                                    // no match
  ```
- Leituras de texto retornam o texto renderizado. `textContent()`, `toHaveText`
  e `toContainText` leem o que `innerText` retorna, então o texto oculto fica
  de fora e `text-transform` se aplica. Veja [leituras de localizador](/reference/screen#locator-reads).
  `toBeEmpty`, por outro lado, mantém a regra do Playwright, então um nó com
  texto oculto não está vazio.
- `toHaveRole` usa o vocabulário de `getByRole`, então `paragraph`, `generic`
  e os outros papéis que esse vocabulário deixa de fora são erros de tipo, e
  `img` é lido como `image`. O matcher compara o papel que a árvore lê, onde um
  editor `contenteditable` é um `textbox`.
- Um localizador é estrito. Uma ação, uma leitura ou um matcher positivo sobre
  várias correspondências resulta em `LOCATOR_AMBIGUOUS`, enquanto
  `page.click(selector)` e `isVisible()` do Playwright pegam a primeira.
  Restrinja com `filter` ou `first()`.
- `.not.toBeChecked()` passa em um botão ou em um título. Consulte o controle
  pelo papel dele, para que a asserção falhe quando o controle mudar de tipo.
- Se uma leitura de `expect.poll` lança um erro, a leitura é tentada novamente.
- Para `toPass`, você vê no relatório só os passos de dentro de cada repetição do bloco.
- Sessões duram uma execução. `test.setup` salva o estado com um nome e
  `{ session }` restaura esse estado. O arquivo é criptografado e apagado na
  limpeza, então não existe um `.auth/user.json` para reutilizar.
- Os testes não recebem um `Page` bruto, porque nada feito nele é registrado,
  ocultado ou mascarado. `surfaceOf(engine)` serve para
  [executores personalizados](/executors#driving-the-page-yourself), não para código de teste.

## Padrões diferentes

| Configuração | Playwright | e2e |
| --- | --- | --- |
| Tempo limite do teste | 30 s | 120 s, `timeout` |
| Tempo limite de ação | nenhum | 30 s, `actionTimeout` |
| Tempo limite do expect | 5 s | 5 s, `assertionTimeout` |
| Tempo limite de navegação | nenhum | 120 s, o orçamento do teste |
| Novas tentativas | 0 | 1 na CI, 0 localmente |
| Workers | metade dos núcleos de CPU | 1 na CI, metade dos núcleos de CPU localmente |
| Trace | `off` (`on-first-retry` na configuração gerada) | `retain-on-failure` |
