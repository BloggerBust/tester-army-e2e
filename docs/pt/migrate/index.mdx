Um guia de migração mapeia a configuração, a API e os comandos de um runner de
testes para o e2e. Ele também lista o que o e2e ainda não tem: o que está
planejado, o que está sem data e o que o e2e deixa de fora de propósito, com
uma alternativa quando existe uma. Um teste sem alternativa fica no runner
antigo. Mantenha a suíte antiga instalada enquanto você move um teste por
vez, para que as duas suítes continuem verdes.

## Mova um teste por vez

<Note>Instale o e2e primeiro com o [Início rápido](/quickstart). Só os passos do agente precisam de um modelo.</Note>

Os testes do e2e rodam no Node, em TypeScript por padrão. Para testes em
[JavaScript](/reference/config#javascript), defina `tests` para incluí-los.
Para uma suíte em Java, Python ou nativa, instale o e2e em uma pasta `e2e/`
com um `package.json` próprio.

Cada guia segue os mesmos passos:

1. Porte a configuração. A URL base, o comando do app e os dispositivos do
   runner antigo viram um alvo em `e2e.config.ts`.
2. Reescreva um teste como um arquivo `.e2e.ts` em `tests/`. Mantenha
   separados os padrões de arquivo dos dois runners, para que nenhum deles
   rode os testes do outro.
3. Rode o novo teste com `npx e2e run <file>` até ele passar.
4. Apague o teste antigo quando confiar no novo.

## Deixe um agente migrar a suíte

Para mover um teste com um agente de código, copie o prompt do agente no topo
do guia do seu runner. Para uma migração ao longo de várias sessões, use a
[skill `migrate-to-e2e`](/coding-agents#migrate-an-existing-suite). Ela
registra o progresso em um arquivo `MIGRATION.md` e mantém a suíte antiga
rodando.

## Migre de um runner sem guia

O WebdriverIO para web não tem guia. Mapeie as chamadas de WebDriver do
WebdriverIO com o guia do [Selenium](/migrate/selenium). O mapeamento é
parcial: nenhum guia cobre a API do próprio WebdriverIO. Para o WebdriverIO
com Appium em um app mobile, veja [Migrar do Appium](/migrate/appium).
