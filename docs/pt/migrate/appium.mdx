O e2e substitui o servidor do Appium, os drivers dele e a biblioteca cliente
por um único pacote Node. `@e2e-dev/mobile` controla simuladores iOS,
emuladores Android e aparelhos conectados pelo
[agent-device](https://github.com/callstack/agent-device), que vem
incluído. As capabilities viram um alvo em `e2e.config.ts`, e os comandos de
`driver` viram as fixtures `app` e `device`. O build do seu app e os ids de
acessibilidade do app continuam como estão.

Os exemplos usam o WebdriverIO. Um cliente Java ou Python é mapeado da mesma
forma.

## Porte as capabilities

<Note>Configure um alvo com o [guia mobile](/mobile) e um modelo com o [Início rápido](/quickstart). Só os passos do agente precisam de um modelo.</Note>

| Appium | e2e |
| --- | --- |
| `platformName`, `appium:automationName` | `mobile({ platform: 'ios' })` ou `'android'` |
| `appium:deviceName`, `appium:udid` | `mobile({ device: 'iPhone 17' })`: um nome, o UDID de um simulador ou um serial `emulator-5554`. Um aparelho é identificado pelo nome |
| `appium:app` | `app: { appPath }`. Instale o build você mesmo, veja [Aponte para o seu app](/mobile#point-at-your-app) |
| `appium:bundleId`, `appium:appPackage` | `app: { bundleId }`, o app que `app.open()` inicia |
| `appium:processArguments`, `appium:optionalIntentArguments` | `app.launchArguments`, uma lista de strings ou um objeto que mapeia o nome de cada argumento para o valor dele |
| `appium:permissions` | `app.permissions: { camera: 'grant' }`. Cada nome de [`DevicePermission`](/reference/mobile#device-fixture) aceita `grant`, `deny` ou `reset` |
| `appium:autoGrantPermissions` (Android) | `app.permissions: 'all'`, que concede todas as permissões de tempo de execução que o app declara |
| `appium:noReset` | `true` é o padrão, então nada apaga os dados do app. Para `false`, chame `app.clearState()` no início do teste |
| `appium:fullReset` | `device.installApp(path, { reinstall: true })` |
| `appium:newCommandTimeout`, tempos limite do WebDriverAgent | Não é necessário. As ações usam `actionTimeout`, as asserções `assertionTimeout` e os testes `timeout` |
| `bstack:options`, `lt:options` | Um provedor de dispositivos: [`browserstack()`](/integrations/browserstack) ou [`testmu()`](/integrations/testmu) |
| `appium:platformVersion`, `appium:language`, `appium:locale` em um dispositivo hospedado | `osVersion`, `language` e `locale` em `browserstack()` e `testmu()`; `android.osVersion` em [`limrun()`](/integrations/limrun) |
| Várias capabilities, `maxInstances` | Um alvo por plataforma, `workers` e uma lista `device` com um worker por dispositivo |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    {
      name: 'ios',
      engine: mobile({ platform: 'ios', device: 'iPhone 17' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'ios/build/MyApp.app',
        launchArguments: ['-e2e', 'YES'],
        permissions: { notifications: 'grant' },
      },
    },
    {
      name: 'android',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'android/app/build/outputs/apk/release/app-release.apk',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { notifications: 'grant' },
      },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

## Reescreva um teste

Comece por um teste cujos seletores XPath ou esperas explícitas quebram com
frequência.

```js title="Appium (WebdriverIO)"
describe('login', () => {
  it('signs in', async () => {
    await $('~email').setValue('ada@example.test');
    await $('~password').setValue('hunter2');
    await $('//XCUIElementTypeButton[@name="Sign in"]').click();
    await $('~welcome').waitForDisplayed({ timeout: 10000 });
    await expect($('~welcome')).toHaveText('Welcome, Ada');
  });
});
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('email').fill('ada@example.test');
  await screen.getByTestId('password').fill('hunter2');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByText('Welcome, Ada')).toBeVisible({ timeout: 10_000 });
});
```

- Nada é iniciado sozinho, então o teste começa com `app.open()`.
- As ações esperam pelo elemento delas e as asserções tentam novamente, então
  a espera explícita deixa de ser necessária.

Onde uma sequência de toques roteirizados quebra com frequência, um único
objetivo `agent.act` pode substituí-la. O [cache de replay](/cache) grava
as ações do objetivo assim que uma verificação posterior passa, e a próxima
execução as reproduz sem chamar o modelo. Uma senha fica nas
[credenciais configuradas](/authentication), que o modelo nunca vê:

```ts
import { credentials } from 'e2e';

const ada = credentials.user('ada');
await agent.act('sign in as {username}', { params: { username: ada.username, password: ada.password } });
```

## Reescreva os seletores

| Appium | e2e |
| --- | --- |
| `$('~login')` no iOS, um accessibility identifier ou o `testID` do React Native | `screen.getByTestId('login')` |
| `$('~Log in')` no Android, uma content description ou o `accessibilityLabel` do React Native | `screen.getByLabel('Log in')` |
| `$('id=com.example:id/email')`, `resourceId` | `screen.getByTestId('email')`; o prefixo `com.example:id/` é opcional |
| `-ios predicate string:label == "Sign in"`, `android=new UiSelector().text("Sign in")` | `screen.getByText('Sign in')` ou `getByLabel('Sign in')` |
| `-ios class chain`, nomes de classe (`XCUIElementTypeButton`, `android.widget.Button`) | `screen.getByRole('button', 'Sign in')` |
| `$$(selector)[2]` | `.nth(2)`; `.all()` retorna todas as correspondências |
| Um seletor que as consultas não conseguem expressar | `device.locator('role=text label="Total"')`, a sintaxe de seletores do agent-device |

- `getByText`, `getByLabel` e `getByTestId` correspondem à string inteira e
  diferenciam maiúsculas de minúsculas. Passe uma `RegExp`, ou `{ exact: false }`
  para um trecho do texto ou do rótulo sem diferenciar maiúsculas de
  minúsculas.
- O `$()` do Appium retorna a primeira correspondência. Uma ação do e2e
  precisa de exatamente uma e falha com `LOCATOR_AMBIGUOUS` quando há várias.
  Restrinja o localizador com `.filter()`, `.first()` ou `.nth()`.
- Papéis como `button`, `textbox` e `switch` são os mesmos no iOS e no
  Android, então um único teste roda nas duas plataformas. Veja
  [Papéis](/reference/mobile#roles).

## Permissões e deep links

Defina uma permissão antes de `app.open()`, já que no iOS uma mudança encerra
um app em execução. As permissões de que todo teste precisa ficam em
`app.permissions`.

```js title="Appium (WebdriverIO)"
await driver.execute('mobile: setPermission', {
  bundleId: 'com.example.app',
  access: { location: 'yes' },
});
await driver.activateApp('com.example.app');
await driver.url('myapp://orders/42');
await expect($('~order-title')).toHaveText('Order #42');
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('opens an order from a link', async ({ app, device, screen }) => {
  await device.setPermission('location', 'grant');
  await app.open();
  await device.openLink('myapp://orders/42');
  await expect(screen.getByText('Order #42')).toBeVisible();
});
```

## Rode na CI

Sem servidor para iniciar, um job do e2e instala o build e roda a suíte. Cada
plataforma precisa do próprio job, veja [Jobs mobile](/ci#mobile-jobs).

```bash pnpm

pnpm exec e2e run --target ios --reporter list,junit
```


## O que o e2e ainda não tem

As linhas de “Planejado” estão no roadmap, e as de “Ainda não” ficam sem
data. As de “Não planejado” foram deixadas de fora de propósito. Uma chamada
pelo [`unstable_raw`](/reference/mobile#unstable_raw) não é um passo, então
fica fora do relatório e da ocultação de segredos.

| Appium | Use hoje |
| --- | --- |
| `appium:autoAcceptAlerts`, `appium:autoDismissAlerts` | Defina `app.permissions` ou chame `device.alert('accept')` |

| `performActions()` com vários dedos ou pontos intermediários | Gestos simples, ou `client.interactions.gesture` pelo [`unstable_raw`](/reference/mobile#unstable_raw) |
| `mobile: shell`, `getPerformanceData()` | Rode `adb` ou `simctl` a partir do Node com `device.unstable_raw.deviceId`; somente dispositivos locais |
| `mobile: setSimulatedLocation`, `mobile: setAppearance`, `mobile: setPasteboard` em um iPhone | Rode esses testes em um simulador, veja [Dispositivos físicos](/mobile#physical-devices) |
| Outras chaves de `bstack:options`, como `gpsLocation` e `uploadMedia` | - |
| `appium:platformVersion` em um dispositivo local, o `appium:udid` de um aparelho | Nomeie um simulador ou emulador que rode a versão. Coloque o nome do aparelho em `device` |
| `appium:avd`, `avdArgs`, `isHeadless` | Faça o boot do emulador antes da execução e informe o serial dele |
| Testes em Java, Python, Ruby ou C# | Os testes do e2e rodam no Node. Reescreva-os em TypeScript em uma pasta `e2e/` ao lado do app |

### Não planejado

| Appium | Use em vez disso |
| --- | --- |
| XPath | Encadeie consultas (`screen.getByTestId('row').getByText('Delete')`) ou use `filter({ has, hasText })`. O XPath prende um teste à árvore de uma única plataforma |
| Seletores `-image`, `findImage` | `screen.tapAt({ x, y })`, ou um objetivo `agent.act` |
| `$(selector)` agindo sobre a primeira de várias correspondências | `.first()`, veja [Reescreva os seletores](#rewrite-selectors) |
| Capabilities do WebDriverAgent como `usePrebuiltWDA` | Nada a definir. O agent-device faz o build do próprio runner e o assina |
| Lógica composta de `-ios predicate string`, flags de `UiSelector` e `fromParent()` | Uma consulta `getBy*` com `filter({ has })` ou uma `RegExp` |
| Arquivos de feature do Gherkin | Um teste por cenário. Um passo pode ser um objetivo `agent.act` |
| Sessões salvas, `test.setup` e `{ session }` | Faça login em cada teste ou pré-carregue dados no app. Um dispositivo não tem sessão para salvar, veja [O que muda em relação à web](/mobile#what-differs-from-the-web) |
| Um grid ou hub de dispositivos, outras nuvens de dispositivos | Um provedor hospedado, ou um `DeviceProvider` que você escreve |
| `sauce:options` | Escreva um [`DeviceProvider`](/mobile#hosted-devices) |
| Appium Inspector | `screen.debug()`, ou [`npx e2e mcp`](/mcp-server) para a sessão ao vivo de um agente de código |
| `driver.updateSettings()`, `appium:settings[...]` | `snapshot`, `settle` e `transition` em [`mobile()`](/reference/mobile#engine) |
| `.getAttribute('clickable')`, `.isClickable()` | Aja sobre o elemento. A ação espera até que o elemento possa ser acionado |
| Um servidor remoto do Appium (`hostname`, `port`) | Rode o e2e na máquina que tem os dispositivos |
| Allure | Alimente o Allure com `.e2e/junit.xml`, ou use `htmlReporter()` |
