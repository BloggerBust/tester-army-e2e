O e2e substitui as cadeias de comandos do Cypress por testes assíncronos em
TypeScript que rodam no Node. As duas suítes podem ficar no projeto enquanto
você move uma spec por vez.

## Porte a configuração

<Note>Instale o e2e e configure um modelo com o [Início rápido](/quickstart). O exemplo abaixo usa uma chamada do agente.</Note>

| Cypress | e2e |
| --- | --- |
| `baseUrl`, `start-server-and-test` | `app: { url, command }` no alvo, veja [Iniciar seu app](/web#starting-your-app) |
| Seletores `data-cy` | `web({ testIdAttribute: 'data-cy' })`, depois `screen.getByTestId` |
| `viewportWidth`, `viewportHeight`, `cy.visit(url, { auth, headers })` | `web({ viewport, basicAuth, headers })` |
| `retries: { runMode: 2, openMode: 0 }` | `retries: process.env.CI ? 2 : 0`, somente um número |
| `env`, `Cypress.env()`, `cypress.env.json` | `process.env`; os valores de login vão em `credentials` e `secrets`, veja [Autenticação](/authentication) |
| `cypress run --browser firefox` | Um alvo com `web({ browser: 'firefox' })`, rodado com `--target <name>` |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{
    engine: web({ testIdAttribute: 'data-cy' }),
    app: { url: 'http://localhost:3000' },
  }],
} satisfies E2EConfig;
```

## Reescreva uma spec

```js title="Cypress"
describe('todos', () => {
  it('completes one', () => {
    cy.visit('/todos');
    cy.get('[data-cy=new-todo]').type('Buy milk{enter}');
    cy.get('[data-cy=new-todo]').type('Walk the dog{enter}');
    cy.contains('li', 'Buy milk').find('[data-cy=toggle]').click();
    cy.get('[data-cy=todo]').should('have.length', 2);
    cy.contains('1 item left').should('be.visible');
  });
});
```

```ts title="e2e"
import { describe, test } from '@e2e-dev/web';
import { expect } from 'e2e';

describe('todos', () => {
  test('completes one', async ({ app, agent, screen }) => {
    await app.open('/todos');
    await agent.act('add todos "Buy milk" and "Walk the dog"');
    await expect(screen.getByTestId('todo')).toHaveCount(2);
    await agent.act('complete "Buy milk"');
    await expect(screen.getByText('1 item left')).toBeVisible();
  });
});
```

## Mapeie cada comando

| Cypress | e2e |
| --- | --- |
| `cy.visit(path)`, `cy.reload()`, `cy.viewport(w, h)`, `cy.setCookie()` | `app.open(path)`, `browser.reload()`, `browser.setViewport({ width, height })`, `browser.setCookies()` |
| `cy.get('[data-cy=x]')`, `.find('[data-cy=x]')` | `screen.getByTestId('x')`, `row.getByTestId('x')` |
| `cy.get('css')` | `browser.locator('css')`, somente na web; prefira um papel ou um rótulo |
| `cy.contains('text')`, `cy.contains('li', 'text')` | `screen.getByText('text', { exact: false })`, `screen.getByRole('listitem').filter({ hasText: 'text' })` |
| `.click()`, `.dblclick()`, `.clear()`, `.check()`, `.uncheck()`, `.focus()`, `.blur()`, `.first()`, `.last()`, `.scrollIntoView()` | Os mesmos |
| `.rightclick()`, `.eq(n)`, `.selectFile(path)` | `.secondaryTap()`, `.nth(n)`, `.setInputFiles(path)` |
| `.type('text')`, `.type('{enter}')`, `.clear().type('text')` | `.pressSequentially('text')` acrescenta o texto com eventos de tecla, `.press('Enter')`, `.fill('text')` |
| `.select('Pro')` | `.selectOption('Pro')` corresponde ao rótulo; um valor precisa de `{ value: 'pro' }`, um índice de `{ index: 1 }` |
| `.should('be.visible')`, `be.checked`, `be.disabled`, `be.focused`, `exist` | `await expect(locator).toBeVisible()`, `toBeChecked()`, `toBeDisabled()`, `toBeFocused()`, `toBeAttached()` |
| `.should($el => ...)` | Use [`expect(fn).toPass()`](/reference/expect#retrying-a-block) para várias asserções. Use [`expect.poll`](/reference/expect#polling-a-value) para um único valor que muda |
| `have.text`, `contain`, `have.value`, `have.attr`, `have.length`, `not.exist` | `toHaveText`, `toContainText`, `toHaveValue`, `toHaveAttribute`, `toHaveCount(n)`, `toHaveCount(0)` |
| `cy.url().should('include', p)`, `cy.title()` | `expect(browser).toHaveURL(/p/)`, `expect(browser).toHaveTitle(t)` |
| `cy.intercept('/api/users', body)` | `browser.route('**/api/users', route => route.fulfill({ json: body }))`, um glob de URL resolvido em relação à URL do app |
| `cy.intercept('POST', '/api/users', body)` | `browser.route({ method: 'POST', url: '**/api/users' }, route => route.fulfill({ json: body }))` |
| `cy.on('window:confirm')`, `cy.on('window:alert')` | `await browser.onDialog('accept')` antes da ação, `'dismiss'` para cancelar |
| `cy.session` | `test.setup` e `{ session }` |
| `cy.request(method, url, body)` | `request.fetch(url, { method, json: body })`, ou `{ body }` para uma string. `cy.request` falha com um status fora de 2xx e 3xx e `request` não, então verifique `response.status`. Veja [`request`](/reference/request) |
| `cy.task`, `cy.exec`, `cy.fixture` | Código Node: `fs`, o cliente do seu banco de dados, `import data from './fixture.json'` |
| `Cypress.Commands.add` | Uma função, ou uma fixture de `test.extend` |

## O que o e2e ainda não tem

As lacunas em “Planejado” estão no roadmap, e as lacunas em “Ainda não” ficam sem data. As lacunas em “Não planejado” foram deixadas de fora de propósito.

### Planejado

| Cypress | Use hoje |
| --- | --- |
| `.find('css')`, `.filter('css')`, `.not('css')` | Encadeie uma consulta `getBy*` ou escreva um único seletor: `browser.locator('li.active >> .title')` |
| `.invoke()`, `.its()`, `.then($el => ...)` | `getAttribute()`, `textContent()`, `inputValue()`, senão `browser.evaluate`; envolva em `expect.poll` para tentar novamente |
| `have.class`, `have.css`, `have.prop`, `be.empty` | `expect(browser).toHaveClass(locator, /regexp/)`, `expect(locator).toBeEmpty()` para um campo vazio ou um nó sem texto (o `be.empty` do Cypress significa nenhum nó filho); senão `expect.poll(() => browser.evaluate(...))` |
| `.trigger()`, `cy.scrollTo()` | `hover()`, `dragTo()`, `scrollIntoView()`; para outros eventos sintéticos, use `browser.evaluate` |
| `cy.intercept({ headers })` e outros matchers de cabeçalho | Verifique `route.request.headers` no handler, senão chame `route.fallback()` |
| `cy.wait('@alias')`, `.its('request.body')`, `@alias.all` | Inicie `browser.waitForResponse(pattern)` antes da ação; leia a requisição em um handler de `browser.route` |
| `Cypress.on('uncaught:exception')` | Um erro do app não faz um teste falhar. Para falhar com um erro, colete `window.onerror` em `browser.addInitScript` e depois verifique que a lista está vazia com `browser.evaluate` |
| `--browser chrome`, `edge`, `electron`, `before:browser:launch` | `web({ browser: 'chromium' })`, ou conecte-se ao seu próprio Chrome com `web({ connect: { cdpEndpoint } })` |
| `cypress open`, snapshots de viagem no tempo | `npx e2e run --headed --watch`, ou `--step`; a [página de trace](/debugging#traces) mostra cada passo depois da execução |
| `before()` e `after()` que controlam o app | Preparação pela UI em `beforeEach`, limpeza em `afterEach`; login em um `test.setup` de nível superior que salva uma sessão |
| `cy.clock()`, `cy.tick()` | Um script de fake timers carregado com `browser.addInitScript({ path })` e controlado por `browser.evaluate` |
| `cy.request()` com os cookies do navegador | Envie `browser.cookies(url)` no cabeçalho `cookie` de uma chamada a `request`, veja [Requisições autenticadas](/api-testing#signed-in-requests) |

### Ainda não

| Cypress | Use hoje |
| --- | --- |
| `supportFile`, `blockHosts` | Um `test` compartilhado de `test.extend` que todo arquivo importa; bloqueie os hosts nele com `browser.route` |
| `cypress run --record --parallel`, Cypress Cloud | `--shard` em cada job da CI, os reporters `junit` e `github()`, `.e2e` enviado como artefato |
| `cy.visit()` falhando em uma página 4xx ou 5xx | `app.open` ignora o status. Faça asserções sobre o conteúdo da página |
| `cy.stub()`, `cy.spy()`, `cy.clearLocalStorage()` | Envolva a função em `browser.addInitScript`; leia as chamadas ou limpe o armazenamento com `browser.evaluate` |

### Não planejado

| Cypress | Use em vez disso |
| --- | --- |
| `cy.wait(ms)` | Uma asserção de localizador sobre o estado pelo qual o teste espera |
| `it`, `context`, `specify`, `xit` | `test`, `describe`, `test.skip` |
| chai `expect(x).to...`, `assert.*` | `toEqual`, `toContain`, `toMatchObject` em `expect(value)`, ou importe o `chai` você mesmo |
| `cy.window()`, `cy.document()`, `onBeforeLoad(win)` | `browser.evaluate` e `browser.addInitScript` com valores JSON. Os testes rodam no Node, não na página |
| Reporters do Mocha, `reporterOptions` | `list`, `dot`, `line`, `json`, `junit`, `markdown`, `ctrf`, `htmlReporter()`, `github()` ou seu próprio [reporter](/reference/reporters) |
| Arquivos `.feature` do Cucumber, `file:preprocessor` | Reescreva as features como testes. O TypeScript não precisa de pré-processador |
| Testes de componente | Mantenha-os no Cypress. O e2e testa um app em execução |
| `.parent()`, `.closest()`, `.siblings()`, `.next()` | Localize o ancestral e restrinja-o: `card.filter({ has: child })` |
| `{ force: true }` | Aja sobre o rótulo visível, ou use `tap({ position })`, que pula as verificações de acionabilidade |

## O que é diferente de propósito

- Não existe cadeia de comandos. Use await em cada chamada e guarde o localizador ou o valor em uma variável, onde o Cypress usa `.as()`, `.within()` ou `.then()`.
- [Localizadores](/reference/screen) são estritos. Uma ação ou uma asserção de nó único sobre várias correspondências falha com `LOCATOR_AMBIGUOUS`. Restrinja com `.filter()`, `.first()` ou `.nth()`, ou percorra `await locator.all()` em um loop.
- Uma string em uma consulta corresponde ao texto inteiro. `{ exact: false }` corresponde a um trecho, sem diferenciar maiúsculas de minúsculas. `cy.contains` diferencia maiúsculas de minúsculas e pega a primeira correspondência, então passe uma RegExp ou adicione `.first()`.
- Os matchers de texto comparam o texto renderizado. O `text-transform` do CSS se aplica e os filhos ocultos ficam de fora, veja [leituras de localizador](/reference/screen#locator-reads).
- Os diálogos não são aceitos automaticamente. Um `alert` ou `confirm` sem handler faz o próximo passo falhar, enquanto o Cypress o aceita.

## Padrões diferentes

| Configuração | Cypress | e2e |
| --- | --- | --- |
| Viewport | 1000 por 660 | 1280 por 720 |
| Tempos limite de ação e de asserção | `defaultCommandTimeout`, 4 s | `actionTimeout` 30 s, `assertionTimeout` 5 s |
| Novas tentativas na CI | `0` | `1` |
