O e2e substitui os fluxos YAML do Maestro por testes em TypeScript. Cada
comando vira uma chamada com await, geralmente em um localizador, ou um
objetivo do agente cobre vários comandos. Os dois runners podem usar o mesmo
simulador ou emulador enquanto você move um fluxo por vez.

## Porte a configuração

<Note>Configure um alvo com o [guia mobile](/mobile) e um modelo com o [Início rápido](/quickstart).</Note>

| Maestro | e2e |
| --- | --- |
| `appId` no topo de cada fluxo | `app: { bundleId: 'com.example.app' }` no alvo, o app que `app.open()` inicia |
| um `appId` diferente por fluxo, ou um segundo no meio do fluxo | `device.openApp(id)` no teste, ou uma configuração por app |
| `--platform`, `--device` | `mobile({ platform: 'ios', device: 'iPhone 17' })`, um alvo por plataforma; uma lista em `device` é um pool. Para uma execução, `e2e run --target ios --device 'iPhone 17'` |
| `.maestro/config.yaml` `flows`, `'!helper.yaml'` | `tests: ['tests/**/*.e2e.ts', '!tests/helpers/**']` |
| `tags`, `--include-tags`, `--exclude-tags` | `{ tags: [...] }` em um teste ou grupo; `--tag`, `--exclude-tag` na CLI |
| `env` e `${VAR}` | constantes do módulo e `params` em um objetivo: `agent.act('sign in as {email}', { params: { email } })` |
| variáveis `MAESTRO_*` | `process.env` na configuração; senhas e tokens vão em `credentials` ou `secrets`, veja [Autenticação](/authentication) |
| `--format junit` | `--reporter list,junit` escreve `.e2e/junit.xml` |
| `--format html` | `htmlReporter()` de `@e2e-dev/html-reporter` escreve `.e2e/report.html` |
| `--shards`, `--shard-split` | `device: [...]` mais `workers` em uma máquina; `--shard <index/total>` entre máquinas, veja [Sharding](/ci#sharding) |
| `maestro record` | `npx e2e run --video`, um MP4 do dispositivo por tentativa, ou a gravação do próprio provedor hospedado |
| `maestro test -c` | `npx e2e run --watch` |
| `maestro hierarchy` | `await screen.debug()` em um teste exibe a árvore da tela; `screen.tree()` a retorna |

## Reescreva um fluxo

Comece por um fluxo cujos passos `optional` e ramificações
`runFlow: { when }` precisem de atualização com frequência.

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

## Mapeie cada comando

Chamadas em `device` rodam só em um dispositivo, então um teste que faz essas
chamadas declara `platforms: ['ios', 'android']` e os outros alvos pulam esse
teste. Para as assinaturas dos métodos, veja [screen](/reference/screen),
[expect](/reference/expect), [test](/reference/test) e a
[engine mobile](/reference/mobile).

## Reescreva os seletores

- O Maestro lê texto e id como expressões regulares que não diferenciam
  maiúsculas de minúsculas. `getByText` e `getByTestId` correspondem à string inteira e
  diferenciam maiúsculas de minúsculas. Escreva
  `getByText(/^mute account$/i)`, ou `{ exact: false }` para um trecho do
  texto.
- O Maestro toca na primeira de várias correspondências. O e2e falha com
  `LOCATOR_AMBIGUOUS`, então adicione `.first()` quando a primeira
  correspondência for a que você quer.
- `isVisible()` substitui `optional` e `runFlow: { when }`. Ele lê a tela uma
  vez e não espera. Ele falha com várias correspondências, então adicione
  `{ visible: true }` ou `.first()` quando puder existir um gêmeo oculto.
- `below`, `above`, `leftOf` e `rightOf` não têm equivalente, veja
  [Ainda não](#not-yet). `filter({ has })` e o encadeamento não encontram nada
  em uma `View` simples do React Native no iOS, veja [Limitações conhecidas de dispositivos](/mobile#known-device-limitations).

## O que o e2e ainda não tem

“Planejado” está no roadmap, e “Ainda não” fica sem data. “Não planejado” foi
deixado de fora de propósito.

### Planejado

| Maestro | Use hoje |
| --- | --- |
| O padrão de conceder tudo, nomes como `bluetooth` e `storage` | `app.permissions: 'all'`, que no Android concede cada permissão de tempo de execução que o app declara, ou aceite o prompt com `device.alert('accept')` |
| `inputText` e `pressKey: Enter` sem campo, `eraseText: N`, `pressKey: backspace`, `tab` | `fill` ou `press` no localizador do campo; `fill` com um `inputValue()` encurtado para apagar; toque no próximo campo para o Tab |
| `addMedia` | Em um simulador iOS, `xcrun simctl addmedia` antes de `app.open()`; o Android não foi verificado. Veja “Fotos para um teste com o seletor de fotos” em [A fixture device](/mobile#the-device-fixture) |
| `label` em um comando | `-`. A chamada nomeia cada passo |
| `scrollUntilVisible: { centerElement, visibilityPercentage }` | Sem equivalente exato. Depois que a chamada resolver, leia `boundingBox()` e então `screen.swipe({ direction, momentum: 'slow' })` se o nó estiver fora do centro |
| Logs do dispositivo e relatórios de crash junto de uma falha | `adb logcat` ou `xcrun simctl spawn <udid> log stream`, coletados em uma fixture |
| `maestro hierarchy` como comando de terminal | Um teste de uma linha que chama `screen.debug()` |
| `--device-locale` | `app.launchArguments: { AppleLanguages: ['de'], AppleLocale: 'de_DE' }` no iOS, veja [Rode o app em outro idioma](/mobile#run-the-app-in-another-language); no Android, defina o idioma do dispositivo antes da execução |
| Maestro Cloud | Sua [CI](/ci) com um [provedor de dispositivos hospedados](/mobile#hosted-devices) |
| `pressKey: lock`, `power`, `volume up`, `volume down` | `client.command.hardwareButton` em [`unstable_raw`](/reference/mobile#unstable_raw): o botão liga/desliga e o volume no Android, o volume em um iPhone físico |
| `properties` do JUnit, um caminho JUnit com `--output` | Ids em tags ou no título; copie `.e2e/junit.xml` depois da execução |

### Ainda não

| Maestro | Use hoje |
| --- | --- |
| `optional: true` | `if (await locator.isVisible())` ou try/catch; o relatório não mostra aviso |
| `executionOrder` | Um `describe(..., { serial: true })` que chama cada fluxo como uma função |
| `retry: { maxRetries, commands }` | Um loop `for` com try/catch; `expect.poll` para um valor, `{ retries }` para o teste inteiro |
| Morte do processo no Android com `killApp` | `device.home()`, depois `adb shell am kill <package>`, depois `device.openApp(id)` |
| `assertDarkMode`, `assertLightMode` | Faça a asserção sobre um controle com tema, ou `toHaveScreenshot` |
| `Remote System Navigation Up`, `Down`, `Remote Button A`, `B` | `-` |

### Não planejado

| Maestro | Use em vez disso |
| --- | --- |
| Texto e id como regex, a primeira correspondência vence | Uma `RegExp` e `.first()`, veja [Reescreva os seletores](#rewrite-selectors) |
| `retryTapIfNoChange` | Faça a asserção do resultado e depois toque de novo no teste. Um segundo toque às cegas pode acionar um controle duas vezes |
| `waitToSettleTimeoutMs` | Uma asserção com o próprio `timeout` depois da ação; essa asserção é a espera |
| `toggleAirplaneMode`, `toggleDarkMode` | Defina o estado que você quer: `device.setAirplaneMode(true)`, `device.setAppearance('dark')` |
| Maestro Studio | Um agente de código conectado a [`npx e2e mcp`](/mcp-server), ou `screen.debug()` com `npx e2e run --watch` ou `--step` |
| `waitForAnimationToEnd` | `await expect(locator).toBeVisible()` sobre o que aparece no fim da animação |
| `below`, `above`, `leftOf`, `rightOf` | `getByLabel`, um test id, `filter({ has })` em um contêiner compartilhado ou um objetivo `agent.act` |

## O que é diferente de propósito

- O Maestro concede todas as permissões quando inicia o app. O e2e não
  concede nenhuma que você não nomeie, então um fluxo portado encontra prompts
  do sistema que o Maestro nunca mostrou. Defina
  [`app.permissions: 'all'`](/mobile#launch-arguments-and-permissions), ou
  nomeie cada uma com `grant`, `deny` e `reset` para `allow`, `deny` e `unset`
  do Maestro. Em um simulador iOS, `'all'` deixa de fora as notificações, que
  o simulador se recusa a definir: aceite esse prompt com
  `device.alert('accept')`.
- Chamadas por [`device.unstable_raw`](/reference/mobile#unstable_raw) não
  são passos. Elas ficam fora do relatório, do trace, do cache do agente e da ocultação.
- Um dispositivo não tem `test.setup` nem `{ session }`, veja
  [o que muda em relação à web](/mobile#what-differs-from-the-web).
