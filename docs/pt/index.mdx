O e2e é um framework de testes open source para apps web e mobile. Um teste
pode usar [localizadores](/core-concepts#locators) e
[asserções](/reference/expect#locator-matchers) exatos,
[objetivos](/core-concepts#goals) em linguagem natural que um agente cumpre,
ou os dois no mesmo teste.

<VideoCard
  id="NEawZb6Hssw"
  title="Entenda o e2e em 2 minutos"
  subtitle="Encadeie objetivos do agente com verificações por localizador, rode o mesmo teste na web, no iOS e no Android, e configure um projeto em um minuto."

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('a member upgrades to Pro', async ({ app, agent, screen }) => {
  await app.open('/settings/billing');

  await agent.act('upgrade the workspace to the Pro plan');
  await agent.assert('the invoice preview shows a prorated amount');

  await expect(screen.getByRole('status')).toContainText('Pro');
});
```

## Por que e2e

- **Menos tempo com testes.** Escreva um objetivo em vez de um script de
  seletores e esperas. Quando a UI muda, o agente se adapta, então você
  conserta menos testes.
- **Execuções baratas.** O e2e grava um passo `agent.act` quando uma
  verificação posterior passa. A próxima execução [reproduz esse passo](/cache)
  sem chamadas ao modelo e devolve o controle ao agente quando o app mudou.
  Com o agente embutido, `assert`, `waitFor` e `extract` sempre chamam o
  modelo.

## Como funciona

- **Alvos.** Cada teste roda uma vez por alvo, como o Chromium ou um
  simulador de iPhone. A [engine web](/web) controla navegadores pelo
  Playwright. A [engine mobile](/mobile) controla simuladores iOS e
  emuladores Android pelo agent-device. Você também pode
  [escrever a sua](/writing-an-engine).
- **Passos do agente.** `agent.act` cumpre um objetivo. `agent.assert`,
  `agent.waitFor` e `agent.extract` avaliam a tela. Use sua própria
  [assinatura](/subscriptions), [chave de API ou modelo local](/models).
  Testes sem passos do agente não precisam de modelo.
- **Relatórios.** O runner [oculta os segredos registrados](/security) da
  entrada do modelo. Ele registra passos, falhas e artefatos em um
  [relatório](/debugging) que você ou seu agente de código podem ler.
