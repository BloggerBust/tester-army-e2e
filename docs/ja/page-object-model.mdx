ページオブジェクトは、ひとつの画面のロケーターと操作を一か所にまとめるものです。テストでは同じ検索を繰り返し書かずに、そのメソッドを呼び出します。どのテストフレームワークでも使える設計パターンなので、Playwright や Selenium でページオブジェクトを書いたことがあれば、なじみのある形です。

e2e のページオブジェクトは、`screen` を受け取る通常の TypeScript クラスです。フィクスチャを通してテストに渡します。

## ページオブジェクトを作る

コンストラクターで `screen` を受け取り、ロケーターを作ります。ロケーターは遅延評価されるため、メソッドで使うまで要素の検索は行われません。

```ts title="tests/pages/sign-in-page.ts"
import type { Locator, Screen, Secret } from 'e2e';

export class SignInPage {
  readonly email: Locator;
  readonly password: Locator;
  readonly submit: Locator;
  readonly error: Locator;

  constructor(readonly screen: Screen) {
    this.email = screen.getByLabel('Email');
    this.password = screen.getByLabel('Password');
    this.submit = screen.getByRole('button', 'Sign in');
    this.error = screen.getByRole('alert');
  }

  async signIn(email: string, password: string | Secret) {
    await this.email.fill(email);
    await this.password.fill(password);
    await this.submit.tap();
  }
}
```

ファイル名の末尾を `.e2e.ts` にしないでください。ランナーがテストとして収集してしまいます。

## フィクスチャとして渡す

`test.extend` のフィクスチャ内でページオブジェクトを作成します。この `test` をインポートするテストは、`beforeEach` を書かずに受け取れます。

```ts title="tests/fixtures.ts"
import { test as base } from 'e2e';
import { SignInPage } from './pages/sign-in-page.ts';

export const test = base.extend<{ signInPage: SignInPage }>({
  signInPage: async ({ screen }, use) => {
    await use(new SignInPage(screen));
  },
});
```

```ts title="tests/sign-in.e2e.ts"
import { expect } from 'e2e';
import { test } from './fixtures.ts';

test('rejects a wrong password', async ({ app, signInPage }) => {
  await app.open();
  await signInPage.signIn('ada@example.test', 'not-the-password');
  await expect(signInPage.error).toHaveText('Wrong email or password');
});
```

## 複数のプラットフォームで使えるようにする

`screen` だけを使うページオブジェクトは、Web とモバイルの両方のターゲットで動きます。`browser`（キーボード、CSS セレクター、`evaluate`）や `device` が必要な場合は、そのプラットフォームだけで動きます。

フィクスチャが `browser` または `device` を指定すると、そのフィクスチャを使うすべてのテストがそれを必要とします。他のターゲットでは、実行が収集時に `COLLECTION_ERROR` で失敗します。他のターゲットで失敗させずにスキップするには、該当するテストに `platforms: ['web']` を指定します。そのフィクスチャを指定しないテストは、プラットフォームを問わず実行できます。

## エージェントのゴールを組み込む

メソッドの引数で `agent` を受け取れば、アプリの改修でよく変わる操作を、ゴールとしてメソッドにまとめられます。

```ts
async addCard(agent: Agent, name: string) {
  await agent.act('add a new card named {name}', { params: { name } });
}
```

フィクスチャ内で `agent` を参照しないでください。その `test` の全テストで、決定論的なテストも含めてモデルの設定が必要になってしまいます。

ページオブジェクトのメソッドには、フローに沿ってクリックするだけのものも多くあります。それらはひとつの [`agent.act` のゴール](/core-concepts#goals)で置き換えられます。全テストが繰り返し使い、厳密に実行する必要があるステップはメソッドとして残してください。

ログイン済みの状態でテストを始める場合、毎回 `signIn` を呼ぶ必要はありません。代わりに、セッションを一度保存します。[認証](/authentication)を参照してください。
