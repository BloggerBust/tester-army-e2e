移行ガイドでは、各テストランナーの設定、API、コマンドと e2e の対応関係を説明します。
e2e にまだない機能についても、実装予定のもの、時期が未定のもの、意図的に対象外としているものを区別し、
代替手段がある場合は紹介します。代替手段のないテストは、元のランナーに残してください。
元のスイートをインストールしたまま、テストを 1 つずつ移行し、両方のスイートが成功する状態を維持します。

## テストを 1 つずつ移行する

<Note>まず[クイックスタート](/quickstart)に従って e2e をインストールしてください。モデルが必要なのはエージェントステップだけです。</Note>

e2e のテストは Node 上で動作し、デフォルトでは TypeScript で記述します。[JavaScript](/reference/config#javascript) のテストを使う場合は、対象に一致するよう `tests` を設定してください。
Java、Python、ネイティブのスイートの場合は、専用の `package.json` を持つ `e2e/` フォルダーに e2e をインストールします。

各ガイドは同じ手順で進めます。

1. 設定を移します。元のランナーのベース URL、アプリ起動コマンド、デバイス設定を、`e2e.config.ts` のターゲットにまとめます。
2. テストを 1 つ、`tests/` 以下の `.e2e.ts` ファイルに書き換えます。
   互いのテストを実行しないよう、2 つのランナーのファイルパターンを分けてください。
3. 新しいテストが成功するまで `npx e2e run <file>` で実行します。
4. 新しいテストを信頼できるようになったら、古いテストを削除します。

## エージェントにスイートの移行を任せる

コーディングエージェントでテストを 1 つ移行する場合は、移行元ランナーのガイド冒頭にあるエージェント用プロンプトをコピーします。
複数のセッションにわたる移行には、[`migrate-to-e2e` スキル](/coding-agents#migrate-an-existing-suite)を使ってください。
このスキルは `MIGRATION.md` ファイルに進捗を記録し、元のスイートを動かしたまま移行を進めます。

## ガイドがないランナーから移行する

Web 用の WebdriverIO には専用ガイドがありません。WebDriver の呼び出しは、[Selenium](/migrate/selenium) ガイドで対応付けてください。
ただし対応は部分的であり、WebdriverIO API 自体を扱うガイドはありません。
モバイルアプリで WebdriverIO と Appium を使っている場合は、[Appium からの移行](/migrate/appium)を参照してください。
