e2e は Appium サーバー、ドライバー、クライアントライブラリを、1 つの Node パッケージに置き換えます。
`@e2e-dev/mobile` は、同梱の [agent-device](https://github.com/callstack/agent-device) を通じて
iOS シミュレーター、Android エミュレーター、接続された実機を操作します。
ケイパビリティは `e2e.config.ts` のターゲットに、`driver` コマンドは `app` と `device` フィクスチャに移します。
アプリのビルドとアクセシビリティ ID はそのまま使えます。

例では WebdriverIO を使っています。Java や Python のクライアントでも対応関係は同じです。

## ケイパビリティの移行

<Note>[モバイルガイド](/mobile)でターゲットを、[クイックスタート](/quickstart)でモデルを設定してください。モデルが必要なのはエージェントステップだけです。</Note>

| Appium | e2e |
| --- | --- |
| `platformName`, `appium:automationName` | `mobile({ platform: 'ios' })` または `'android'` |
| `appium:deviceName`, `appium:udid` | `mobile({ device: 'iPhone 17' })`。名前、シミュレーターの UDID、`emulator-5554` などのシリアル。実機は名前で指定 |
| `appium:app` | `app: { appPath }`。ビルドは自分でインストールします。[対象アプリの指定](/mobile#point-at-your-app)を参照 |
| `appium:bundleId`, `appium:appPackage` | `app: { bundleId }`。`app.open()` が起動するアプリ |
| `appium:processArguments`, `appium:optionalIntentArguments` | 文字列のリストである `app.launchArguments` |
| `appium:permissions` | `app.permissions: { camera: 'grant' }`。各 [`DevicePermission`](/reference/mobile#device-fixture) 名に `grant`、`deny`、`reset` を指定 |
| `appium:noReset` | デフォルトは `true` で、アプリのデータは消去しません。`false` に相当する動作には、テスト開始時に `app.clearState()` を呼ぶ |
| `appium:fullReset` | `device.installApp(path, { reinstall: true })` |
| `appium:newCommandTimeout`、WebDriverAgent のタイムアウト | 不要。操作には `actionTimeout`、アサーションには `assertionTimeout`、テストには `timeout` |
| `bstack:options`, `lt:options` | デバイスプロバイダーの [`browserstack()`](/integrations/browserstack) または [`testmu()`](/integrations/testmu) |
| ホスト型デバイスの `appium:platformVersion`、`appium:language`、`appium:locale` | `browserstack()` と `testmu()` の `osVersion`、`language`、`locale`。[`limrun()`](/integrations/limrun) の `android.osVersion` |
| 複数のケイパビリティ、`maxInstances` | プラットフォームごとのターゲット、`workers`、デバイスごとに 1 ワーカーを割り当てる `device` リスト |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    {
      name: 'ios',
      engine: mobile({ platform: 'ios', device: 'iPhone 17' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'ios/build/MyApp.app',
        launchArguments: ['-e2e', 'YES'],
        permissions: { notifications: 'grant' },
      },
    },
    {
      name: 'android',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'android/app/build/outputs/apk/release/app-release.apk',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { notifications: 'grant' },
      },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

## テストを 1 つ書き換える

XPath セレクターや明示的な待機が頻繁に壊れるテストから始めます。

```js title="Appium (WebdriverIO)"
describe('login', () => {
  it('signs in', async () => {
    await $('~email').setValue('ada@example.test');
    await $('~password').setValue('hunter2');
    await $('//XCUIElementTypeButton[@name="Sign in"]').click();
    await $('~welcome').waitForDisplayed({ timeout: 10000 });
    await expect($('~welcome')).toHaveText('Welcome, Ada');
  });
});
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('email').fill('ada@example.test');
  await screen.getByTestId('password').fill('hunter2');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByText('Welcome, Ada')).toBeVisible({ timeout: 10_000 });
});
```

- アプリは自動では起動しないため、テストは `app.open()` から始めます。
- 操作は対象要素を待ち、アサーションは再試行するため、明示的な待機は不要になります。

スクリプト化した一連のタップが頻繁に壊れる箇所は、1 つの `agent.act` のゴールに置き換えられます。
[リプレイキャッシュ](/cache)は後続の検証が成功した時点で操作を記録し、次回はモデルを呼ばずに再生します。
パスワードは、モデルに渡されない[認証情報の設定](/authentication)に入れます。

```ts
import { credentials } from 'e2e';

const ada = credentials.user('ada');
await agent.act('sign in as {username}', { params: { username: ada.username, password: ada.password } });
```

## セレクターの書き換え

| Appium | e2e |
| --- | --- |
| iOS の `$('~login')`、アクセシビリティ識別子、React Native の `testID` | `screen.getByTestId('login')` |
| Android の `$('~Log in')`、コンテンツの説明、React Native の `accessibilityLabel` | `screen.getByLabel('Log in')` |
| `$('id=com.example:id/email')`, `resourceId` | `screen.getByTestId('email')`。`com.example:id/` 接頭辞は省略可能 |
| `-ios predicate string:label == "Sign in"`, `android=new UiSelector().text("Sign in")` | `screen.getByText('Sign in')` または `getByLabel('Sign in')` |
| `-ios class chain`、クラス名（`XCUIElementTypeButton`、`android.widget.Button`） | `screen.getByRole('button', 'Sign in')` |
| `$$(selector)[2]` | `.nth(2)`。`.all()` はすべての一致を返します |
| クエリで表現できないセレクター | `device.locator('role=text label="Total"')`。agent-device のセレクター構文 |

- `getByText`、`getByLabel`、`getByTestId` は、大文字と小文字も含めて文字列全体に一致します。
  `RegExp` を渡すか、テキストやラベルを大文字と小文字を区別せず部分一致させるには `{ exact: false }` を指定します。
- Appium の `$()` は最初の一致を返します。e2e の操作は一致がちょうど 1 つ必要で、複数なら `LOCATOR_AMBIGUOUS` で失敗します。
  `.filter()`、`.first()`、`.nth()` で絞り込んでください。
- `button`、`textbox`、`switch` などのロールは iOS と Android で共通なので、同じテストを両方で実行できます。
  [ロール](/reference/mobile#roles)を参照してください。

## 権限とディープリンク

iOS では権限の変更によって実行中のアプリが停止するため、`app.open()` の前に権限を設定します。
すべてのテストに必要な権限は `app.permissions` に指定します。

```js title="Appium (WebdriverIO)"
await driver.execute('mobile: setPermission', {
  bundleId: 'com.example.app',
  access: { location: 'yes' },
});
await driver.activateApp('com.example.app');
await driver.url('myapp://orders/42');
await expect($('~order-title')).toHaveText('Order #42');
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('opens an order from a link', async ({ app, device, screen }) => {
  await device.setPermission('location', 'grant');
  await app.open();
  await device.openLink('myapp://orders/42');
  await expect(screen.getByText('Order #42')).toBeVisible();
});
```

## e2e にまだない機能

「実装予定」の項目はロードマップにあり、「未対応」の項目は時期が未定です。「実装予定なし」は意図的に対象外としています。
[`unstable_raw`](/reference/mobile#unstable_raw) 経由の呼び出しはステップではないため、レポートに記録されず、シークレットの秘匿も行われません。

### 実装予定

<AccordionGroup>
<Accordion title="ケイパビリティとデバイス">

| Appium | 現在使える方法 |
| --- | --- |
| `appium:autoGrantPermissions`、一覧にない Android 権限、iOS の位置情報 `always` | `app.permissions` に各権限を列挙するか、実行前に `adb shell pm grant`。iOS の位置情報 `always` はプロンプトのボタンをタップ |

| `appium:processArguments.env` | 起動引数を渡し、アプリ内で読み取る |
| ローカルデバイスの `appium:language`、`appium:locale` | iOS では `app.launchArguments: ['-AppleLanguages', '(fr)', '-AppleLocale', 'fr_FR']`。[別の言語でアプリを実行する](/mobile#run-the-app-in-another-language)を参照。Android では実行前にデバイスの言語を設定 |
| `appium:disableWindowAnimation`, `reduceMotion` | Android では [`unstable_raw`](/reference/mobile#unstable_raw) 経由の `client.settings.update` |

</Accordion>

| Appium | 現在使える方法 |
| --- | --- |
| ラベル、ID、クラス用の `.getAttribute()`、`.isSelected()`、`.getTagName()` | ラベルには `toHaveAccessibleName`、選択状態には `toBeSelected`。ID、クラス、タグ名の読み取りはありません |
| `pressKeyCode(code)`, `driver.keys('Backspace')` | `.press()` は `Enter`、`Space`、1 文字を受け付けます。`.clear()` と `.fill()` を使用 |
| `driver.getWindowRect()`, `getWindowSize()`, `mobile: deviceInfo` | 方向を指定してスワイプするか、全画面要素の `.boundingBox()` を読み取る |
| `UiScrollable` の `scrollToEnd()`、`scrollToBeginning()` | `allTextContents()` が変わらなくなるまで `locator.swipe({ direction: 'down' })` を繰り返す。先頭へは `'up'` |
| `mobile: selectPickerWheelValue`、日付・時刻ピッカー、スライダー値 | ホイールをスワイプして `.inputValue()` を読み取るか、`agent.act` のゴールを使用 |
| `mobile: pinchOpenGesture`、`mobile: pinch`、座標への `mobile: dragGesture`、`mobile: dragFromToForDuration` | [`unstable_raw`](/reference/mobile#unstable_raw) 経由の `client.interactions.pinch` または `.drag` |

### 実装予定なし

| Appium | 代わりに使う方法 |
| --- | --- |
| XPath | クエリを連結（`screen.getByTestId('row').getByText('Delete')`）するか、`filter({ has, hasText })` を使用。XPath はテストを 1 つのプラットフォームのツリーに結び付けます |
| `-image` セレクター、`findImage` | `screen.tapAt({ x, y })`、または `agent.act` のゴール |
| 複数一致の先頭を操作する `$(selector)` | `.first()`。[セレクターの書き換え](#rewrite-selectors)を参照 |

| 複合的な `-ios predicate string` の条件、`UiSelector` フラグ、`fromParent()` | `filter({ has })` または `RegExp` を使う `getBy*` クエリ |
| Gherkin の feature ファイル | シナリオごとに 1 テスト。ステップには `agent.act` のゴールを使用可能 |
| 保存済みセッション、`test.setup` と `{ session }` | テストごとにログインするか、アプリに初期データを投入。デバイスには保存するセッションがありません。[Web との違い](/mobile#what-differs-from-the-web)を参照 |
| デバイスのグリッドやハブ、その他のデバイスクラウド | ホスト型プロバイダー、または自作の `DeviceProvider` |
| `sauce:options` | [`DeviceProvider`](/mobile#hosted-devices) を実装 |
| Appium Inspector | `screen.debug()`、またはコーディングエージェントのライブセッション用の [`npx e2e mcp`](/mcp-server) |
| `driver.updateSettings()`, `appium:settings[...]` | [`mobile()`](/reference/mobile#engine) の `snapshot`、`settle`、`transition` |

| リモート Appium サーバー（`hostname`、`port`） | デバイスが接続されているマシンで e2e を実行 |
| Allure | `.e2e/junit.xml` を渡すか、`htmlReporter()` を使用 |
