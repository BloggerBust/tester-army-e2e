e2e は Maestro の YAML フローを TypeScript のテストに置き換えます。
各コマンドを、通常はロケーターに対する await 付きの呼び出しにするか、複数のコマンドを 1 つのエージェントのゴールにまとめます。
フローごとに移行する間、両ランナーは同じシミュレーターやエミュレーターを使えます。

複数のセッションにわたる移行では、[`migrate-to-e2e` スキル](/coding-agents#migrate-an-existing-suite)が移行済みの内容を進捗ファイルに記録し、各テストを廃止するまで元のスイートを動かし続けます。

## 設定の移行

<Note>[モバイルガイド](/mobile)でターゲットを、[クイックスタート](/quickstart)でモデルを設定してください。</Note>

| Maestro | e2e |
| --- | --- |
| 各フロー冒頭の `appId` | ターゲットの `app: { bundleId: 'com.example.app' }`。`app.open()` が起動するアプリ |
| フローごとに異なる `appId`、フロー途中の別のアプリ | テスト内の `device.openApp(id)`、またはアプリごとに別の設定 |
| `--platform`, `--device` | `mobile({ platform: 'ios', device: 'iPhone 17' })`。プラットフォームごとに 1 ターゲット。`device` のリストはプール。1 回の実行だけなら `e2e run --target ios --device 'iPhone 17'` |
| `.maestro/config.yaml` の `flows`、`'!helper.yaml'` | `tests: ['tests/**/*.e2e.ts', '!tests/helpers/**']` |
| `tags`, `--include-tags`, `--exclude-tags` | テストやグループの `{ tags: [...] }`。CLI の `--tag`、`--exclude-tag` |
| `env` と `${VAR}` | モジュールの定数と、ゴールの `params`: `agent.act('sign in as {email}', { params: { email } })` |
| `MAESTRO_*` 変数 | 設定内の `process.env`。パスワードとトークンは `credentials` または `secrets`。[認証](/authentication)を参照 |
| `--format junit` | `--reporter list,junit` が `.e2e/junit.xml` を出力 |
| `--format html` | `@e2e-dev/html-reporter` の `htmlReporter()` が `.e2e/report.html` を出力 |
| `--shards`, `--shard-split` | 1 台では `device: [...]` と `workers`。マシン間では `--shard <index/total>`。[シャーディング](/ci#sharding)を参照 |
| `maestro record` | `npx e2e run --video`。試行ごとにデバイスの MP4 を 1 つ、またはホスト型プロバイダー自身の録画 |
| `maestro test -c` | `npx e2e run --watch` |
| `maestro hierarchy` | テスト内の `await screen.debug()` が画面のツリーを表示。`screen.tree()` はそれを返す |

## フローを 1 つ書き換える

`optional` ステップや `runFlow: { when }` の分岐を頻繁に更新するフローから始めます。

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

## 各コマンドの対応付け

`device` の呼び出しはデバイスでのみ実行できるため、使用するテストに `platforms: ['ios', 'android']` を宣言します。
他のターゲットはそのテストをスキップします。シグネチャは
[screen](/reference/screen)、[expect](/reference/expect)、[test](/reference/test)、
[モバイルエンジン](/reference/mobile)を参照してください。

## セレクターの書き換え

- Maestro はテキストと ID を、大文字と小文字を区別しない正規表現として扱います。
  `getByText` と `getByTestId` は大文字と小文字も含めて文字列全体に一致します。
  `getByText(/^mute account$/i)` と書くか、テキストの部分一致には `{ exact: false }` を使ってください。
- Maestro は複数一致の先頭をタップします。e2e は `LOCATOR_AMBIGUOUS` で失敗するため、
  先頭の要素を意図しているなら `.first()` を追加してください。
- `isVisible()` は `optional` と `runFlow: { when }` の代わりになります。
  画面を一度だけ読み取り、待機しません。複数一致では失敗するため、同じ条件に一致する非表示の要素があり得る場合は
  `{ visible: true }` または `.first()` を追加してください。
- `below`、`above`、`leftOf`、`rightOf` に対応する機能はありません。[未対応](#not-yet)を参照してください。
  iOS では、通常の React Native `View` に対する `filter({ has })` やクエリの連結は何にも一致しません。
  [既知のデバイス制限](/mobile#known-device-limitations)を参照してください。

## e2e にまだない機能

「実装予定」はロードマップにある機能です。「未対応」は時期が未定、「実装予定なし」は意図的に対象外としている機能です。

### 実装予定

| Maestro | 現在使える方法 |
| --- | --- |
| `permissions: { all }`、すべて付与するデフォルト動作、`bluetooth` や `storage` などの名前 | `app.permissions` に権限を個別に指定するか、`device.alert('accept')` でプロンプトを許可 |
| `point: "50%,50%"`、`swipe` の割合指定の `start` と `end` | 全画面ノードの `boundingBox()` からピクセル値を計算 |
| フィールド指定なしの `inputText` と `pressKey: Enter`、`eraseText: N`、`pressKey: backspace`、`tab` | フィールドのロケーターに `fill` または `press`。削除は短くした `inputValue()` を `fill`。Tab は次のフィールドをタップ |
| `addMedia` | iOS シミュレーターでは `app.open()` の前に `xcrun simctl addmedia`。Android は未検証。[device フィクスチャ](/mobile#the-device-fixture)の「ピッカーのテスト用の写真」を参照 |
| コマンドの `label` | `-`。各ステップ名は呼び出しから付けられます |
| `scrollUntilVisible: { centerElement, visibilityPercentage }` | 完全に対応する機能はありません。完了後に `boundingBox()` を読み、ノードが中央からずれていれば `screen.swipe({ direction, momentum: 'slow' })` |
| 失敗に添付されるデバイスログやクラッシュレポート | フィクスチャで `adb logcat` または `xcrun simctl spawn <udid> log stream` を収集 |
| ターミナルコマンドとしての `maestro hierarchy` | `screen.debug()` を呼ぶ 1 行のテスト |
| `--device-locale` | iOS では `app.launchArguments: ['-AppleLanguages', '(de)', '-AppleLocale', 'de_DE']`。[別の言語でアプリを実行する](/mobile#run-the-app-in-another-language)を参照。Android は実行前にデバイスの言語を設定 |
| Maestro Cloud | [ホスト型デバイスプロバイダー](/mobile#hosted-devices)を使う自身の [CI](/ci) |
| `pressKey: lock`, `power`, `volume up`, `volume down` | [`unstable_raw`](/reference/mobile#unstable_raw) の `client.command.hardwareButton`。Android では電源と音量、iPhone 実機では音量 |
| JUnit の `properties`、`--output` による JUnit のパス | タグやタイトルに ID を含める。実行後に `.e2e/junit.xml` をコピー |

### 未対応

| Maestro | 現在使える方法 |
| --- | --- |
| `optional: true` | `if (await locator.isVisible())` または try/catch。レポートに警告は表示されません |
| `executionOrder` | 各フローを関数として呼ぶ 1 つの `describe(..., { serial: true })` |
| `retry: { maxRetries, commands }` | try/catch を含む `for` ループ。値には `expect.poll`、テスト全体には `{ retries }` |
| `killApp` による Android のプロセス終了 | `device.home()`、`adb shell am kill <package>`、`device.openApp(id)` の順 |
| `assertDarkMode`, `assertLightMode` | テーマに応じたコントロールを検証、または `toHaveScreenshot` |
| TV リモコンのキー | `-` |

### 実装予定なし

| Maestro | 代わりに使う方法 |
| --- | --- |
| 正規表現のテキスト・ID、先頭一致の採用 | `RegExp` と `.first()`。[セレクターの書き換え](#rewrite-selectors)を参照 |
| `retryTapIfNoChange` | 結果を検証し、テスト内で再度タップ。無条件の 2 回目のタップは、コントロールを二重に実行するおそれがあります |
| `waitToSettleTimeoutMs` | 操作の後に、独自の `timeout` を指定したアサーション。そのアサーションが待機を担います |
| `toggleAirplaneMode`, `toggleDarkMode` | 目的の状態を指定: `device.setAirplaneMode(true)`、`device.setAppearance('dark')` |
| Maestro Studio | [`npx e2e mcp`](/mcp-server) 経由のコーディングエージェント、または `screen.debug()` と `npx e2e run --watch` や `--step` |
| `waitForAnimationToEnd` | アニメーション終了時に現れる要素への `await expect(locator).toBeVisible()` |
| `below`, `above`, `leftOf`, `rightOf` | `getByLabel`、テスト ID、共通コンテナーの `filter({ has })`、または `agent.act` のゴール |

## 意図的な違い

- Maestro はアプリ起動時にすべての権限を付与します。e2e は指定した権限以外を付与しないため、
  移行したフローでは Maestro で表示されなかったシステムプロンプトが現れます。
  [`app.permissions`](/mobile#launch-arguments-and-permissions) に権限を個別に指定してください。
  Maestro の `allow`、`deny`、`unset` に対して、`grant`、`deny`、`reset` を使います。
- [`device.unstable_raw`](/reference/mobile#unstable_raw) 経由の呼び出しはステップではありません。
  レポート、トレース、エージェントキャッシュ、機密値の除去の対象外です。
- デバイスには `test.setup` や `{ session }` はありません。[Web との違い](/mobile#what-differs-from-the-web)を参照してください。
