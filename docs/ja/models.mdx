エージェントステップは、`e2e.config.ts` に設定したモデルを使います。デフォルトのモデルはありません。[AI SDK](https://ai-sdk.dev/providers/ai-sdk-providers) のプロバイダーを通して、ゲートウェイ、直接の API キー、ローカルサーバー、[サブスクリプション](/subscriptions)のいずれかを使います。初めてのセットアップでは、`e2e init` が設定ファイルを作成します。[クイックスタート](/quickstart#use-a-subscription-or-api-key)を参照してください。

エージェントステップのないテストにモデルは不要です。組み込みエージェントには、ツール呼び出しと画像に対応したモデルが必要です。Clef や Jev などの[デシジョンモデル](/decision-models)は、カスタムエグゼキューターを通して使います。

## ゲートウェイまたはプロバイダーを選ぶ

どのプロバイダーでも、組み込みエージェントには `ai` パッケージが必要です。

<CodeGroup>
```bash npm
npm install -D ai
```

```bash pnpm
pnpm add -D ai
```

```bash bun
bun add -d ai
```
</CodeGroup>

プロバイダーは自身のキーを環境変数から読み取ります。ゲートウェイを使うと、ひとつのキーで複数のプロバイダーにアクセスできます。切り替えるには、モデルのインポートと `model` の値を変更します。コード例が `agent` を定義している場合は、それを `agents.default` に設定してください。

<Tabs>
  <Tab title="Vercel AI Gateway">

`gateway` は `ai` パッケージに含まれます。`AI_GATEWAY_API_KEY` を設定するか、キーの代わりに [Vercel OIDC トークン](#vercel-oidc-instead-of-a-key)を使います。

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
} satisfies E2EConfig;
```
  </Tab>
  <Tab title="OpenRouter">

`@openrouter/ai-sdk-provider` をインストールし、`OPENROUTER_API_KEY` を設定します。

```ts title="Model setup"
import { openrouter } from '@openrouter/ai-sdk-provider';

const agent = { model: openrouter('openai/gpt-6-luna-fast') };
```
  </Tab>
  <Tab title="プロバイダーの API キー">

プロバイダーの AI SDK パッケージをインストールし、その API キーを設定します。OpenAI の場合は、`@ai-sdk/openai` をインストールし、`OPENAI_API_KEY` を設定します。

```ts title="Model setup"
import { openai } from '@ai-sdk/openai';

const agent = { model: openai('gpt-6-luna') };
```

他のプロバイダーでも、専用のパッケージ、モデル ID、認証情報を使う点以外は同じです。[AI SDK プロバイダー](#ai-sdk-providers)を参照してください。
  </Tab>
  <Tab title="ローカルまたはセルフホスト">

`@ai-sdk/openai-compatible` をインストールします。エンドポイントの URL と、そのエンドポイントが提供するモデル ID を設定してください。サーバーが必要とする場合は `apiKey` を追加します。Ollama のように JSON Schema のレスポンス形式を受け付けるサーバーでは、`supportsStructuredOutputs: true` を設定します。設定しない場合、AI SDK は `responseFormat` の警告を出してスキーマを省略するため、エージェントステップのモデル呼び出しが増える場合があります。

```ts title="Model setup"
import { createOpenAICompatible } from '@ai-sdk/openai-compatible';

const local = createOpenAICompatible({
  name: 'local',
  baseURL: 'http://127.0.0.1:11434/v1',
  supportsStructuredOutputs: true,
  // apiKey: process.env.LLM_API_KEY,
});

const agent = { model: local.chatModel('your-model-id') };
```
  </Tab>
</Tabs>

ゲートウェイでは通常 `provider/model` 形式の ID を使います。直接接続するプロバイダーでは、それぞれ固有の ID を使います。

### キーの代わりに Vercel OIDC を使う

`AI_GATEWAY_API_KEY` がない場合、`gateway()` は短期間有効な Vercel OIDC トークンで認証し、必要に応じて更新します。初回に Vercel CLI へログインし、プロジェクトをリンクします。

<CodeGroup>
```bash npm
npx vercel login
npx vercel link
npx e2e run
```

```bash pnpm
pnpm dlx vercel login
pnpm dlx vercel link
pnpm exec e2e run
```

```bash bun
bunx vercel login
bunx vercel link
bunx e2e run
```
</CodeGroup>

ゲートウェイは、有効な `VERCEL_OIDC_TOKEN` があればそれを使います。なければ、作業ディレクトリから上へ探した `.vercel/project.json` のプロジェクトに対してトークンを取得します。e2e は `.env` ファイルを読み込まないため、`npx vercel env pull` で得たトークンは、シェルでエクスポートするか、設定ファイルで [`process.loadEnvFile()`](/reference/config#loading) を使って読み込んだ場合にだけ使えます。

## AI SDK プロバイダー

ツール呼び出しに対応するすべての AI SDK プロバイダーを使えます。パッケージと環境変数は、各 [AI SDK プロバイダーのページ](https://ai-sdk.dev/providers/ai-sdk-providers)に記載されています。使用するものを選んでください。

<ModelProvider show="select" />

一覧にないプロバイダーも、AI SDK の言語モデル仕様 v2 以降を実装していれば使えます。

<Steps>
  <Step title="プロバイダーパッケージをインストールする">
  `ai` とプロバイダーパッケージをインストールします。

  <ModelProvider show="install" />

  シェルまたは CI で環境変数をエクスポートします。または、設定内の [`process.loadEnvFile()`](/reference/config#loading) で `.env` ファイルを読み込みます。

  <ModelProvider show="env" />
  </Step>
  <Step title="設定にモデルを追加する">
  `agents.default` にモデルを設定します。モデル ID は例です。

  <ModelProvider show="config" />
  </Step>
</Steps>

<Accordion title="ツール選択の強制を拒否するモデル">
エージェントステップは、どのモデルにも毎ターン、ツール呼び出しを要求します。Claude Opus 5.5、Sonnet 5.5、Fable 5.1 はこのリクエスト形式を拒否します。DeepSeek の V4 モデル（`@ai-sdk/deepseek`）はデフォルトで推論するため拒否し、Muse Spark モデルは `auto` だけを受け付けます。e2e は `auto` に切り替えて続行し、そのモデルの後続ステップも最初から `auto` を使います。推論は有効なままでかまいません。
</Accordion>

<Accordion title="Claude Opus 5.5、Sonnet 5.5、Fable 5.1">
これらのモデルは、各推論ブロックをシステムプロンプトとそれ以前のメッセージに結び付けます。どちらかが変わった後にそのブロックを再送するリクエストは拒否されます。エージェントステップはプロンプトを固定し、過去のメッセージから古くなった画面やスクリーンショットを省略した時点で、そのメッセージ以降の推論も送信しなくなります。ステップの `--debug` トランスクリプトにその旨が記録されます。
</Accordion>

## ひとつの設定で複数のモデルを使う

モデルごとにエージェント名を付け、`--agent` またはテスト内で選びます。[エージェントとペルソナ](/agents)を参照してください。設定ファイルを編集せずにモデルを切り替えるには、環境変数を読み取ります。

```ts title="Agent setup"
const agent = {
  model: gateway(process.env.MODEL ?? 'openai/gpt-6-luna-fast'),
};
```

### 設定されているキーからモデルを選ぶ

チームのメンバーが異なるキーを持っている場合は、設定されている環境変数でモデルを選びます。全員が同じ記録を再生できるよう、エージェント名はひとつに保ちます。

```ts title="Agent setup"
import { anthropic } from '@ai-sdk/anthropic';
import { gateway } from 'ai';

const agent = {
  model: process.env.ANTHROPIC_API_KEY
    ? anthropic('claude-sonnet-5-5')
    : gateway('openai/gpt-6-luna-fast'),
};
```

フォールバックには `gateway()` を使ってください。[Vercel OIDC](#vercel-oidc-instead-of-a-key) は、確認できる環境変数がなくても認証できるためです。`.env` のキーは、このコードより前に [`process.loadEnvFile()`](/reference/config#loading) が実行された場合にだけ認識されます。

別のモデルで記録したステップも引き続き再生され、記録したモデル名が表示されます。[一致が必要な情報](/cache#what-must-match)を参照してください。

### 専用のジャッジを使う

デフォルトでは、ひとつのモデルが `agent.act` を実行し、`agent.assert`、`agent.waitFor`、`agent.extract` に答えます。それらの確認に別のモデルを使うには、`judge` を設定します。

```ts title="Agent setup"
const agent = {
  model: gateway('openai/gpt-6-luna-fast'),
  judge: gateway('anthropic/claude-sonnet-5'),
};
```

組み込みの `agent.assert` で `explore: true` を指定した場合は、`judge` が設定されていても、`agents.<name>.model` でツールループを実行します。

レポートには判定ごとのモデル名が表示されます。`judge` は AI SDK の言語モデルを受け取ります。Clef や Jev には[デシジョンエグゼキューター](/decision-models)を使ってください。[判定に渡される情報](/agent-steps#what-the-model-sees)も参照してください。

## データ保持とコンプライアンス

モデルへの入力は、機密情報を秘匿した画面、ステップの指示、エージェントが要求したスクリーンショットです。e2e は応答後にプロバイダーから情報を読み戻さないため、実行のためにプロバイダーが状態を保存する必要はありません。

すべてのモデルリクエストには e2e を識別する情報が付きます。`User-Agent` は `e2e/<version> (<platform>; <arch>)` で始まり、Vercel AI Gateway と OpenRouter には `HTTP-Referer:
https://tester.army/e2e` と `X-Title: e2e` も付きます。プロバイダーのインスタンスに同名のヘッダーがあれば置き換えます。

<AccordionGroup>
<Accordion title="OpenAI と Azure OpenAI: データ保持なし">
Responses モデル（`openai(...)`、`azure(...)`、ゲートウェイの `openai/*`）へのすべてのリクエストには、`store: false` とプロンプトキャッシュキーが付きます。Chat Completions モデルと OpenAI 互換プロバイダーには、どちらも付きません。プロバイダーは会話のコピーを保持せず、プロンプトキャッシュは引き続き機能します。データ保持なしの組織に追加設定は不要です。

レスポンスを保存したい場合は、`providerOptions` に `store` を設定します。Azure OpenAI ではキーが `azure` になります。

```ts title="Agent setup"
const agent = {
  model: openai('gpt-6-luna'),
  providerOptions: { openai: { store: true } },
};
```
</Accordion>
<Accordion title="BAA 契約下で Anthropic を使う">
エージェントステップは、Messages API のツール使用、プロンプトキャッシュ、画像、構造化出力を使います。これらはすべて、Anthropic の HIPAA 対応の対象です。

契約が対象とするのは `api.anthropic.com` だけです。ゲートウェイや OpenRouter を経由せず、`@ai-sdk/anthropic` で直接呼び出してください。すべてのリクエストがひとつの契約の対象になるよう、`judge` は設定しないでください。Anthropic の Covered Models には 30 日間の保持が必要なため、データ保持なしの組織では使えません。
</Accordion>
</AccordionGroup>

## どこで何が失敗するか

| 問題 | コード | 対処 |
| --- | --- | --- |
| モデルが AI SDK インスタンスではなく文字列 | `INVALID_CONFIG` | `gateway('openai/gpt-6-luna-fast')` などでインスタンスを作成します。 |
| 組み込みエージェントにモデルがない | `MODEL_UNAVAILABLE` | `agents.<name>.model` を設定します。 |
| GitHub Copilot がそのアカウントにモデルを提供していない | `MODEL_UNAVAILABLE` | 契約プランで使える ID を選びます。[モデルを選ぶ](/subscriptions#pick-a-model)を参照してください。 |
| 設定読み込み時にキーを読むプロバイダーで、キーがない | `CONFIG_LOAD_FAILED` | キーを設定します。 |
| 最初のモデル呼び出しで認証に失敗する | `MODEL_PROVIDER_FAILED` | プロバイダーの API キーを確認します。サブスクリプションなら `npx e2e login` を実行します。Vercel OIDC を使う場合も、メッセージには `AI_GATEWAY_API_KEY` しか表示されません。`vercel login` と `.vercel/project.json` を確認してください。 |
| `ai` パッケージがない | `MODEL_UNAVAILABLE` | `ai` をインストールします。[ゲートウェイまたはプロバイダーを選ぶ](#pick-a-gateway-or-a-provider)を参照してください。 |
| ステップの 2 ターン目が `Item with id 'rs_…' not found` で失敗する | `MODEL_PROVIDER_FAILED` | `providerOptions` の `store` をデフォルトどおり無効にするか、ゲートウェイ経由ではなく OpenAI を直接呼び出します。 |
| カスタムエグゼキューター自身の `model` または `judge` が agents エントリーと異なる | `INVALID_CONFIG` | [カスタムエグゼキューター](/executors#keep-the-loop-change-the-vocabulary)を参照してください。 |
