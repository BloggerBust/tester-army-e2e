これらの環境変数でランナーと公式パッケージを設定します。表の `set` は変数が存在すること、`value` は空でないこと、`flag` は空、`0`、`false` のいずれでもないことを表します。フラグの値では大文字と小文字を区別しません。

```bash
export E2E_USER_ADMIN_PASSWORD="$ADMIN_PASSWORD"
export E2E_CACHE_DIR=~/.cache/e2e
export E2E_TELEMETRY_DISABLED=1
```

## リファレンス

### モデル

モデルは `e2e.config.ts` で設定します。API キーは各プロバイダーが読み取ります。`gateway()` は `AI_GATEWAY_API_KEY`、`openrouter()` は `OPENROUTER_API_KEY`、`openai()` は `OPENAI_API_KEY` を使います。`AI_GATEWAY_API_KEY` がなければ、`gateway()` は [Vercel OIDC トークン](/models#vercel-oidc-instead-of-a-key)を使います。認証情報がない場合、最初のモデル呼び出しで失敗します。サブスクリプションモデルは、代わりに保存済みのログイン情報を使います。[モデル](/models)と[サブスクリプション](/subscriptions)を参照してください。

| 変数 | 例 | 判定 | 効果 |
| --- | --- | --- | --- |
| [`E2E_OAUTH_CREDENTIALS`](#e2e_oauth_credentials) | `E2E_OAUTH_CREDENTIALS="$(cat oauth.json)"` | value | 保存済みのサブスクリプションのログイン情報を JSON で指定します |
| [`OPENCODE_API_KEY`](#opencode_api_key) | `OPENCODE_API_KEY=<key>` | value | 保存済みの `opencode-console` のログイン情報を置き換えます |
| `XDG_CONFIG_HOME` | `XDG_CONFIG_HOME=~/.config` | value | ログイン情報の保存先ディレクトリです。保存先は `$XDG_CONFIG_HOME/e2e/oauth.json`、デフォルトは `~/.config/e2e/oauth.json` です |

#### `E2E_OAUTH_CREDENTIALS`

誰もサインインできないマシン向けに、保存済みのサブスクリプションのログイン情報を JSON で指定します。内容は `oauth.json` と同じです。

- `e2e/oauth/*` のモデルと `e2e models` は、`$XDG_CONFIG_HOME/e2e/oauth.json` の代わりにこの値を読み取ります。
- `e2e login` と `e2e logout` では変更できません。
- 更新されたトークンは書き戻されません。

#### `OPENCODE_API_KEY`

OpenCode Console のサービスアカウント API キー、または OpenCode Go サブスクリプションの API キーです。`opencodeConsole()` と `e2e models opencode-console` は、保存済みの `opencode-console` のログイン情報の代わりにこの値を使います。OpenCode も同じ変数を読み取ります。

### 認証情報とシークレット

| 変数 | 例 | 判定 | 効果 |
| --- | --- | --- | --- |
| `E2E_USER_<NAME>_USERNAME` | `E2E_USER_ADMIN_USERNAME=admin@example.test` | set | `credentials.<name>.username` を置き換えます |
| `E2E_USER_<NAME>_PASSWORD` | `E2E_USER_ADMIN_PASSWORD="$ADMIN_PASSWORD"` | set | `credentials.<name>.password` を置き換えます |
| `E2E_SECRET_<NAME>` | `E2E_SECRET_API_KEY="$API_KEY"` | set | `secrets.<name>` の値を置き換えます |

- `<NAME>` は名前を大文字にし、`A-Z0-9` 以外の文字をすべて `_` に置き換えたものです。たとえば `power-user` は `E2E_USER_POWER_USER_USERNAME` になります。
- 2 つの認証情報、または 2 つのシークレットの名前が同じ `<NAME>` になる場合、環境変数の設定有無にかかわらず、設定の読み込み時に `INVALID_CONFIG` になります。これにより、1 回のローテーションで 2 つのエントリーが置き換わることを防ぎます。メッセージには該当するエントリーと変数が示されます。たとえば `api-key` と `api_key` はどちらも `E2E_SECRET_API_KEY` を、`svc-a` と `svc_a` はどちらも `E2E_USER_SVC_A_USERNAME` と `_PASSWORD` を読み取ります。
- 認証情報とシークレットは接頭辞が異なるため、同じ名前を使えます。
- 設定にない名前の変数は無視されます。
- パスワードやシークレットが空、または 6 文字（コードポイント）未満の場合は `INVALID_CONFIG` になります。秘匿は値が出現するすべての箇所を書き換えるため、短すぎる値では通常のテキストまで置き換わってしまいます。空のユーザー名は指定できます。

### 実行モード

| 変数 | 例 | 判定 | 効果 |
| --- | --- | --- | --- |
| [`CI`](#ci) | `CI=1` | flag | CI モードを有効にします |

#### `CI`

CI モードを有効にします。

- `retries` と `workers` のデフォルトが 1 になります。
- `cache` のデフォルトが `read-only` になります。
- フォーカス指定されたテストは `ONLY_IN_CI` になります。
- アプリのコマンドの `reuseExisting` は無視されます。

### リプレイキャッシュ

| 変数 | 例 | 判定 | 効果 |
| --- | --- | --- | --- |
| [`E2E_CACHE_DIR`](#e2e_cache_dir) | `E2E_CACHE_DIR=~/.cache/e2e` | value | [`cache.dir`](/reference/config#cache) を置き換えます |

#### `E2E_CACHE_DIR`

`e2e run` と `e2e cache` の [`cache.dir`](/reference/config#cache) を置き換えます。パスはプロジェクトルートを基準に解決します。

- `~` または先頭の `~/` はホームディレクトリを表します。
- `--cache-dir` の指定が優先されます。
- 独自の `cache.store` はこの値を無視します。
- キャッシュモードは設定どおりのままです。`--no-cache` を指定すれば引き続きキャッシュを無効にできます。

### 診断

| 変数 | 例 | 判定 | 効果 |
| --- | --- | --- | --- |
| `NO_COLOR` | `NO_COLOR=1` | set | CLI 出力の色を無効にします。未設定の場合、TTY または CI では色が有効になり、パイプ出力では無効になります |
| `FORCE_COLOR` | `FORCE_COLOR=1` | set | パイプ出力でも CLI の色を有効にします |
| `TERM` | `TERM=dumb` | value | `dumb` の場合、CI と同様に `e2e init` のロゴをアニメーションなしで表示します |
| `GITHUB_SHA`, `GITHUB_HEAD_REF`, `GITHUB_REF_NAME` | `GITHUB_REF_NAME=main` | value | `git` がプロジェクトルートを読み取れない場合、レポートの `run.vcs` に記録するコミットとブランチです。`GITHUB_HEAD_REF` が `GITHUB_REF_NAME` より優先されます |

`--debug` と `--ai-trace` は環境変数ではなくフラグです。[CLI](/reference/cli#e2e-run) を参照してください。

#### `E2E_TELEMETRY_FLEET`

ユーザー向けに e2e を実行するプラットフォームの名前を指定します。

- イベントはマシンごとの ID ではなく `fleet:<name>` に紐づけられます。
- 設定ファイルは書き込まれず、通知も表示されません。
- 単純なトークンではない値は `other` として送信されます。

## アプリのプロセスが継承する変数

アプリの `command` には `PATH`、`HOME`、`TMPDIR`、`TMP`、`TEMP`、`SystemRoot`、`COMSPEC` に加えて、`command.inheritEnv` に一致する変数と、`command.env` で設定した値を渡します。

`APP_URL` を読み取るのは、ひな形として生成された設定モジュールであり、ランナーではありません。開発サーバーでも必要な場合は、`command.env` を通して渡してください。
