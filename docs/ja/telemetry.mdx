`e2e` CLI は、利用されているコマンド、エンジン、機能、実行が失敗する箇所について、匿名の利用データを送信します。テレメトリーはデフォルトで有効です。送るのは件数やバージョンで、テスト内容、アプリの内容、認証情報は送信しません。

## 無効にする

次のいずれかで、テレメトリーを無効にできます。

<CodeGroup>
```bash npm
npx e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```

```bash pnpm
pnpm exec e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```

```bash bun
bunx e2e telemetry disable   # saved in ~/.config/e2e/telemetry.json
export E2E_TELEMETRY_DISABLED=1          # for a shell or a CI job
export DO_NOT_TRACK=1                    # the cross-tool convention
```
</CodeGroup>

環境変数は保存済みの設定より優先されます。`e2e telemetry enable` は保存済みの `disable` を解除します。`e2e telemetry` は状態を表示し、無効な場合は理由も表示します。設定ファイルは、`$XDG_CONFIG_HOME` が設定されていれば `$XDG_CONFIG_HOME/e2e/` 配下、Windows では `%APPDATA%\e2e\` 配下にあります。

`disable` は、別のターミナルですでに実行中のコマンドからの送信も止めます。設定ディレクトリに書き込めない場合や、e2e リポジトリのソースチェックアウトから実行した場合は、何も送信しません。

## 送信される内容を確認する

<CodeGroup>
```bash npm
E2E_TELEMETRY_DEBUG=1 npx e2e run
```

```bash pnpm
E2E_TELEMETRY_DEBUG=1 pnpm exec e2e run
```

```bash bun
E2E_TELEMETRY_DEBUG=1 bunx e2e run
```
</CodeGroup>

CLI は、実際のペイロードを `[telemetry] {...}` として標準エラー出力に表示し、何も送信しません。

## 送信する情報

各コマンドは `e2e_cli_session` イベントを 1 つ送ります。加えて、`run` と `explore` は `e2e_run_completed`、`init` は `e2e_init_completed`（先に init ウィザードを動かす `explore` も同様）、`upgrade` は `e2e_upgrade_completed` を送ります。`mcp` は MCP セッションごとに `e2e_mcp_session` を 1 つ送ります。`--help` と `--version` は、どのコマンドでも何も送りません。`e2e/runner` の `run()` と `explore()` はセッションイベントを送らず、レポートを返す呼び出しごとに `e2e_run_completed` を 1 つだけ送ります。

コマンド、`run()`、`explore()` の終了時に、イベントをひとつのリクエストにまとめ、2 秒の期限で送信します。`e2e mcp` はセッションイベントごとに別のリクエストを送り、`e2e run --watch` は各実行の終了時にそのイベントを送ります。

イベントに含まれるのは、以下のプロパティだけです。大文字のトークンでないエラーコードは `OTHER` として送ります。エンジン、プラットフォーム、モデル、フリート、MCP クライアントの名前と、MCP クライアントのバージョンは、英字、数字、ドット、ハイフン、アンダースコアだけのトークンでなければ `other` として送ります。semver でないエンジンバージョンは `unversioned` として送ります。操作数とツール呼び出し数では、プロジェクトツールをまとめて `tool`、その他の未知の名前を `other` として数えます。

## 送信しない情報

テレメトリーは、テストタイトル、ファイルパス、URL、オリジン、指示、観測内容、ページ内容、スクリーンショット、エラーメッセージ、スタックトレース、環境変数の値、認証情報、ファイル内容を送信しません。ターゲット、エージェント、認証情報、シークレット、プロジェクトツールの名前、MCP ツールの引数や結果、探索のゴールやチャーター、検出結果の文章も送信しません。

## CI 環境

CI の実行は、マシンではなく CI ベンダー単位で集計します。設定ファイルは使わず、通知も表示しません。CI ベンダーの環境ではないのに、コーディングエージェントがシェルで `CI` を設定した場合は、そのエージェントが動いているマシンとして数えます。

CI では、環境変数でのみテレメトリーを無効にできます。ジョブの `env` に `E2E_TELEMETRY_DISABLED: '1'` を設定してください。

## フリート環境

利用者のために新しいマシンで e2e を動かすプラットフォームでは、そのままだと各マシンを新しいユーザーとして数えてしまいます。それらのマシンに `E2E_TELEMETRY_FLEET=<name>` を設定してください。イベントは `fleet:<name>` として集計されます。CI と同様に、設定ファイルは使わず、通知も表示しません。何も送らない場合は `E2E_TELEMETRY_DISABLED=1` を設定します。

## 送信先

イベントは、e2e のメンテナーが運用する PostHog プロジェクトの `eu.i.posthog.com` に送られます。PostHog は個人プロフィールを保持せず、リクエスト元アドレスを保存せず、各イベントで GeoIP を使いません。データは集計した形で参照されます。

テレメトリーには[セキュリティポリシー](https://github.com/e2e-inc/e2e/blob/main/SECURITY.md)が適用されます。実行が行うその他の接続は、[外向きの接続](/reference/security#outbound-connections)に記載しています。

## フィードバック

[`e2e feedback`](/reference/cli#e2e-feedback) はテレメトリーではありません。フラグ内の文章を、上記のマシン情報とともに、ひとつの `e2e_feedback` イベントとして同じ PostHog プロジェクトへ送ります。テレメトリーが有効な場合は、テレメトリーのイベントと同じ匿名 ID を使います。

保存済みの `e2e telemetry disable` では停止しません。`E2E_TELEMETRY_DISABLED=1` と `DO_NOT_TRACK=1` では停止します。[CLI リファレンス](/reference/cli#e2e-feedback)で、秘匿、`--dry-run`、`--repro` のないバグ報告について説明しています。

## 通知

最初のコマンド、または `e2e/runner` の最初の `run()` や `explore()` は、無効化方法を示す通知を標準エラー出力に表示します。`--reporter json` の出力は変えません。`e2e init` と `e2e telemetry` は通知を表示せず、次のコマンドまで待ちます。収集するデータに大きな変更があると、通知を再表示します。
