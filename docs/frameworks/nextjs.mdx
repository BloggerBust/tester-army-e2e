## Add e2e to your app

In your app's directory, run the wizard:

<CodeGroup>
```bash npm
npx e2e init
```

```bash pnpm
pnpm dlx e2e init
```

```bash bun
bunx e2e init
```
</CodeGroup>

Choose **Web (Playwright)** and a model provider. The wizard writes
`e2e.config.ts` and `tests/example.e2e.ts`, adds dependencies, and adds the
`.e2e/` run output to `.gitignore`. See the [Quickstart](/quickstart) for
each choice.

The wizard finds Next.js in `package.json`, writes a target that starts
your app, and prints what it wrote:

```text title="Output"
Found Next.js: the web target starts npm run dev on http://localhost:3000, and npm run start in CI after npm run build
```

## Start the app from the config

`app.command` starts your app and waits until `app.url` responds. `init`
generates a target using your package manager and dev port. If you're adding
this to an existing config, keep your `agents` entry:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

// e2e reads CI the same way: unset, '', '0', and 'false' mean a local run.
const ci = !['', '0', 'false'].includes(process.env.CI?.trim().toLowerCase() ?? '');

export default {
  // Keep the `agents` entry that `init` wrote.
  targets: [{
    engine: web(),
    app: {
      url: 'http://localhost:3000',
      // CI serves the production build: run `next build` before `e2e run`.
      command: ci
        ? { executable: 'npm', args: ['run', 'start'] }
        : { executable: 'npm', args: ['run', 'dev'], reuseExisting: true },
    },
  }],
} satisfies E2EConfig;
```

- **Locally**, e2e runs `next dev` (and reuses an already-running dev server
  when `reuseExisting: true` is set).
- **In CI**, e2e runs `next start` against your production build (and ignores
  `reuseExisting`).
- **Port matching:** Both `dev` and `start` need to listen on the port in
  `app.url` (3000 by default). If your `package.json` has no `start` script
  or uses different ports, `init` falls back to `next dev` everywhere.

Then run the tests:

<CodeGroup>
```bash npm
npx e2e run
```

```bash pnpm
pnpm exec e2e run
```

```bash bun
bunx e2e run
```
</CodeGroup>

For the other `command` options, such as `log`, `env`, and port `0`, see
[Starting your app](/web#starting-your-app).

## Run in CI

Build the app before the tests. The CI service sets `CI`, so the config
starts `next start`:

<CodeGroup>
```bash npm
npm run build
npx e2e run
```

```bash pnpm
pnpm build
pnpm exec e2e run
```

```bash bun
bun run build
bunx e2e run
```
</CodeGroup>

For a full workflow, run `e2e init --ci github-actions` or `--ci gitlab`:
the web job it writes runs the build before the tests
([CI pipeline](/reference/cli#ci-pipeline)). To write the job by hand, add
the build step to the [GitHub Actions](/ci/github-actions#web) job and leave
out its `APP_URL`. For CI defaults, see [Continuous integration](/ci).

To test each Vercel preview deployment instead, see
[Vercel Previews](/ci/vercel-previews).

## Fix Next.js problems

<AccordionGroup>
<Accordion title="The page renders but never hydrates">
Next.js 16 blocks cross-origin requests to its dev resources. When the
target opens `127.0.0.1` or `[::1]`, as
[port `0`](/web#let-the-runner-pick-the-port) does, `next dev` still
identifies as `localhost`. The page renders, locators resolve, and clicks
land, but no React handler runs.

Add the host the target opens to `allowedDevOrigins`. Use `'[::1]'` when
`app.url` opens `http://[::1]:0`:

```ts title="next.config.ts"
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  allowedDevOrigins: ['127.0.0.1'],
};

export default nextConfig;
```

A `localhost` target and a production `next start` target need no entry.
</Accordion>

<Accordion title="getByRole('alert') finds an extra element">
The App Router renders an empty `role="alert"` route announcer on every
page. `screen.getByRole('alert')` matches it too. Pick your alert by its
text:

```ts title="Test fragment"
await expect(screen.getByRole('alert').filter({ hasText: 'Enter a name first.' })).toBeVisible();
```

The agent doesn't see the route announcer, and the
[replay cache](/cache) doesn't count it as a change.
</Accordion>

<Accordion title="next dev recompiles while the tests run">
e2e writes its run output under `.e2e/`: results, logs, traces, and the
replay cache. A watcher that reads this folder can rebuild the app again
and again during a run.

- Keep the `.e2e/` entries that `init` adds to `.gitignore`. Tools that
  scan the project for source files, such as Tailwind CSS, skip ignored
  files.
- With webpack, the `next dev` default before Next.js 16, add `.e2e` to
  the paths the watcher ignores:

```ts title="next.config.ts"
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  webpack: (config, { dev }) => {
    if (dev) {
      config.watchOptions = {
        ...config.watchOptions,
        ignored: ['**/.git/**', '**/.next/**', '**/node_modules/**', '**/.e2e/**'],
      };
    }
    return config;
  },
};

export default nextConfig;
```

This list keeps the Next.js defaults. When your config already sets
`ignored`, add `'**/.e2e/**'` to it instead.
</Accordion>
</AccordionGroup>

## Start a new app

Create a Next.js App Router app with e2e already set up, from the
[`with-next` example](https://github.com/e2e-inc/e2e/tree/main/examples/with-next):

<CodeGroup>
```bash npm
npx create-next-app --example https://github.com/e2e-inc/e2e/tree/main/examples/with-next my-app
cd my-app
npm run test:e2e
```

```bash pnpm
pnpm create next-app --example https://github.com/e2e-inc/e2e/tree/main/examples/with-next my-app
cd my-app
pnpm test:e2e
```

```bash bun
bun create next-app --example https://github.com/e2e-inc/e2e/tree/main/examples/with-next my-app
cd my-app
bun run test:e2e
```
</CodeGroup>

The app has three locator tests and two agent tests. The agent tests skip
until you set `AI_GATEWAY_API_KEY`.

To deploy to Vercel and test every deployment, start from the
[Next.js with e2e template](https://github.com/e2e-inc/e2e-vercel-previews)
instead. Its README has a **Deploy** button.
